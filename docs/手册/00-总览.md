# 00 · 总览

EvoFlow 是一个 **header-only 的 C++17 演化计算框架**，面向组合优化与连续优化：把「**问题建模**」与「**优化器装配**」解耦，通过自注册组件表把各类元启发式算子（PSO/ACO/GA/DE/EDA/ES/GWO/WOA/免疫/烟花…）自由组合到一条可配置的优化流水线上。

公开产品版本为 **3.0.1.5**。Windows x64 是当前完整验证与正式发布平台；Linux C++ 核心/CLI 已在 Ubuntu 24.04.4 WSL2 x86_64、GCC 13.3、CMake 3.28.3、Ninja 1.11.1 环境完成源码构建与运行验证，但不提供 Linux 预编译发布包。图形界面和模型连接当前仅支持 Windows，macOS 尚未验证。Windows Python 预编译包覆盖 64 位 CPython 3.8–3.12。

源码与程序包只带 13 个首方最小样例；来源和再分发状态明确的 701 个较大实例作为独立完整数据覆盖包交付。TSPLIB、QAPLIB 与 GK 原始实例不随项目再分发，用户可按 `tutorial/external-data/README.md` 下载或准备本地原文件并转换。exe 可用 `evoflow data [路径]` 检查结构与大小，Python 可用 `python -m evoflow --check-data [路径]` 进一步逐文件验证 SHA-256。

统一入口：只需 `#include "evoflow.h"`（= 问题侧 `problem.h` + 优化器侧 `optimizer-builder.h`）。

## 1. 三层架构

```
┌──────────────────────── 优化器模块 ────────────────────────┐
│  ConfigBuilder(fluent) → FullConfig → AssertMatcher(校验)    │
│                        → OptimizerBuilder → Optimizer        │
│  执行链: Optimizer→Population→Subpopulation→O_Workflow        │
│          →[O_Component: 生成→评估→选择]→IndividualArray→Individual │
│  可插拔算子(注册表): 学习策略/学习拓扑/生成器/选择器/评估器/终止器/档案 │
└──────────────┬──────────────────────────────────────────────┘
               │ 消费问题句柄的公共接口(evaluate/greedy/feasible…)
┌──────────────┴──────────── 问题模块 ────────────────────────┐
│  Problem(4 域 Define) --compile--> ProblemHandle(4 域 Manager) │
│  Variable / Objective / Constrain / Heuristic 四域            │
│  12 个开箱问题模板(tsp/qap/mkp/mds/…)                          │
└──────────────┬──────────────────────────────────────────────┘
               │ 复用
┌──────────────┴──────────── 基础组件层 ──────────────────────┐
│  basics(随机源/数学/排序/系统) · calculator+exprTree(公式求值)  │
│  solution(解表示+解码) · logger(日志) · cp(约束传播) · distribution(采样) │
└─────────────────────────────────────────────────────────────┘
```

### 1.1 基础组件层（底座）
| 组件 | 提供 |
|---|---|
| `basics/` | 可复现随机源（统一引擎）、数学、排序、系统/时间、常量 |
| `calculator/` + `exprTree/` | 公式字符串求值（muParserX 后端），供表达式目标/约束/启发 |
| `solution/` | 候选解 `Solution`（`result`+`fitness` 双向量）+ `SolutionDecoder`（多变量布局解码） |
| `logger/` | 两正交轴日志（系统级 / 每优化器级），见 日志使用规范 |
| `cp/` | 区间约束传播引擎（无 muParserX），支撑表达式约束的域缩减 |
| `distribution/` | 采样分布模型（Gaussian/Cauchy/Uniform/Histogram），供 EDA |

### 1.2 问题模块层（建模）
- **`Problem`**：问题定义总装，持 4 个域的 **Define**（描述），`add*` 方法委派填充，`compile` 组合出 `ProblemHandle`。
- **`ProblemHandle`**：4 个域的 **Manager**（编译后的运行期引擎）+ 跨域编排。优化器只通过它的公共接口与问题交互。
- **四域**：Variable（变量域）/ Objective（目标域）/ Constrain（约束域）/ Heuristic（启发域），每域 `xx-define.h`（描述）+ `xx-manager.h`（引擎）。
  - 约束族：域（domain）/基数（cardinality）/累积（accumulate）/图（graph）/cp 表达式（expression）。
- **模板**：`problem-template.h` + `pt-*.h` 提供 12 个经典问题一键构造（tsp/qap/mkp/mds/mis/cvrp/cflp/cpmp/fjsp/wfs/stp/sr）。连续问题和外部 benchmark 通过通用目标 functor/callable 建模。

### 1.3 优化器模块层（求解）
- **基础设施**：`Registry<Base>` 自注册表 + `EVOFLOW_REGISTER` 宏；组件按 `tag` 字符串注册、按名装配（新增算子=一个文件+一行注册，不改工厂）。
- **执行单元层级**：`Individual`（+装配期推断挂载的特性）→ `IndividualArray` → `Subpopulation` → `Population`（顶层聚合）→ `Optimizer`。
- **可插拔算子族**（均经注册表）：

| 族 | 基类 | 作用 |
|---|---|---|
| 学习拓扑 | `LearningTopology` | 决定「谁向谁学习」，产出 `LearningGraph` |
| 学习策略 | `LearningStrategy` | 决定「怎么学 / 怎么生成子代」 |
| 子代生成器 | `OffspringGenerator` | 依拓扑+策略批量产子代（4 种框架） |
| 环境选择 | `EnvirSelect` | 用子代更新种群（两层：找谁替换 + 是否替换） |
| 评估器 / 终止器 / 档案 | `Evaluator`/`Terminator`/`BestArchive` | 求适应度+驱动 FES / 停止条件 / 最优保存 |
| 解操作 | `SolutionInitializer`/`SolutionRepaireman` | 初始化 / 越界修复 |

- **编排**：`O_Component`（流水线单元）→ `O_Workflow`（单表 components 按 config 顺序每代顺跑）→ `OptimizerBuilder`（从 config 装配）。
- **配置**：`ConfigBuilder` fluent API → `FullConfig` → `AssertMatcher`（装配期兼容校验：组件间断言匹配）→ `Optimizer`；`config-codec`（text/json 序列化）。

## 2. 三条使用主线

### 2.1 定义问题（问题模块）
```cpp
EvoFlow::Problem p("my_problem");
p.addVariable("x", -5, 5, 0.001, 5);           // 名/下界/上界/精度/维数
p.addObjective("f", 1, true, "x", f_ptr);      // 名/优先级/最小化?/输入变量/求值(函数指针或公式)
p.addConstrainRange("x", -3, 3, 1, "");        // 各类 addConstrainXxx
EvoFlow::ProblemHandle* h = p.compile;          // 编译成运行期句柄
h->solutionEvaluate(sol);                       // 评估一个解
```
或直接用模板：见 `problem-template.h`。完整示例：`tutorial/0.problem.cpp`。

### 2.2 配置并运行优化器（优化器模块）
```cpp
EvoFlow::ConfigBuilder cb;
auto wf = cb.workflow("wf");
wf.initializer("Random");
wf.topology.pgBest;                           // 学习拓扑
wf.repair.boundary;                           // 修复
wf.strategy.velocityDriven(2, 2.0, 0.9, 0.4);   // 学习策略(PSO)
wf.generator.generation;                      // 生成器
wf.evaluator.basic;  wf.selector.index(false);// 评估 + 选择
cb.name("run").maxFES(40000).manager("Single").gArchive("Basic");
cb.subpopulation("1").size(20).workflow("wf").maxFES(40000).archive("Basic");   // 个体类型无需指定

EvoFlow::Optimizer* opt = cb.buildOptimizer;
opt->setProblem(&p);
opt->exe(30);                                    // 跑 30 轮独立实验
Solution* best = nullptr; int n = 0; opt->getBest(best, n);
```
完整示例：`tutorial/1.optimizerconfig.cpp`（待产出）。

### 2.3 使用 Python 完成同一工作流

发布包中的 `python/evoflow` 复用同一套 C++ 问题、配置、运行与分析实现，并提供类型提示、ABI 诊断和示例。预编译版本验证范围为 Windows x64 的 64 位 CPython 3.8–3.12，每个次版本使用自己的 tagged `.pyd`；Linux 已在上述代表性环境以 CPython 3.12.3 完成源码构建与可移植测试，但不提供预编译原生模块。Python 不加入 CMake，发布时与 `evoflow.exe` 同包但 exe 不放入 Python 目录。详见 [15-使用-Python接口](15-使用-Python接口.md)。

## 3. 执行链（一代内发生什么）

```
Optimizer.exe(n)
 └ 每轮: Population 迭代
    └ 每代: Subpopulation.O_Workflow 顺跑 components(按 config 顺序):
        RunGenerate  : topology.getTopology → 逐个体 strategy 生成子代 → repair
        RunEvaluate  : evaluator 逐子代求 fitness，更新 archive、terminator(FES++)
        RunSelect    : selector.update_subswarm(parent, offspring) → 新一代；清 offspring
      (多段 workflow = 多组 生成/评估/选择 按序，如 GA 交叉段+变异段、免疫双 select)
    直到 Terminator 命中(FES/收敛/时间)
```

## 4. 术语表

| 术语 | 含义 |
|---|---|
| **Define / Manager** | 问题域的「描述」/ 编译后的「运行期引擎」（`compile` 由前者产出后者） |
| **ProblemHandle** | 问题编译产物，优化器与问题交互的唯一接口 |
| **Registry / tag** | 组件自注册表 / 组件的字符串名（配置按 tag 取用） |
| **LearningGraph** | 学习图：每条边 = 一个起点个体 + 若干终点学习对象（解）；终点空=不学习直接进子代 |
| **O_Component / O_Workflow** | 流水线单元（生成/评估/选择的包装）/ 其有序编排 |
| **段（segment）** | workflow 内一次「生成+评估+选择」批次；分段点 = 后批生成是否依赖前批评估结果 |
| **AssertMatcher** | 装配期校验：沿 workflow 累积各组件 postAssert（提供的上下文），核对每组件 preAssert（需求） |
| **FES** | 函数评估次数（fitness evaluations），主要预算/终止度量 |
| **个体特性（推断）** | 策略/拓扑经 `featureDemands` 声明所需特性（velocity/pbest/sigma…），装配期推断并逐个体挂载（取代旧「个体子类 postAssert」的 N6） |

## 5. 命名与版本约定（重要）

- **产品版本**：CLI、UI、Python 和发布文档共享 `3.0.1.5`；`evoflow --version` 和 `python -m evoflow --version` 可查询实际产品版本。
- **协议版本独立**：配置 `v3.1/v3.2`、`.rslt/.prcs` 格式版本不是产品版本，不能因发布 3.0.1.5 而改写。
- **组件用行为名，不用母版算法名**（纪律 4）：如 PSO 的拓扑叫 `PGBest`、GWO 的策略叫 `GreyWolfEncircling`（可插拔算子用行为描述；整体算法策略可留标准名如 `AntSystem`）。
- **编码**：源文件统一 UTF-8（`cl /utf-8`）；测试/示例**输出用英文**避免乱码（纪律 6）。
- 更多规范见开发者篇 22-开发-规范。
