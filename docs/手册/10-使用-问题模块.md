# 10 · 使用者篇 · 问题模块

建模你的优化问题：向 `Problem` 添加**变量/目标/约束/启发**，`compile()` 得到 `ProblemHandle`（优化器与问题交互的唯一接口）。
完整可运行示例见 `tutorial/0.problem.cpp`。

```cpp
#include "ecflow.h"
using namespace ECFlow;

Problem p("my_problem");
p.addVariable(...); p.addObjective(...); p.addConstrainXxx(...); p.addInspirationXxx(...);
ProblemHandle* h = p.compile();
```

---

## 1. 变量 `addVariable`

```cpp
int addVariable(name, low_bound, up_bound, accuracy, length,
                height = 1, type = VariableType::discrete);
```
- **name**：变量名（供目标/约束/启发按名引用）。
- **low/up_bound**：取值域 `[low, up]`。
- **length**：该变量的**维数/元素个数**（如 5 表示 x 有 5 个分量 `x[0..4]`）。
- **height**：多行布局，一般缺省。
- **type**：**变量类型**，决定该变量是**离散**还是**连续** —— 见下，这是唯一的判定依据。
- **accuracy**：**含义随 type 而变** —— 见下。
- 返回变量 id。**总维数** = 各变量 length 之和。

### 1.1 变量类型与 `accuracy`（⚠ 两者绑定）

平台的域只有一种实现（连续区间集），**"离散/连续"是加在其上的两种解释**，由 `type` 选定：

| type | 值域 | `accuracy` 的含义 | 随机取值 | 生成的决策值 |
|---|---|---|---|---|
| `discrete`（**默认**）· `allocation` · `sequence_direction` · `sequence_bidiagraph` · `sub_module` | **网格点** `{low + k·accuracy}` | **网格步长** | 格点**等概率** | 被**吸附到格点** |
| **`continuous`** | **实区间** `[low, up]` | "**多细算同一个值**"的粒度——**不是**步长，**不作用于取值** | 按**长度测度**均匀 | **原样保留，不被量化** |

> `continuous` 的 `accuracy` **不会**改动你的决策值 —— 连续变量的取值就是实数本身。它只用于两件事：①界定"删掉一个值"时的邻域（连续域上删单点是零测度的空操作，约束传播会失效）；②输出/展示的精度。
>
> **这决定了你的解能有多精细**。同一个 PSO 跑 5 维 sphere（`[-5,5]`，`accuracy=0.3`），只换变量类型：
>
> | | 最优 f | 解 `x[0]` |
> |---|---|---|
> | `continuous` | **5.17e-93** | `1.97e-55`（不在网格上） |
> | `discrete` | **0.05** | `0.1`（格点 `-5+17×0.3`） |
>
> 离散版**卡在 0.05 出不去** —— 那是 `5 × 0.1²`，即 0.3 网格的**精度地板**。声明为 `continuous` 才没有这个地板。

```cpp
p.addVariable("x", -100, 100, 1e-5, 30, 1, VariableType::continuous);   // 连续:1e-5 = 输出精度
p.addVariable("s", 0, n-1, 1, n);                                        // 离散(默认):1 = 网格步长
```

> ⚠ **连续变量务必声明 `VariableType::continuous`，不要靠"把 accuracy 设得很小"来近似**。后者会让该变量被当成**网格**：`[-100,100]` 配 `1e-5` 就是 **2×10⁷ 个格点** —— 枚举会真的构造那么大的数组，取一个随机值也要先数遍全部格点。声明为 `continuous` 后走测度解释，两者皆无。
>
> 连续变量上，"枚举候选/候选计数"（`getFeasibleList`/`getChoiceNumber`）**退化为点采样**（按测度均匀取至多 `FEASIBLE_LIST_LIMIT` 个点）——连续域本无"全部候选"可言。这与既有约定一致：`getChoiceNumber` 与 `getFeasibleList` 的长度**本就不必相等**（见 [§5](#5-编译与句柄-problemhandle)）。
>
> ⚠ `continuous` 与 **ACO**（信息素矩阵）、**SetPSO**（集合速度表）**结构性不兼容** —— 二者都要求"每维候选可枚举"。

## 2. 目标 `addObjective`（三种求值形式）

```cpp
void addObjective(name, priority, min_is_better, input_elements, double(*f)(double**)); // 函数指针
void addObjective(name, priority, min_is_better, input_elements, eccalcul_functor* f);  // 函数对象(可带状态)
void addObjective(name, priority, min_is_better, input_elements, formula);              // 公式字符串(muParserX)
```
- **priority**：优先级。**优先级 < 0（或 0 视实现）的目标不参与择优比较**（可作约束惩罚的宿主）；数值大者优先决定（词典序）。
- **min_is_better**：`true`=最小化、`false`=最大化。
- **input_elements**：逗号分隔的**输入变量名**（如 `"x"` 或 `"x,y"`），决定 `double**` 的布局（见 §3）。

### §3 关键：`double**` 输入布局 ⚠️
求值/启发函数签名为 `double f(double** a)`，其中 **`a[k][j]` = 第 k 个输入变量的第 j 维元素**（k 按 `input_elements` 顺序）。
```
input_elements = "x,y",  x/y 各 5 维:
   a[0] → x 的元素:  a[0][0] a[0][1] ... a[0][4]
   a[1] → y 的元素:  a[1][0] a[1][1] ... a[1][4]
例: 目标 Σx²  →  for(i=0..4) s += a[0][i]*a[0][i];
```
> 这是新用户最易困惑处：`a` 的第一维是「输入变量」，第二维才是「该变量的元素」。

## 3. 约束 `addConstrainXxx`（按族）

各约束可指定惩罚权 `w` 与承接惩罚的目标名 `objs`（记入该目标）。按语义分族：

| 族 | 方法 | 语义 |
|---|---|---|
| **域** | `addConstrainRange(input, left, right, w, objs)` | 各维取值限制在 `[left,right]`（`EMPTYVALUE` 表该侧不设界，见 ⚠️） |
| | `addConstrainEligible(input, allowed, ...)` | 各维只能取给定可行值集合 |
| | `addConstrainCompatibility(input, value, length, ...)` | 相容性（与给定值向量兼容） |
| **基数** | `addConstrainUnique(input, w, objs)` | 各维取值互异（全不同） |
| | `addConstrainDistinctCap(input, p, w, objs)` | 至多 p 种不同取值 |
| | `addConstrainMinDistance(input, gap, w, objs)` | 各维两两最小间距 ≥ gap（gap 可标量或每维数组） |
| **容量/分布** | `addConstrainCapacity(input, caps, nC, vols, nI, ...)` | 背包/容量（物品体积 vs 容器容量） |
| | `addConstrainDistributed(input, vals, size, nums, ...)` | 配额/分布（各取值出现次数受限） |
| **累积** | `addConstrainSequenceAccumulate(input, delta, ...)` | 序列累积（如 VRP 载重沿路径累加、每步不超限） |
| | `addConstrainScheduleAccumulate(input, node_count, ...)` | 调度累积（DAG 工序 max-plus 时序） |
| **图** | `addConstrainGraph{Independent/Distinct/Clique/Conflict/Dominating/VertexCover}(input, edges, ...)` | 图上独立集/染色/团/冲突/支配/顶点覆盖 |
| | `addConstrainNodeSum(input, n_vertices, edges, ...)` | 节点权和约束 |
| | `addConstrainGraphConnectivity(input, n_vertices, edges, ...)` | 连通性 |
| **表达式** | `addConstrainExpr(input_var, input_elements, formula, ...)` | cp 引擎表达式约束（可跨变量、支持域缩减/传播） |
| **自定义** | `addConstrain(input, ini, chk, ...)` | 用户提供 `ini()`/`chk(dim,val)` 函数 |

> ⚠️ `addConstrainRange` 的 `left/right` 用 `EMPTYVALUE`(=NaN) 表示「该侧不设界」——传普通数值边界时注意这个哨兵含义（判定用 `is_empty()`）。

### 3.1 约束详表（签名 · 专有参数 · 语义）

> **所有** `addConstrainXxx` 都以 `double w = 1`（惩罚权）、`const std::string& objs = ""`（承接惩罚的目标名，空=不记入特定目标）**结尾**，下表省略这两参；`input`/`input_var` = 输入变量名。

| 方法 | 专有参数（含义） | 语义 |
|---|---|---|
| `addConstrainRange` | `left`,`right` 域上下界（`EMPTYVALUE`=该侧不设界） | 各维取值限于 `[left,right]` |
| `addConstrainEligible` | `allowed` `vector<vector<double>>` 每维可取值集 | 各维只能取所属集合内的值 |
| `addConstrainCompatibility` | `value` `double*`,`length` | 解须与给定 `value[length]` 向量相容 |
| `addConstrainUnique` | —（无专有） | 各维取值**互异**（全不同） |
| `addConstrainDistinctCap` | `p` `int` 不同值上限 | 至多 `p` 种不同取值 |
| `addConstrainMinDistance` | `gap` `double`（或 `double*` 每维） | 各维两两取值间距 ≥ `gap` |
| `addConstrainCapacity` | `caps` `double*`,`nC` 容器数; `vols` `double*`,`nI` 物品数 | 背包/容量：物品体积装入容器不超容量 |
| `addConstrainDistributed` | `vals` `double*`,`size`; `nums` `int*` 各值配额 | 取值 `vals[i]` 出现次数受 `nums[i]` 限（配额/分布） |
| `addConstrainExpr` | `input_elements` 参与元素; `formula` cp 表达式串 | cp 引擎表达式约束（可跨变量、支持域缩减/传播）；**语法见 [26-表达式公式语法](26-开发-表达式公式语法.md)** |
| `addConstrainSequenceAccumulate` | `delta` `vector<double>` 每步增量; `lower`,`upper` 区间; `init` 初值(0) | 沿序列累加 `delta`，每步保持在 `[lower,upper]`（如 VRP 载重） |
| `addConstrainScheduleAccumulate` | `node_count`; `pred` 前驱; `exec` 工时; `comm` 通信模型; `deadline` 截止 | DAG 调度累积（max-plus 时序，工序不超截止） |
| `addConstrainAccumulate` | —（返回 `ConstrainAccumulate*`） | 通用累积：挂多条资源轨（容量/时间/通信），用返回指针追加 |
| `addConstrainGraphIndependent` | `edges` `vector<int>` 边表 | 图上**独立集**（相邻节点不同选） |
| `addConstrainGraphDistinct` | `edges` | 图**染色相异**（相邻节点取值不同） |
| `addConstrainGraphClique` | `edges` | **团**约束 |
| `addConstrainGraphConflict` | `edges`; `conflict` `bool(*)(double,double)` 冲突判定 | 自定义冲突：相邻节点取值满足 `conflict` 则违反 |
| `addConstrainGraphDominating` | `edges` | **支配集** |
| `addConstrainGraphVertexCover` | `edges` | **顶点覆盖** |
| `addConstrainNodeSum` | `n_vertices`,`edges`,`directed`; `lo`,`hi` 节点权和上下界; `cap` 边容量 | 各节点邻域权和 ∈ `[lo,hi]`，边容量 `cap`（图约束-NodeSum） |
| `addConstrainGraphConnectivity` | `n_vertices`,`edges`; `terminals`(={}) 必连端点 | **连通性**：指定 `terminals` 时=Steiner 连通 |
| `addConstrain` | `ini`,`chk(dim,val)`,`chg(dim,val)` 函数指针 | **自定义**：用户提供初始化/检查/传播三函数 |

## 5. 编译与句柄 `ProblemHandle`

`ProblemHandle* h = p.compile();` 后，通过它与问题交互（不再直接碰 `Problem`）。常用接口：

**规模/元信息**：`getProblemSize()`（总维数）、`getObjectNumber()`、`getVariableNumber()`、`getVariableLowbound/Upbound(dim)`、`getSolutionDecoder()`、`getSolutionComparer()`。

**解评估/比较**：
```cpp
Solution s; s.setSize(h->getProblemSize(), h->getObjectNumber()); s.setDecoder(h->getSolutionDecoder());
for (int i=0;i<PS;i++) s[i]=...;
h->solutionEvaluate(s);                       // 填 s.fitness
Comparer* c = h->getSolutionComparer();
bool better = c->isBetter(s1.fitness, s2.fitness);
double v = h->constraintViolation(s);          // 约束违反程度(见下)
bool ok = h->solutionLegality(s);              // 是否完全不违反(等价于 v == 0)
```

**约束违反度的语义**——平台有**两条**约束通路，勿混：

| | `constraintViolation(s)` / `solutionLegality(s)` | 目标惩罚（`solutionEvaluate` 内部） |
|---|---|---|
| **算什么** | **全部已注册约束**的 **原始** violation 之和 | `violation × penalty_w`，且**仅算绑定到该目标**的约束 |
| **乘权重** | **否** | 是 |
| **谁在用** | **用户 API** —— **优化器不调用** | **评估路径**，进 `s.fitness` |

> 所以 `constraintViolation` 与 `f.fitness` 里的惩罚项**对不上是正常的**：前者是不加权的总量，后者是加权且按目标分摊的。
> `solutionLegality` 与 `constraintViolation` **约束集合一致、结论恒一致**（legal ⟺ violation == 0），但前者是**或逻辑短路**——撞到第一条违反即返回、不再计算其余约束。只想知道"合不合法"时用它，比 `constraintViolation(s)==0` 省计算。

**变量域计入违反度**：`compile()` 会为每个决策变量**自动补一条域(range)约束**（DOMAIN-CLAMP，使出界值被 `constrainCheck` 拦下、交 repairman 夹回）。这条约束**计入** `constraintViolation` —— 因为**变量域正是用户在 `addVariable(name, lo, hi, ...)` 时声明的**，域外解确实违反了用户的声明。它 `penalty_w=0` 且不绑定任何目标 → **只收缩可行域、不进任何 fitness 惩罚**，仅在违反度中体现。

> ⚠ **显式声明 range = 接管该变量的域约束**：若你为某变量调用了 `addConstrainRange`，`compile()` **不再**为它自动补域约束（否则同一处越界会被**算两遍**）。这意味着**你的 range 就是该变量的最终边界** —— 若它比 `addVariable` 声明的域更宽，域边界将**不再被强制**。要同时生效请自行取交（把 range 写成不宽于变量域）。
> 自动补域约束可经 `// #define ECFLOW_DISABLE_AUTO_DOMAIN_CONSTRAIN`（[problem.h](../../src/problem/core/problem.h) 顶部）整体关闭。

**逐维构造 / 约束传播 / 启发**（贪心构造类算法用）：
```cpp
h->constrainReset();  h->setResult(s);
for (int d=0; d<PS; d++) {
    double* feas = h->getFeasibleList(d);      // 当前维可行域  ⚠️ 见下
    int nfeas    = h->getChoiceNumber(d);
    double best  = h->getPrioriChoice(d);      // 启发最优取值
    double hval  = h->getChoiceHeuristic(d, best);
    if (h->constrainCheck(d, best)) { s[d]=best; h->constrainChange(d, s[d]); } // 落子并传播
    delete[] feas;                              // ⚠️ 必须手动释放
}
```
> ⚠️ **`getFeasibleList(int dim)` 返回裸 `double*`，调用方必须 `delete[]`**，否则泄漏。另有缓冲版 `getFeasibleList(int dim, double*& buf, int& size)` 可复用缓冲避免反复分配。

其它构造辅助：`getBoundaryChoice(dim,left)`、`getRandomChoice(dim)` / `getRandomChoiceInspace(dim)`、`getCloseChoice(dim,v)`、`choiceDiscretized(dim,v)`（对齐精度网格）。

## 6. 问题模板（13 个开箱问题）

无需手工 `addVariable/addObjective/...`——用模板类一键构造。每个模板类有 setter + `getProblem()` 返回 `Problem*`：
```cpp
#include "pt-tsp.h"           // 或对应模板头
ECFlow::PT_TSP tsp;
tsp.setCitys(pos, city_number, 2);
tsp.setEdgeWeightType(PT_TSP::DistanceType::Eula);
ECFlow::Problem* p = tsp.getProblem();   // 拿到 Problem 后照常 compile()/接优化器
```

| 类 | 头文件 | 问题 |
|---|---|---|
| `PT_TSP` | pt-tsp.h | 旅行商 |
| `PT_QAP` | pt-qap.h | 二次分配 |
| `PT_MKP` | pt-mkp.h | 多维背包 |
| `PT_Numerical` | pt-numerical.h | 数值优化（CEC 基准） |
| `PT_MDS` / `PT_MIS` | pt-mds.h / pt-mis.h | 最小支配集 / 最大独立集 |
| `PT_CVRP` | pt-cvrp.h | 容量车辆路径 |
| `PT_CFLP` / `PT_CPMP` | pt-cflp.h / pt-cpmp.h | 容量设施选址 / 容量 p-中位 |
| `PT_FJSP` | pt-fjsp.h | 柔性作业车间调度 |
| `PT_WFS` | pt-wfs.h | 工作流调度 |
| `PT_STP` | pt-stp.h | Steiner 树 |
| `PT_SR` | pt-sr.h | 符号回归（GEP 编码） |

端到端用模板 + 跑优化器的完整示例见 `tutorial/5.template.cpp`。

### 6.1 各模板构造 API（关键 setter → `getProblem()`）

> 通用：所有模板 `setName(name)` 可选；多数图/惩罚型有 `setPenalty(p)`；最后 `getProblem()` 返回 `Problem*`。exact `setData` 参数详见各头文件。

| 模板 | 关键构造 setter |
|---|---|
| `PT_TSP` | `setCitys(pos, n, dim)` 或 `setMap(dist, n, symmetric)`；`setEdgeWeightType(DistanceType::{Eula/Manhattan/Chebyshec}, RoundType)` |
| `PT_QAP` | `setFacilities(n, flow_matrix)`；`setLocations(n, distance_matrix)`（均支持一维数组或 `vector<vector<double>>`） |
| `PT_MKP` | `setResourceNumber(r)`；`addBackpacks(n, capacities)`；`addItems(n, profits, occupy)`；`setItemValueSort(bool)` |
| `PT_Numerical` | CEC 基准（`Benmarks::{P_default/CEC2013_N/CEC2013_L}`，数值优化） |
| `PT_MDS` | `setGraph(n, edges)`；`setPenalty(p)` — 最小支配集 |
| `PT_MIS` | `setGraph(n, edges)`；`setPenalty` / `setDegreeSort(bool)` — 最大独立集 |
| `PT_CVRP` | `setData(N, xs, ys, dem, cap...)`；`setVehicles(K)`；`setSplitMode({Greedy/Optimal/Linear})` |
| `PT_CFLP` | `setData(F, M, cap, fcost, ...)`；`setPenalty` — 容量设施选址 |
| `PT_CPMP` | `setData(N, p, cap, dem, d)`；`setHeuristic({GreedySeed/Composite})` — 容量 p-中位 |
| `PT_FJSP` | `setData(ops, M, proc, prev)`；`setSeqMode({Const/Variable})`；`setSeqHeur({MWKR/Random})` |
| `PT_WFS` | `setData(...)`；`setSeqMode`/`setSeqHeur`/`setMapHeur({Fastest/EFT})`/`setObjMode({MaxMakespan/AvgMakespan})` |
| `PT_STP` | `setGraph(nv, edges, w, terminals)`；`setHeuristic({Spanning/SteinerPrune})` |
| `PT_SR` | `addFunctions({Add,Sub,Mul,...})`；`setConstantPool(count,lo,hi)` 或 `setConstants(...)`；`setHeadLength(h)`；`setData(...)`；`ObjMode::{Regression/Heuristic}` |

> 模板同时是"如何用问题模块接口组合完整问题"的最佳参照——想加新模板或看约束/启发怎么搭，读对应 `pt-*.h` 即可。
