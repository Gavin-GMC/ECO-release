# 11 · 使用者篇 · 优化器配置

用 C++ **`ConfigBuilder`** fluent API 或 Python **`evoflow.Config`** 装配优化器：换算法 = 换配置行，不改代码结构。
完整 C++ 示例见 `tutorial/1.optimizerconfig.cpp`，Python 配置与运行示例见 `python/examples/config_model.py`、`python/examples/run_optimizer.py`；批量生成配置表见 `tutorial/config-generate*.cpp`。

> `ConfigBuilder` 随 `evoflow.h` 即得（v3.12 起，见审查 R1 修复），无需再单独 include。

## Python 配置接口（2.6.3）

Python 的 `Config` 直接持有 C++ `FullConfig`，配置编解码、组件目录和校验继续使用平台原生实现；它不是一份与 C++ 漂移的字典副本。

```python
from evoflow import Config

config = Config
config.name = "python_pso"
config.max_fes = 100_000

workflow = config.add_workflow("wf")
workflow.set_initializer("Random")
workflow.add_topology("PGBest")
workflow.add_repair("Random")
workflow.add_strategy("VelocityDriven", [2, 2, 0.9, 0.4, 0])
workflow.add_generator("OrderedConstruct", [0])
workflow.add_evaluator("Basic")
workflow.add_selector("Index", [0])

subpopulation = config.add_subpopulation("1", size=100, workflow="wf")
subpopulation.max_fes = 100_000

report = config.validate(deep=True)
if report.ok:
    config.save("python-pso.cfg")
```

- `Config.load/from_text` 自动探测 v3.1/v3.2；`to_text/save` 默认保留来源版本，传 `"v3.1"` 或 `"v3.2"` 可显式转换。新建配置默认 v3.1。
- 参数序列中的 Python `None` 对应 C++ `EMPTYVALUE`，写 v3.1 为 `nan`、写 v3.2 为 `null`；终止条件的 `None` 表示不限。
- `config.validate` 返回结构化静态校验报告；`status` 为 `error / warning / info / pass` 中最高级，单条 `issue.severity` 使用前三种，`pass` 只表示没有发现问题。`ok` 仅在 Error 或加载失败时为假，因此 Warning/Info 不阻止保存、装配或运行。`deep=True` 会真实装配一次再销毁，但不会运行优化器。
- `component_categories/list_components/resolve_parameter_schema` 提供 12 类组件、5 类初始化器和渐进参数 schema；`component_requirements/component_provisions` 查询给定参数下的装配依赖与供给。
- `Workflow.components` 返回只读快照；增、换、移、删通过工作流方法完成。工作流或子群发生删除/清空后，之前取得的同类句柄会明确抛 `RuntimeError`，不会访问悬空地址；单纯追加不使旧句柄失效。
- `console_echo` 是运行期属性，不写入 `.cfg`；2.6.4 起可将配置直接交给 Python `Optimizer` 构建和运行。

## Python 运行接口（2.6.4）

`Optimizer` 从 `Problem`/`CompiledProblem` 与 `Config` 形成原生深快照；构造完成后修改或销毁源对象，不改变已经装配的优化器。

```python
from evoflow import Config, Optimizer, Problem, VariableType

problem = Problem("sphere")
problem.add_variable("x", -5, 5, 0.001, 5, type=VariableType.CONTINUOUS)
problem.add_objective("f", "x", lambda x: sum(v * v for v in x))

# config 为上一节构造的 Config；也可用 Config.load(...)。
optimizer = Optimizer(
    problem, config,
    optimizer_name="PSO_sweep_01",  # 可选：稳定的输出身份
    max_fes=20_000,
)
result = optimizer.run(
    seed=42,
    runs=3,
    progress=lambda completed, total: print(completed, total),
)
print(result.tag, result.best_fitness)
for round_result in result.rounds:
    print(round_result.run, round_result.result_index, round_result.best_fitness)
```

- `Optimizer.run` 可重复调用，每次重新初始化问题种群。默认编号会扫描同一“优化器 + 问题 + tag”的磁盘结果，从最大已占用编号之后续号；同一对象、重建对象和跨进程调用都不会静默覆盖。
- `round_result.run` 是本次调用内从 1 开始的轮次，`round_result.result_index` 是 `.rslt/.prcs` 文件名中的零基编号；`result.run_start` 是本批首个实际编号。
- 需要固定编号时传 `run_start=N`。已存在时默认整批拒绝；只有同时给 `replace_existing=True` 才会事务替换。替换批次失败或取消会恢复旧 `.rslt/.prcs`，且 `replace_existing=True` 不允许省略 `run_start`。
- `runs=N` 保持 C++ 契约：只用 `seed` 播种一次，N 轮延续同一随机流；不是 `seed+i`。同一 `Optimizer`、同一 seed 的独立 `run` 调用可复现。
- 构造器的 `max_fes/max_convergence/max_time=None` 表示不覆盖配置；给定非负整数时同时覆盖全局和所有子群，与 CLI 一致。`verbose=True` 在运行期打开过程记录和控制台回显。
- `progress(completed, total)` 在每一完整轮结束后调用，表示轮数进度而非 FES。`cancelled` 在原生终止检查点调用；返回真后会被锁存。正常取消返回 `cancelled=True, ok=False` 的部分 `RunResult`。
- 运行、装配和 Python 回调失败抛 Python 异常。进度/取消回调即使在原生观察器边界内出错，也会在原生安全返回后恢复为 `RuntimeError`，不会静默丢失。
- 同一个 `Optimizer` 不可并发运行，也不可从自己的回调重入；可使用互不共享的多个实例。并行构建下 Python 目标函数仍须线程安全。

一次性内存入口 `run(problem, config, ...)` 等价于构造临时 `Optimizer` 后运行。已有问题文件和配置文件可直接走 App/CLI 同源入口：

```python
from evoflow import run_files

result = run_files(
    "_pdata/tsp/sample.tsp",
    "config/ACS.cfg",
    seed=42,
)
```

文件运行普通失败抛 `RuntimeError`；正常取消同样返回部分结果。

成功、未取消的单轮运行可从当前种群状态继续：

```python
first = optimizer.run(seed=42)
more = optimizer.continue_run(max_fes=5_000)
```

`continue_run` 至少要给一个正的新增上限，可连续调用；多轮运行、取消或失败后不可调用。它只是原生 `continue_exe` 的安全门面，不是暂停、检查点或跨进程恢复。原生 continuation 没有进度、取消和新日志钩子，因此 Python 入口也不提供这些参数。

## 1. 配置骨架

```cpp
#include "evoflow.h"
using namespace EvoFlow;

ConfigBuilder cb;

// (A) 一条 workflow = 算子流水线
auto wf = cb.workflow("wf");
wf.initializer("Random");        // 初始化
wf.topology.pgBest;            // 学习拓扑(谁向谁学)
wf.repair.boundary;            // 修复(越界处理)
wf.strategy.velocityDriven(2, 2.0, 0.9, 0.0001);  // 学习策略(怎么生成)
wf.generator.generation;      // 子代生成框架
wf.evaluator.basic;           // 评估
wf.selector.index(false);       // 环境选择

// (B) 优化器级
cb.name("run").maxFES(40000).manager("Single").gArchive("Basic");
cb.logging(false);              // 日志(结果/过程/详细过程/整群)   起第 4 参 swarm
cb.consoleEcho(true);           // 进度回显控制台(不落 .cfg,仅运行期;等价 CLI -v)

// (C) 子种群(绑定 workflow + 规模;个体类型无需指定,特性由装配期推断)
cb.subpopulation("1").size(20)
  .workflow("wf").maxFES(40000).archive("Basic");

// (D) 装配 → 接入问题 → 运行
Optimizer* opt = cb.buildOptimizer;
opt->setProblem(&problem);      // Problem* 或 ProblemHandle*
opt->exe(42);                   // 播种 42 跑一次;多轮: opt->exe(30, 42)
Solution* best = nullptr; int n = 0;
opt->getBest(best, n);
delete opt;
```

### 多段 workflow
一条 workflow 可含**多段**「拓扑→策略→生成」，末尾统一评估+选择。段内 offspring 累积，段末选择一次。典型：GA = 交叉段 + 变异段（变异段用 `topology.continueGraph` 续接交叉产物 + `generator.generation(true)` 原地串联）。也可多组「评估+选择」（如免疫的双 select）。
```cpp
wf.topology.tournament(2,1); wf.strategy.sbxCrossover(20,1); wf.generator.generation;
wf.topology.continueGraph;  wf.strategy.pmMutation(20,0.01); wf.generator.generation(true);
wf.evaluator.basic; wf.selector.rank;
```

`inplace=true` 不创建新子代，只原地修改前段留下的 offspring，因此必须同时满足：当前仍有**未评估、未被 Selector 合入**的子代；当前拓扑以这些 offspring 为学习图起点。内置可用拓扑为 `Continue` 和 `ContinueRankExtremesTriRandom`。普通亲代拓扑、`Inherit`、`NoChange`，以及放在 Evaluator 或 Selector 之后的 inplace Generator，都会在静态校验阶段被拒绝。

续接状态按实际对象分别建模：`Continue`/`ContinueRankExtremesTriRandom` 读取当前 offspring；`Inherit` 同时读取当前 offspring 与 last graph；`NoChange` 只复制 last graph。因此 Selector 之后前两类与 Inherit 会因 offspring 已被清空而拒绝，而 NoChange 仍可复用本次 workflow 尚存的 last graph。Evaluator 会把子代标为已评估、从而禁止后续 inplace，但不会删除 offspring；last graph 在本次 `workflow.run` 结束时才释放。

组件依赖始终针对 Generator 位置上的**当前配置**：新的 `component strategy ...` 会替换当前策略，不能继承前一段策略曾声明的 `constructive` 等能力；topology 和 repair 同理。`AdaptiveOperatorSelection` 是参数化例外：轮盘可能选择池中任一算子，所以只有整个算子池都支持逐维构造时，才能与 `OrderedConstruct`/`ParallelConstruct` 配合；混合池即使包含 `Gauss`，只要还包含 `Overturn` 等整体型算子，就会在静态校验阶段拒绝。

## 2. 装配期校验（两道，依次执行）

`buildOptimizer` / `buildSubpopulation` 在装配前依次跑**两道**校验。Error 即**抛异常**（早失败），Warning 落 `sys_logger.warning`，Info 只在显式 `validate` 的结构化结果中展示，避免给正常运行日志加入无害冗余：

| 顺序 | 校验 | 管什么 | 禁用宏 |
|---|---|---|---|
| ① | **AssertMatcher** | **组件间契约**（策略需要拓扑产出几个学习对象、生成器前须有 repair、tag 是否存在…） | `EVOFLOW_DISABLE_ASSERT_VALIDATION` |
| ② | **ParamMatcher** | **组件自身参数**（元数 / 留空合法性 / 取值范围 / 整值性） | `EVOFLOW_DISABLE_PARAM_VALIDATION` |

> 次序有意为之：assert 含"tag 合法"检查——tag 都不认识时再报参数错只会淹没真正的原因。
> 两个宏在 [optimizer-builder.h](../../src/optimizer/orchestrate/optimizer-builder.h) 顶部以注释形式列出，**取消注释即禁用**（风格沿用原 EvoFlow 的 `EVOFLOW_DISABLE_BUILD_VALIDATION`）。正常使用**不应禁用**——它们拦的多是静默错误（见下）。

### 2.1 参数校验规则（ParamMatcher）

对每个组件，按其注册项的 `ParameterTemplate` 校验 `para`：

| 规则 | 说明 |
|---|---|
| **全空即全默认** | `para` **完全为空** → 合法，组件用内部默认（装配器对空 para 传 `nullptr`，各工厂走缺省路径，根本不读 para） |
| **非空即须完整** | `para` **一旦非空就必须给全** —— 工厂按位置无条件读（如 `p[1]`、或把 `p+2` 交给内层组件），少给即**越界读**。想"只设前几个、后面用默认"→ **显式传 `EMPTYVALUE`**，不要省略 |
| **留空须获许可** | 值为 `EMPTYVALUE` 时，该参数须声明了 `allow_empty`，否则报错 |
| **范围** | 非空值须落在硬边界 `[low, high]` 内 |
| **整值** | `Int` / `Enum` 类参数须为整值 |

**它拦下的都是"不报错的错"**：`Index` 配 `accept_type=2`(退火) 却只给 1 个参数 → 装配器会读越界内存；`TabuDecorator` 不给内层算子参数 → 同理。这类问题在本校验上线前**只会表现为"结果有点怪"**。

### 2.2 参数的机读方式（自动化配置程序）

`ParameterTemplate` 是每个组件参数的**权威 schema**，本就是为**自动化配置程序**提供的机读入口（装配期校验只是它的第二个消费方）。经注册表取用：

```cpp
auto& reg = Registry<LearningStrategy>::instance;
const ParameterTemplate* tpl = reg.params("Index");
// tpl->params 每项:{name, kind(Enum/Int/Real), low, high, allow_empty, rec_low, rec_high}
//   low/high  = 硬边界(校验用)      rec_low/rec_high = 推荐区间(采样用)
//   allow_empty = 可否留空(EMPTYVALUE → 组件用内部默认/自适应)
```

**渐进披露**：部分组件**后续参数的 schema 由前面参数的取值决定** —— 须先定前一级，才能问出下一级。模板**自包含**（`next` 就在 `ParameterTemplate` 上），故逐级走即可：

```cpp
double para[] = { 2 };                                  // accept_type = 2(退火)
ParameterTemplate lv2 = tpl->nextLevel(para, 1);        // → {T0, decay}
// accept_type=1(择优) 时同样调用 → 返回空模板(择优准则零参)
bool progressive = tpl->hasNext;                      // 本级之后是否还有下一级
```

| 组件 | 第一级 | 下一级由谁决定 |
|---|---|---|
| `Index`/`Close`/`Kinship` | `{accept_type}` | 选中的**接受准则**的参数（仅退火有：`T0`·`decay`） |
| `TabuDecorator` | `{inner, tenure}` | `inner` 选中的**内层算子的完整模板**（含其自身的下一级） |
| `AdaptiveOperatorSelection` | `{rho, segment_len, op_count}` | `op_count` 个算子枚举 |

**采样流程**（定长组件 `nextLevel` 返回空模板，可统一处理）：

```cpp
std::vector<double> para;
ParameterTemplate cur = *reg.params(tag);
size_t base = 0;                                        // 本级在 para 中的起点
while (true) {
    for (const ParamInfo& pi : cur.params) para.push_back(sample(pi));   // 采本级
    if (!cur.hasNext) break;
    ParameterTemplate nxt = cur.nextLevel(para.data + base, para.size - base);   // ★ 传本级切片
    if (nxt.params.empty && !nxt.hasNext) break;
    base += cur.params.size;
    cur = nxt;
}
```

> ⚠ **`nextLevel` 收的是「本级切片」，不是整个 para** —— 每个模板都从自己的下标 0 看世界、不关心嵌在第几层。这正是 `TabuDecorator` 能把内层算子的模板**原样返回**（连同其自身的下一级）的前提。
> 采完后可用 `ParamMatcher::validate(tpl, para)` 自检。
>
> 设计约束：模板**只声明组件自己的参数**——别的组件的参数经 `next` 渐进披露，不拍平进来。故 `Index` 的模板只有 `{accept_type}`，`T0`/`decay` 属 `AnnealAccept`、仅在 `accept_type=2` 时披露。

### 2.3 组件间契约（AssertMatcher）

静态结果按最高严重级聚合：

| 级别 | 判定边界 | 对保存、装配和运行的影响 |
|---|---|---|
| **Error** | 静态可确定无法构建、组件链确定无效或参数非法 | 阻止装配与运行 |
| **Warning** | 可以构建，但无法保证正常执行或退出，例如可能零评估空转 | 不阻止；运行前应处理或明确接受风险 |
| **Info** | 可以执行并退出，但语义、结果或效率可能偏离预期，或存在无害冗余 | 不阻止；供用户核对意图 |
| **Pass** | 静态检查没有发现配置问题 | 仅为整体状态，不产生单条 issue；不等于证明所有运行时输入都安全 |

组件契约中，`notLessButNotice` 的“少于需要数”仍是 **Error**，只有“供给多于需要数”才产生 **Info**；`anyButNotice` 的不精确或缺失产生 **Info**。需要表达“仍可构建，但无法保证正常执行或退出”时，组件必须显式使用 `anyButWarning`。硬条件仍使用 `notLess` / `equal`，失败即 Error。

常见契约：
- **个体特性**：某些策略/拓扑需逐个体状态（velocity/pbest/sigma/…）。**INDIV-COMPOSE 后无需配置个体类型**——组件经 `featureDemands` 声明所需特性，装配期自动推断并逐个体挂载（下表"声明的特性"列）。
- **拓扑学习对象数（objects）**：某些策略要求拓扑产出 ≥N 个学习对象。`VelocityDriven` 与 `SetVelocityDriven` 的 N 取各自配置的 `object_number`；拓扑供给不足会造成学习对象数组越界，因此属于 Error，不能构建。供给更多时策略只读取前 N 个，报告 Info 提示冗余。

WWO 折射段还有两条组合检查：

- `WaveRefractionActivation + WaveRefraction` 会按波高激活并把波高重置为正值。若整条 workflow 没有任何实际使用 `WavePropagation` 的生成段维护/递减波高，某些状态下可能所有个体都直通、FES 不再增长，外层循环无法保证退出，因此报告 **Warning** `wave_refraction_without_height_progress`。
- `WaveRefraction` 的波长更新与直通语义以子代和亲代的同索引无条件替换为基础；后续不是 `Index(0)` 时仍可运行，但会改变该语义。例如 `Rank` 报告 **Info** `wave_refraction_selector_semantics`。

因此 `WaveRefractionActivation → Greedy → WaveRefraction(16) → Generation(0) → Basic → Rank` 的聚合状态为 **Warning**：其中缺少波高推进是 Warning，Rank 是 Info；`Generation` 与 `Greedy` 本身不因这组静态组合被额外判错。标准闭环应在 workflow 中包含实际执行的 `WavePropagation` 生成段，并在折射段后使用 `Index(0)`。

| 策略 | 声明的特性（自动挂载） | 需要的拓扑(objects) |
|---|---|---|
| `velocityDriven`(PSO) | velocity（+ pbest 由 `pgBest` 声明） | objects ≥ `object_number`；默认 2 可配 `pgBest`(2) |
| `setVelocityDriven`(SetPSO) | setvelocity（pbest 由拓扑声明，若用 pgBest） | objects ≥ `object_number`；默认 2 可配 `pgBest`(2) |
| `gaussianSelfAdapt`(ES) | sigma | `isolate`(0) |
| `greyWolfEncircling`(GWO) | —（无逐个体状态） | `topRanked(3)`(≥3) |
| `whaleForaging`(WOA) | whalestate | `leaderAndRandom`(2) |
| `gaussianSpark`(FWA 高斯火花) | fireworkstate | `randomSelect(m̂)` |
| 交叉/变异/EDA/普通策略 | —（无） | 视策略而定 |

## 3. 算子目录（tag / 参数 / 适用编码）

> 参数以 config-setter.h 的具名方法为权威。编码：**连续**=实数域、**排列/序列**=离散置换、**二进制**=0/1。

### 3.1 学习拓扑 `wf.topology.*`
| 方法 | 语义 | objects |
|---|---|---|
| `pgBest` | pbest + gbest（PSO 族） | 2 |
| `randomLearning(n)` | 每体随机 n 个学习对象（DE 族） | n |
| `isolate` | 不学习、自扰动（ES/EDA/ACO） | 0 |
| `elite(e, r)` | 前 e 精英各重复 r 次作起点 | 1 |
| `competition` | 竞争配对（CSO） | — |
| `levelBasedLearning(l)` | 分层学习（LLSO） | — |
| `stochasticDominantLearning` | 随机占优（SDLSO） | — |
| `continueGraph` | 续接上段产物（多段变异用） | — |
| `inherit` / `noChange` | 继承/不变上代图 | — |
| `roulette(n)` / `tournament(s,n)` / `uniform(n)` | 轮盘/锦标赛/均匀选 n 学习对象 | n |
| `topRanked(k)` | 当代前 K 名（GWO 用 3） | k |
| `leaderAndRandom` | 全局最优 + 随机个体（WOA） | 2 |

> **运行时空决策**（v3.0.0.4–3.0.0.5）：上述配置无需为 `EMPTYVALUE` 增加特殊参数。第一类矩阵边界中，AS/ACS/MMAS 遇到空路径前驱时让当前维继续保持空；集合 SPSO 不学习含空端点的序列边，且当前位置为空时不执行 position crisp；EDA 逐维忽略空样本。第二类数值传播中，CMA-ES 只用完整解维护分布，完整父代不足时冻结该代更新；Competition/LeaderRandomCenter 的逐维中心忽略空成员；GOA 跳过空邻居；VelocityDriven、RSA 与 Aquila 从有效领袖/向导恢复，辅助向导为空时回退，无有效来源时保留空。它们都沿用问题侧的有限最劣值契约，不抛异常、不警告、不停止优化。

**交叉**（GA，`coupled` 默认 true）:`pointCrossover(pts,rate)` / `uniformCrossover(rate)` / `sbxCrossover(η,rate)` / `differenceCrossover(rate,F)`（DE 差分）/ 序列型 `partialMapped/cycle/order/subtourExchange/positionBased Crossover(rate,...)`。
**变异**:`bitMutation(rate)` / `bitFlipMutation(rate)` / `pmMutation(η,rate)` / `gaussMutation(σ,rate)` / 片段型 `overturn/exchange/insert/reorder/segmentRelocate(times,rate)` / 序列扩充 `cyclicExchange(k,rate)`、`blockSwap(times,rate)` / 值类族 `multiPointSameValue(point_rate)`、`setExchange(subset_rate)`、`classRelocate(subset_rate)`、`classMerge(rate)`（详见 [§6 先进邻域](#先进邻域v1462均问题无关纯编码级)）。

> ⚠ `mutation_rate` 在变异族**有两种语义**，由算子所属的族决定：
> - **逐维选中概率** —— `bit`/`bitFlip`/`pm`/`gauss`：每一维**独立**以该概率被选中变异（`rate=1` 即每维必变）。
> - **整体施加概率** —— `overturn`/`exchange`/`insert`/`reorder`/`segmentRelocate`/`cyclicExchange`/`blockSwap`/`classMerge`：本次算子**做或不做**。
> - 独立命名者：`multiPointSameValue(point_rate)` 逐维选中、`setExchange`/`classRelocate` 的 `subset_rate` 为类成员入选概率且**可留空**（EMPTYVALUE → 免参随机抽率）。

> GA/DE 无独立策略类 = 交叉+变异+拓扑的组合（多段 workflow）。

## 5. 并行执行（子群级）

- **默认串行**。**编译期宏 `EVOFLOW_PARALLEL_SUBPOP` 激活子群级并行**——一轮内 N 个子群的迭代分派到 N 个线程并行跑。构建时加 `/D EVOFLOW_PARALLEL_SUBPOP`（或 CMake `add_compile_definitions(EVOFLOW_PARALLEL_SUBPOP)`）；不加即串行（默认构建行为不变）。
- **收益边界**：只有**多子群**（island-model，`manager("NoInteraction"/"Immigrant"/...)` + 多个 `subpopulation(...)`）获益；**单子群退化为串行**（不起线程）。评估越昂贵、子群越多，加速越明显；**评估平凡时线程开销可能盖过收益**。实测 8 子群 / 16 核、昂贵评估 ≈ **6× 加速**。
- **可复现保证**：**同 seed 必同结果，与串行/并行、与线程调度无关**——各子群持独立确定性 RNG + 独立问题句柄 + 预分好的预算，汇集按子群号顺序。故**串行与并行结果逐位一致**（可用于验证正确性）。
- **⚠ 目标函数线程安全契约**：并行下多个子群**并发调用**你的目标函数/约束。**你的目标函数必须线程安全**：① 不得用共享可变的全局/静态态做过程缓存；② 随机必须用框架的 per-子群 RNG（`get_int`/`rand01`/`get_normal` 等），不要自持全局随机器。框架无法静态强制这点——激活并行时会在运行期打印一条提醒让你自检。**带共享全局态的目标函数请勿激活并行**（默认串行即安全）。

## 6. 配置序列化（保存/加载配置表）

**按文件 save/load**（ CONFIG-IO，`ConfigBuilder` 静态方法，FullConfig↔文件）：
```cpp
ConfigBuilder::saveConfig(fc, "myrun", "v3.1", "config");  // 写 config/myrun.cfg(ver 缺省 v3.1)
FullConfig fc = ConfigBuilder::loadConfig("myrun", "config");  // 读 config/myrun.cfg → 首行探测版本 → 解码
```
- **统一后缀 `.cfg`**（纯文本）；**版本仅由首行分派**（`<ver= v3.1>` 文本 / `{"version":"v3.2"` JSON），**不用后缀区分版本**；未知版本/缺文件抛异常。
- 底层 codec：`ConfigCodecV31::encode/decode`（v3.1 文本）/ `ConfigCodecV32`（v3.2 JSON，`config-codec-json.h`）。`detectVersion(text)` 读首行判版本。
- 批量生成配置表见 `tutorial/config-generate*.cpp`（经 `saveConfig` 落 `config/*.cfg`）。

**未设置参数（EMPTYVALUE）的表示**：参数模板标 `allow_empty` 的项可以“留空”，表示“用组件内部默认/自适应”（如 `tao_ini`、`factor`、PSO 族的 `w_final`、`subset_rate`）。PSO 族在 `w_final` 留空时保留随机惯性模式，而不是执行线性调度。两种格式的落盘写法**不同**：

| 格式 | 未设置参数写作 | 说明 |
|---|---|---|
| v3.1 文本 | `nan` | `std::stod("nan")` 原样读回 |
| v3.2 JSON | **`null`** | **裸 `nan` 不是合法 JSON**，故用 `null`——语义恰为"无值"。读回即 EMPTYVALUE（**不是 0**） |

> ⚠ 读取旧配置：早期 v3.2 编码会印出裸 `nan`（非法 JSON，且当时的解码器会**解析错位并抛异常**）。现解码器容错读取这类旧产物，但**新写出的一律是 `null`**。
> ⚠ 手写配置时，未设置参数在 JSON 里请写 `null`、在文本里写 `nan`；**不要写 0** —— `0` 是一个**确定的取值**，与"未设置"语义不同（如 `subset_rate=0` 意为"子集恒空、不变异"，而留空意为"每次随机抽概率"）。

|---|---|---|---|---|---|
| **Path Relinking**（路径重连） | `repeatWithBest(k)`（每体 k 起点，端点=当代最优作向导解） | `pathRelinking` | gen | `index(true)` | **无参数**；β~U(0,1) 每子代一抽（`relinkdepth` 标量特性自动挂载）= k 点采样式路径扫描 |
| **ALNS**（自适应大邻域） | `isolate` | `adaptiveOperatorSelection(ρ, segment_len, ops)` | gen | `index(true)` 或 `indexAnneal(T0,decay)` | 算子池 `ops` 传 tag 枚举；每代轮盘选一个算子，按 σ1/σ2/σ3 记分、每 `segment_len` 代更新权重 |

**邻域算子扩充**（可直接用作上述 `ops` 池成员，或单独作邻域策略配爬山/退火/禁忌）：

| 算子 | 一句话 | 适用编码 |
|---|---|---|
| `cyclicExchange(k, rate)` | k 个互异维**环状轮转**（k=2 即 `exchange`）；守恒 | 排列/序列 |
| `blockSwap(times, rate)` | **任意两段互换**（长度可不等、可隔距）；守恒。`segmentRelocate`（相邻）与 `exchange`（单维）均为其退化域 | 排列/序列 |
| `multiPointSameValue(point_rate)` | 逐维以 `point_rate` 选中 → **全置同一个**随机值（与 `bit` 只差"是否共用一个值"） | 通用/指派 |
| `setExchange(subset_rate)` | 两个**值类**各取随机子集**互换取值**（成组再平衡）；**留空→免参**（两侧各随机抽率） | 指派/分组 |
| `classRelocate(subset_rate)` | 一个值类的随机子集**单向迁到新值**（能**启用未使用值 / 拆分类**——`setExchange` 做不到）；**可留空** | 指派/分组 |
| `classMerge(rate)` | 一个值类**整体并入另一现值** → **在用值个数确定减 1**（整合/关停） | 指派/分组 |

> **值类族四方向已齐**：对调（`setExchange`）· 拆分/外迁（`classRelocate`）· 合并（`classMerge`）· 逐维塌缩（`multiPointSameValue`）。
> 端到端与语义验证见 `tests/optimizer/strategy/smoke-{pathrelink,alns,multipoint,cyclicexchange,setexchange,classrelocate,blockswap,classmerge}.cpp`。

### 精英解局部搜索（**段追加到任意 workflow 末尾**的强化）
每代取若干精英、邻域生成候选、择优替换。按 setter 调用顺序**接在主算法各段之后**（`components`=执行序）。两条来源路径，select 层区分：

| 路径 | 拓扑 | 策略 | 选择器 |
|---|---|---|---|
| **种群 top-e**（血缘定向） | `topIndividual(e, r)`（起点=种群槽） | 邻域算子（`differencePerturbation`/`gauss`…） | `kinshipGreedy`（读 `parent_id` 归属回精英槽、优则**替换精英**） |
| **档案精英**（全局归并） | `elite(e, r)`（档案精英/内部 buffer） | 高斯等（端点=自身，不能用差分） | `rank` |

> 血缘 id 由 `RunGenerate` 通用盖（种群路径）；kinship 特性由 `kinshipGreedy` 声明、装配期自动挂载。配置表 `elite_pop_pso`/`elite_archive_pso`、教程 `tutorial/6.elite-local-search.cpp`、端到端 `tests/optimizer/strategy/smoke-elite-ls.cpp`。

### 多目标（Pareto；档案用 `Multiobject`，各目标设**同优先级**、全最小化）
| 算法 | 个体特性(自动挂载) | 拓扑 | 策略 | 生成器 | 选择器 | 修复 |
|---|---|---|---|---|---|---|
| **NSGA-II** | —（无特性） | `tournament(2,1)` + `continueGraph` | SBX + PM（2 段） | gen + gen(true) | **`rankCrowding`**（非支配 rank + 拥挤度） | boundary |
| **MOEA/D** | —（无特性） | `neighborhood(T,δ)` + `continueGraph` | SBX + PM（2 段） | gen + gen(true) | **`scalarReplace(nr,T)`**（Tchebycheff 邻域替换；T 须与拓扑一致） | boundary |

> 多目标端到端见 `tests/optimizer/multiobjective/smoke-nsga2.cpp` / `smoke-moead.cpp`；批量配置见 `tutorial/config-generate-multiobjective.cpp`。

**各算法"本质" = 哪几个组件决定它**：PSO=velocity 特性+PGBest；局搜=Isolate+邻域变异+择优接受（退火换 Metropolis）；GA=锦标赛+交叉/变异两段；ACO/EDA=Isolate+构造生成器/分布策略；GWO/WOA/免疫/FWA=各自的专用拓扑+策略（详见对应 tutorial 与 24 清单）。完整可运行配方见 `tutorial/config-generate*.cpp`。
