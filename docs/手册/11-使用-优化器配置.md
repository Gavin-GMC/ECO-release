# 11 · 使用者篇 · 优化器配置

用 **`ConfigBuilder`** fluent API 装配优化器：换算法 = 换配置行，不改代码结构。
完整可运行示例见 `tutorial/1.optimizerconfig.cpp`；批量生成配置表见 `tutorial/config-generate*.cpp`。

> `ConfigBuilder` 随 `ecflow.h` 即得（v3.12 起，见审查 R1 修复），无需再单独 include。

---

## 1. 配置骨架

```cpp
#include "ecflow.h"
using namespace ECFlow;

ConfigBuilder cb;

// (A) 一条 workflow = 算子流水线
auto wf = cb.workflow("wf");
wf.initializer("Random");        // 初始化
wf.topology.pgBest();            // 学习拓扑(谁向谁学)
wf.repair.boundary();            // 修复(越界处理)
wf.strategy.velocityDriven(2, 2.0, 0.9, 0.0001);  // 学习策略(怎么生成)
wf.generator.generation();      // 子代生成框架
wf.evaluator.basic();           // 评估
wf.selector.index(false);       // 环境选择

// (B) 优化器级
cb.name("run").maxFES(40000).manager("Single").gArchive("Basic");
cb.logging(false);              // 日志(结果/过程/详细过程)

// (C) 子种群(绑定 workflow + 规模;个体类型无需指定,特性由装配期推断)
cb.subpopulation("1").size(20)
  .workflow("wf").maxFES(40000).archive("Basic");

// (D) 装配 → 接入问题 → 运行
Optimizer* opt = cb.buildOptimizer();
opt->setProblem(&problem);      // Problem* 或 ProblemHandle*
opt->exe(42);                   // 播种 42 跑一次;多轮: opt->exe(30, 42)
Solution* best = nullptr; int n = 0;
opt->getBest(best, n);
delete opt;
```

### 多段 workflow
一条 workflow 可含**多段**「拓扑→策略→生成」，末尾统一评估+选择。段内 offspring 累积，段末选择一次。典型：GA = 交叉段 + 变异段（变异段用 `topology.continueGraph()` 续接交叉产物 + `generator.generation(true)` 原地串联）。也可多组「评估+选择」（如免疫的双 select）。
```cpp
wf.topology.tournament(2,1); wf.strategy.sbxCrossover(20,1); wf.generator.generation();
wf.topology.continueGraph();  wf.strategy.pmMutation(20,0.01); wf.generator.generation(true);
wf.evaluator.basic(); wf.selector.rank();
```

## 2. 装配期校验（两道，依次执行）

`buildOptimizer()` / `buildSubpopulation()` 在装配前依次跑**两道**校验，任一硬失败即**抛异常**（早失败），警告落 `sys_logger.warning`：

| 顺序 | 校验 | 管什么 | 禁用宏 |
|---|---|---|---|
| ① | **AssertMatcher** | **组件间契约**（策略需要拓扑产出几个学习对象、生成器前须有 repair、tag 是否存在…） | `ECFLOW_DISABLE_ASSERT_VALIDATION` |
| ② | **ParamMatcher**（v1.4.6.4） | **组件自身参数**（元数 / 留空合法性 / 取值范围 / 整值性） | `ECFLOW_DISABLE_PARAM_VALIDATION` |

> 次序有意为之：assert 含"tag 合法"检查——tag 都不认识时再报参数错只会淹没真正的原因。
> 两个宏在 [optimizer-builder.h](../../src/optimizer/orchestrate/optimizer-builder.h) 顶部以注释形式列出，**取消注释即禁用**（风格沿用原 ECFlow 的 `ECFLOW_DISABLE_BUILD_VALIDATION`）。正常使用**不应禁用**——它们拦的多是静默错误（见下）。

### 2.1 参数校验规则（ParamMatcher）

对每个组件，按其注册项的 `ParameterTemplate` 校验 `para`：

| 规则 | 说明 |
|---|---|
| **全空即全默认** | `para` **完全为空** → 合法，组件用内部默认（装配器对空 para 传 `nullptr`，各工厂走缺省路径，根本不读 para） |
| **非空即须完整** | `para` **一旦非空就必须给全** —— 工厂按位置无条件读（如 `p[1]`、或把 `p+2` 交给内层组件），少给即**越界读**。想"只设前几个、后面用默认"→ **显式传 `EMPTYVALUE`**，不要省略 |
| **留空须获许可** | 值为 `EMPTYVALUE` 时，该参数须声明了 `allow_empty`，否则报错 |
| **范围** | 非空值须落在硬边界 `[low, high]` 内 |
| **整值** | `Int` / `Enum` 类参数须为整值 |

**它拦下的都是"不报错的错"**：`Index` 配 `accept_type=2`(退火) 却只给 1 个参数 → 装配器会读越界内存；`TabuDecorator` 不给内层算子参数 → 同理。这类问题在本校验上线前**只会表现为"结果有点怪"**。

### 2.2 参数的机读方式（自动化配置程序）

`ParameterTemplate` 是每个组件参数的**权威 schema**，本就是为**自动化配置程序**提供的机读入口（装配期校验只是它的第二个消费方）。经注册表取用：

```cpp
auto& reg = Registry<LearningStrategy>::instance();
const ParameterTemplate* tpl = reg.params("Index");
// tpl->params 每项:{name, kind(Enum/Int/Real), low, high, allow_empty, rec_low, rec_high}
//   low/high  = 硬边界(校验用)      rec_low/rec_high = 推荐区间(采样用)
//   allow_empty = 可否留空(EMPTYVALUE → 组件用内部默认/自适应)
```

**渐进披露**：部分组件**后续参数的 schema 由前面参数的取值决定** —— 须先定前一级，才能问出下一级。模板**自包含**（`next` 就在 `ParameterTemplate` 上），故逐级走即可：

```cpp
double para[] = { 2 };                                  // accept_type = 2(退火)
ParameterTemplate lv2 = tpl->nextLevel(para, 1);        // → {T0, decay}
// accept_type=1(择优) 时同样调用 → 返回空模板(择优准则零参)
bool progressive = tpl->hasNext();                      // 本级之后是否还有下一级
```

| 组件 | 第一级 | 下一级由谁决定 |
|---|---|---|
| `Index`/`Close`/`Kinship` | `{accept_type}` | 选中的**接受准则**的参数（仅退火有：`T0`·`decay`） |
| `TabuDecorator` | `{inner, tenure}` | `inner` 选中的**内层算子的完整模板**（含其自身的下一级） |
| `AdaptiveOperatorSelection` | `{rho, segment_len, op_count}` | `op_count` 个算子枚举 |

**采样流程**（定长组件 `nextLevel` 返回空模板，可统一处理）：

```cpp
std::vector<double> para;
ParameterTemplate cur = *reg.params(tag);
size_t base = 0;                                        // 本级在 para 中的起点
while (true) {
    for (const ParamInfo& pi : cur.params) para.push_back(sample(pi));   // 采本级
    if (!cur.hasNext()) break;
    ParameterTemplate nxt = cur.nextLevel(para.data() + base, para.size() - base);   // ★ 传本级切片
    if (nxt.params.empty() && !nxt.hasNext()) break;
    base += cur.params.size();
    cur = nxt;
}
```

> ⚠ **`nextLevel` 收的是「本级切片」，不是整个 para** —— 每个模板都从自己的下标 0 看世界、不关心嵌在第几层。这正是 `TabuDecorator` 能把内层算子的模板**原样返回**（连同其自身的下一级）的前提。
> 采完后可用 `ParamMatcher::validate(tpl, para)` 自检。
>
> 设计约束：模板**只声明组件自己的参数**——别的组件的参数经 `next` 渐进披露，不拍平进来。故 `Index` 的模板只有 `{accept_type}`，`T0`/`decay` 属 `AnnealAccept`、仅在 `accept_type=2` 时披露。

### 2.3 组件间契约（AssertMatcher）

不兼容则**装配期抛异常**（早失败）。常见约束：
- **个体特性**：某些策略/拓扑需逐个体状态（velocity/pbest/sigma/…）。**INDIV-COMPOSE 后无需配置个体类型**——组件经 `featureDemands()` 声明所需特性，装配期自动推断并逐个体挂载（下表"声明的特性"列）。
- **拓扑学习对象数（objects）**：某些策略要求拓扑产出 ≥N 个学习对象。

| 策略 | 声明的特性（自动挂载） | 需要的拓扑(objects) |
|---|---|---|
| `velocityDriven`(PSO) | velocity（+ pbest 由 `pgBest` 声明） | `pgBest`(2) |
| `setVelocityDriven`(SetPSO) | setvelocity（pbest 由拓扑声明，若用 pgBest） | `pgBest`(2) 等 |
| `gaussianSelfAdapt`(ES) | sigma | `isolate`(0) |
| `greyWolfEncircling`(GWO) | —（无逐个体状态） | `topRanked(3)`(≥3) |
| `whaleForaging`(WOA) | whalestate | `leaderAndRandom`(2) |
| `gaussianSpark`(FWA 高斯火花) | fireworkstate | `randomSelect(m̂)` |
| 交叉/变异/EDA/普通策略 | —（无） | 视策略而定 |

## 3. 算子目录（tag / 参数 / 适用编码）

> 参数以 config-setter.h 的具名方法为权威。编码：**连续**=实数域、**排列/序列**=离散置换、**二进制**=0/1。

### 3.1 学习拓扑 `wf.topology.*`
| 方法 | 语义 | objects |
|---|---|---|
| `pgBest()` | pbest + gbest（PSO 族） | 2 |
| `randomLearning(n)` | 每体随机 n 个学习对象（DE 族） | n |
| `isolate()` | 不学习、自扰动（ES/EDA/ACO） | 0 |
| `elite(e, r)` | 前 e 精英各重复 r 次作起点 | 1 |
| `competition()` | 竞争配对（CSO） | — |
| `levelBasedLearning(l)` | 分层学习（LLSO） | — |
| `stochasticDominantLearning()` | 随机占优（SDLSO） | — |
| `continueGraph()` | 续接上段产物（多段变异用） | — |
| `inherit()` / `noChange()` | 继承/不变上代图 | — |
| `roulette(n)` / `tournament(s,n)` / `uniform(n)` | 轮盘/锦标赛/均匀选 n 学习对象 | n |
| `topRanked(k)` | 当代前 K 名（GWO 用 3） | k |
| `leaderAndRandom()` | 全局最优 + 随机个体（WOA） | 2 |
| `clonalExpansion(β)` | 克隆扩增（免疫,好抗体多克隆） | 0 |

| `fireworkExplosion(M,a,b)` | 烟花爆炸（火花数∝好坏） | 0 |
| `topIndividual(e,r)` | 种群 top-e 精英作起点 ×r + 随机同伴（精英局搜） | 2 |
| `bestAndWorst()` | 两端：end[0]=当代最优 / end[1]=当代最差（Jaya） | 2 |
| `repeatWithBest(k)` | 每体 ×k 起点、端点=当代最优（最优自身跳过；路径重连） | 1 |

### 3.2 学习策略 `wf.strategy.*`
**群体智能**
| 方法 | 算法 | 参数 |
|---|---|---|
| `velocityDriven(obj,c,w,w_att)` | PSO | 对象数,加速系数,初始惯性,惯性衰减 |
| `binaryVelocityDriven(w_att)` / `stickyBinary(c,rp,rg,ustkS)` | BPSO / 粘性 BPSO | 见签名 |
| `distributionEstimation(model,good_n,good_rate)` | EDA | model:1 Gauss/2 Cauchy/3 Uniform/4 Histogram |
| `gaussianOneFifth(σ,adapt)` / `gaussianSelfAdapt()` / `cmaes(σ)` | ES / 自适应 ES / CMA-ES | — |
| `antSystem(para)` / `maxMinAntSystem(α,β,ρ,p_best,ug,ul)` / `antColonySystem(para)` | AS / MMAS / ACS | — |
| `greyWolfEncircling(a_max,a_min)` | GWO | a 衰减边界(默认 2/0) |
| `whaleForaging(a_max,a_min,b)` | WOA | a 边界 + 螺旋常数 |
| `affinityHypermutation(σ,base_rate,ρ)` / `randomGeneration()` | 免疫超变异 / 随机重采样 | — |
| `explosionSpark(Â,dim_rate)` / `gaussianSpark(dim_rate)` | FWA 爆炸/高斯火花 | 最大幅度,维选中率 |
| `tabuDecorator(inner,tenure,[para])` / `tabuBit(tenure)` | 禁忌搜索 | inner 邻域枚举 |

**交叉**（GA，`coupled` 默认 true）:`pointCrossover(pts,rate)` / `uniformCrossover(rate)` / `sbxCrossover(η,rate)` / `differenceCrossover(rate,F)`（DE 差分）/ 序列型 `partialMapped/cycle/order/subtourExchange/positionBased Crossover(rate,...)`。
**变异**:`bitMutation(rate)` / `bitFlipMutation(rate)` / `pmMutation(η,rate)` / `gaussMutation(σ,rate)` / 片段型 `overturn/exchange/insert/reorder/segmentRelocate(times,rate)` / 序列扩充 `cyclicExchange(k,rate)`、`blockSwap(times,rate)` / 值类族 `multiPointSameValue(point_rate)`、`setExchange(subset_rate)`、`classRelocate(subset_rate)`、`classMerge(rate)`（详见 [§6 先进邻域](#先进邻域v1462均问题无关纯编码级)）。

> ⚠ `mutation_rate` 在变异族**有两种语义**，由算子所属的族决定：
> - **逐维选中概率** —— `bit`/`bitFlip`/`pm`/`gauss`：每一维**独立**以该概率被选中变异（`rate=1` 即每维必变）。
> - **整体施加概率** —— `overturn`/`exchange`/`insert`/`reorder`/`segmentRelocate`/`cyclicExchange`/`blockSwap`/`classMerge`：本次算子**做或不做**。
> - 独立命名者：`multiPointSameValue(point_rate)` 逐维选中、`setExchange`/`classRelocate` 的 `subset_rate` 为类成员入选概率且**可留空**（EMPTYVALUE → 免参随机抽率）。

> GA/DE 无独立策略类 = 交叉+变异+拓扑的组合（多段 workflow）。

### 3.3 生成器 `wf.generator.*`
| 方法 | 语义 |
|---|---|
| `generation(inplace=false)` | 整体生成 + 约束修复（最常用） |
| `generationNoCheck(inplace)` | 整体生成、无修复 |
| `orderedConstruct(inplace)` | 逐维顺序构造（需策略 constructive） |
| `parallelConstruct(inplace)` | 逐维并行构造（每体独立句柄，逐维约束传播） |

### 3.4 环境选择 `wf.selector.*`
| 方法 | 语义 |
|---|---|
| `index(better=false)` | 逐位 1:1 替换（false=无条件位置替换/PSO;true=择优爬山） |
| `indexAnneal(T0,decay)` | 逐位 + Metropolis 退火接受。`T0`/`decay` **可留空**（EMPTYVALUE）→ 回落内部默认 **100.0 / 0.95** |
| `indexAging()` | 逐位 + 计龄贪心接受（Better + 停滞计数；scout 独立为 `ageActivation` 段，不在此）。需 `age` 特性(Singular)，自动挂载 |
| `kinshipAging()` | ABC onlooker：血缘定向（读 `parent_id` 定位源槽）+ 计龄接受。需 `kinship`/`age`(Singular)，自动挂载 |
| `kinshipGreedy()` | 精英局搜：血缘定向 + 择优接受（邻居优于精英→替换精英槽）。需 `kinship`(Singular)，自动挂载 |
| `rank()` | (μ+λ) 择优归并 |
| `close(better)` / `closeAnneal(T0,decay)` | 替换最相似(距离)个体 |
| `worstReplace()` | 无条件替换最差 λ 个（免疫换血） |
| `distanceSelect()` | 留最优 + 距离密度选（FWA，保多样性） |

### 3.5 评估 / 修复 / 初始化 / 个体 / 档案 / 管理器
- **评估** `wf.evaluator.*`：`basic()`（逐个评估） / `hash()`（重复解去重、命中不计 FES）。
- **修复** `wf.repair.*`：`boundary()`（夹回边界） / `modular()`（模映射绕回，FWA） / `random()`（域内随机） / `greedy()`（优先级贪心） / `no()`。
- **初始化** `wf.initializer("...")`：`Random` / `Greedy` / `R_G` / `Distribution` / `No`。
- **个体**：只有基类 `Individual`，**无需在配置指定**；逐个体状态（velocity/pbest/sigma/whalestate/fireworkstate/setvelocity）由组件 `featureDemands()` 声明、装配期推断挂载（见 [24 §9 个体特性](24-开发-组件清单.md)）。
- **档案** `.archive("...")` / `cb.gArchive("...")`：`Basic` / `Multiobject` / `Multimodal`。
- **子群协作管理器** `cb.manager("...")`：`Single`（单子群）等。

## 4. 终止与多轮

- 终止条件（优化器级与子群级各一套）：`maxFES(n)`（评估次数，主预算）/ `maxConvergence(n)`（收敛停滞）/ `maxTime(s)`（秒）。
- 运行：`opt->exe(seed)` 播种跑一次；`opt->exe(n, seed)` 播种一次跑 n 轮并逐轮记结果；`opt->continue_exe(new_terminator)` 换终止器续跑。
- 取结果：`opt->getBest(best, size)`。

## 5. 配置序列化（保存/加载配置表）

**按文件 save/load**（v1.4.5 CONFIG-IO，`ConfigBuilder` 静态方法，FullConfig↔文件）：
```cpp
ConfigBuilder::saveConfig(fc, "myrun", "v3.1", "config");  // 写 config/myrun.cfg(ver 缺省 v3.1)
FullConfig fc = ConfigBuilder::loadConfig("myrun", "config");  // 读 config/myrun.cfg → 首行探测版本 → 解码
```
- **统一后缀 `.cfg`**（纯文本）；**版本仅由首行分派**（`<ver= v3.1>` 文本 / `{"version":"v3.2"` JSON），**不用后缀区分版本**；未知版本/缺文件抛异常。
- 底层 codec：`ConfigCodecV31::encode/decode`（v3.1 文本）/ `ConfigCodecV32`（v3.2 JSON，`config-codec-json.h`）。`detectVersion(text)` 读首行判版本。
- 批量生成配置表见 `tutorial/config-generate*.cpp`（经 `saveConfig` 落 `config/*.cfg`）。

**未设置参数（EMPTYVALUE）的表示**（v1.4.6.3）：参数模板标 `allow_empty` 的项可以"留空"，表示"用组件内部默认/自适应"（如 `tao_ini`、`factor`、`w_attenuation`、`subset_rate`）。两种格式的落盘写法**不同**：

| 格式 | 未设置参数写作 | 说明 |
|---|---|---|
| v3.1 文本 | `nan` | `std::stod("nan")` 原样读回 |
| v3.2 JSON | **`null`** | **裸 `nan` 不是合法 JSON**，故用 `null`——语义恰为"无值"。读回即 EMPTYVALUE（**不是 0**） |

> ⚠ 读取旧配置：v1.4.6.3 之前的 v3.2 编码会印出裸 `nan`（非法 JSON，且当时的解码器会**解析错位并抛异常**）。现解码器容错读取这类旧产物，但**新写出的一律是 `null`**。
> ⚠ 手写配置时，未设置参数在 JSON 里请写 `null`、在文本里写 `nan`；**不要写 0** —— `0` 是一个**确定的取值**，与"未设置"语义不同（如 `subset_rate=0` 意为"子集恒空、不变异"，而留空意为"每次随机抽概率"）。

## 6. 算法配方（"我要 X 算法" → 怎么配）

下表把**常见算法**映射到组件配置（个体特性 · 拓扑 · 策略 · 生成器 · 选择器 · 修复；个体统一为基类 Individual，特性自动挂载）。均取自 `tutorial/config-generate*.cpp` 的实际配置（可运行）。参数含义见 [24-组件清单](24-开发-组件清单.md)。
> 记法：`gen` = `generation` · `oc` = `orderedConstruct` · `pc` = `parallelConstruct` · `index(T/F)` = `index(better_replace)`。

### PSO 族（连续）
| 算法 | 个体特性(自动挂载) | 拓扑 | 策略 | 生成器 | 选择器 | 修复 |
|---|---|---|---|---|---|---|
| **PSO** | velocity | `pgBest` | `velocityDriven(2,c,w,w_att)` | oc | index(F) | random |
| **CSO** | velocity | `competition` | `velocityDriven` | oc | index(F) | boundary |
| **LLSO** | velocity | `levelBasedLearning(L)` | `velocityDriven` | oc | index(T) | random |
| **SDLSO** | velocity | `stochasticDominantLearning` | `velocityDriven` | oc | index(T) | random |
| **SetPSO/SLLSO/SSDLSO** | setvelocity | 同上 | `setVelocityDriven(...)` | oc | index | random |

### 先进邻域（v1.4.6.2；均问题无关，纯编码级）
| 算法 | 拓扑 | 策略 | 生成器 | 选择器 | 备注 |
|---|---|---|---|---|---|
| **Path Relinking**（路径重连） | `repeatWithBest(k)`（每体 k 起点，端点=当代最优作向导解） | `pathRelinking()` | gen | `index(true)` | **无参数**；β~U(0,1) 每子代一抽（`relinkdepth` 标量特性自动挂载）= k 点采样式路径扫描 |
| **ALNS**（自适应大邻域） | `isolate()` | `adaptiveOperatorSelection(ρ, segment_len, ops)` | gen | `index(true)` 或 `indexAnneal(T0,decay)` | 算子池 `ops` 传 tag 枚举；每代轮盘选一个算子，按 σ1/σ2/σ3 记分、每 `segment_len` 代更新权重 |

**邻域算子扩充**（可直接用作上述 `ops` 池成员，或单独作邻域策略配爬山/退火/禁忌）：

| 算子 | 一句话 | 适用编码 |
|---|---|---|
| `cyclicExchange(k, rate)` | k 个互异维**环状轮转**（k=2 即 `exchange`）；守恒 | 排列/序列 |
| `blockSwap(times, rate)` | **任意两段互换**（长度可不等、可隔距）；守恒。`segmentRelocate`（相邻）与 `exchange`（单维）均为其退化域 | 排列/序列 |
| `multiPointSameValue(point_rate)` | 逐维以 `point_rate` 选中 → **全置同一个**随机值（与 `bit` 只差"是否共用一个值"） | 通用/指派 |
| `setExchange(subset_rate)` | 两个**值类**各取随机子集**互换取值**（成组再平衡）；**留空→免参**（两侧各随机抽率） | 指派/分组 |
| `classRelocate(subset_rate)` | 一个值类的随机子集**单向迁到新值**（能**启用未使用值 / 拆分类**——`setExchange` 做不到）；**可留空** | 指派/分组 |
| `classMerge(rate)` | 一个值类**整体并入另一现值** → **在用值个数确定减 1**（整合/关停） | 指派/分组 |

> **值类族四方向已齐**：对调（`setExchange`）· 拆分/外迁（`classRelocate`）· 合并（`classMerge`）· 逐维塌缩（`multiPointSameValue`）。
> 端到端与语义验证见 `tests/optimizer/strategy/smoke-{pathrelink,alns,multipoint,cyclicexchange,setexchange,classrelocate,blockswap,classmerge}.cpp`。

### 精英解局部搜索（**段追加到任意 workflow 末尾**的强化）
每代取若干精英、邻域生成候选、择优替换。按 setter 调用顺序**接在主算法各段之后**（`components`=执行序）。两条来源路径，select 层区分：

| 路径 | 拓扑 | 策略 | 选择器 |
|---|---|---|---|
| **种群 top-e**（血缘定向） | `topIndividual(e, r)`（起点=种群槽） | 邻域算子（`differencePerturbation`/`gauss`…） | `kinshipGreedy()`（读 `parent_id` 归属回精英槽、优则**替换精英**） |
| **档案精英**（全局归并） | `elite(e, r)`（档案精英/内部 buffer） | 高斯等（端点=自身，不能用差分） | `rank()` |

> 血缘 id 由 `RunGenerate` 通用盖（种群路径）；kinship 特性由 `kinshipGreedy` 声明、装配期自动挂载。配置表 `elite_pop_pso`/`elite_archive_pso`、教程 `tutorial/6.elite-local-search.cpp`、端到端 `tests/optimizer/strategy/smoke-elite-ls.cpp`。
