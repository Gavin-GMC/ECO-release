# 12 · 使用者篇 · 结果分析（ECAnalyzer）

跑完实验后，把**多算法 × 多问题**的结果日志汇总成一张**性能对比表**（含描述统计、显著性检验、排名、胜负、最优加粗），一键导出 Txt/Csv/LaTeX。
面向要**做实验对比**的使用者。配套可运行示例：`tutorial/4.log-analysis.cpp`。

> 统一入口只 `#include "evoflow.h"` **不含**分析层；用分析器需额外 `#include "ec-analyzer.h"`。

---

## 1. 数据从哪来：结果日志 `.rslt`

分析器**不重新跑优化**，它读优化器已经落盘的结果日志。所以前提是**跑实验时开了结果日志**：

```cpp
cb.name("psoA").tag("sphere").logging(/*result*/true);   // 开 .rslt
Optimizer* opt = cb.buildOptimizer;
opt->setProblem(&p);
opt->exe(20, seed);        // 跑 20 次重复 → 自动写 _0.rslt … _19.rslt
```

落盘路径固定为 `_log/<优化器名>/<问题名>/<优化器名>_<问题名>(<tag>)_<重复号>.rslt`。
分析器按同一规则回找，故 `addOptimizer(名, tag, 重复数)` 的 **名/tag/重复数必须与跑实验时一致**（`tag` 即 `cb.tag(...)`，不设则为时间戳、不可复现，**做对比实验务必显式设 tag**）。

默认日志根为 `_log`。若结果位于其他目录，在添加参与者前调用
`az.logRoot("D:/experiments/run-01")`；`.rslt` 与 `.prcs` 都会从该根目录下按同一布局读取。
空路径回落到 `_log`。CLI/UI 的报告门面会自动把用户选择的日志目录传给此接口。

## 2. 三阶段流水线

分析器把结果压成表格分三步（对应三组方法）：

| 阶段 | 方法 | 干什么 |
|---|---|---|
| **① 归约** | `reduceBy(...)` （**单选**） | 把**一次运行的解集**压成 1 个标量 |
| **② 聚合** | `addStatistic(...)` （**多列**） | 把 `重复数` 个标量聚合成表格列 |
| **③ 比较** | `addComparison(...)` | 算法间对比：显著性 / 排名 / 胜负 / 最优加粗 |

然后 `run` 计算、`report(格式, 路径)` 导出。所有配置方法均**链式**（返回自身）。

---

## 3. 五个枚举

| 枚举 | 成员 | 用在 |
|---|---|---|
| `Stat` | `Mean, Variance, Std, Median, Mode, Smallest, Largest,`<br>`Q1, Q3, IQR, Range, SEM, CV, GeometricMean, HarmonicMean` | **①②通用**（跨用途：既可做单run归约，又可做跨run聚合）。另有参数化分位数：`addPercentile(p)`（聚合）/ `reduceByPercentile(p)`（归约） |
| `Indicator` | `HyperVolume, GD, IGD, PeakRatio, PeakDistance, PeakInaccuracy` | **仅①**（解集质量指标，需参考点/前沿；多峰三指标需 `logging(full result)`） |
| `Compare` | `Significance, Rank, WinTieLose, Best,`<br>`KruskalWallis, WilcoxonSignedRank, Friedman, Nemenyi, Dunn` | **仅③**（后 5 者为非参统计检验套件，见 §6） |
| `Direction` | `MinIsBetter, MaxIsBetter` | ③的目标方向 |
| `Format` | `Txt, Csv, Latex`（可用）·`Excel, Word, Png`（延后） | 输出格式 |

> 描述统计那组（`Stat`）是**同一枚举在①②两个阶段复用**：`reduceBy(Stat::Mean)` = 对解集求均值，`addStatistic(Stat::Mean)` = 对重复求均值——含义随方法不同。

## 4. 接口一览

```cpp
ECAnalyzer az;

// 参与者：算法 × 问题（重复数须与实验一致）
az.logRoot("_log")                         // 可省略；默认即 _log
  .addOptimizer("psoA", "sphere", 20)
  .addOptimizer("psoB", "sphere", 20)
  .addProblem("sphere");                    // 或 addProblem({"p1","p2",...})

// ① 归约（二选一，单选）
az.reduceBy(ECAnalyzer::Stat::Mean, /*objIndex*/0);          // 描述式：对第 objIndex 个目标列
// az.reduceBy(ECAnalyzer::Indicator::IGD, refPerProblem);   // 指标式：见 §5

// ② 聚合列（可多次）
az.addStatistic(ECAnalyzer::Stat::Mean)
  .addStatistic(ECAnalyzer::Stat::Std)
  .addStatistic(ECAnalyzer::Stat::Smallest);

// ③ 比较（可多次）
az.addComparison(ECAnalyzer::Compare::Significance)                        // Mann-Whitney U，对基准算法出 p 值列
  .addComparison(ECAnalyzer::Compare::Rank,       ECAnalyzer::Stat::Mean, ECAnalyzer::Direction::MinIsBetter)
  .addComparison(ECAnalyzer::Compare::WinTieLose, ECAnalyzer::Stat::Mean, ECAnalyzer::Direction::MinIsBetter)
  .addComparison(ECAnalyzer::Compare::Best,       ECAnalyzer::Stat::Mean, ECAnalyzer::Direction::MinIsBetter);

// 计算 + 导出
az.run
  .report(ECAnalyzer::Format::Txt,   "result")   // → _analysis/result.txt
  .report(ECAnalyzer::Format::Csv,   "result")
  .report(ECAnalyzer::Format::Latex, "result");  // → _analysis/result.tex
```

- **比较方法的 `on`**：指定拿哪一**聚合列**做比较（如按 `Stat::Mean` 列排名）；`Significance` 忽略 `on`（它直接比①的逐run标量）。
- **`Direction`**：`MinIsBetter`（默认，目标越小越好）/`MaxIsBetter`。
- **`report` 路径**：不含分隔符的名字自动落 `_analysis/<名>.<扩展>`；留空则 `_analysis/<归约名>(时间戳).<扩展>`。显式路径缺扩展名时自动补全；后缀与请求格式冲突时改成正确后缀并写警告（如 PNG + `out/table.svg` → `out/table.png`）。`_analysis` 目录自动创建；显式路径的父目录仍由调用方准备。

生成表大致长这样（`+/=/-` 为胜/平/负，最优列在 LaTeX 里 `\textbf` 加粗，`Rank` 为平均排名）：

```
        psoA                       psoB
        mean    std    smallest    p-value   mean    std    smallest   p-value
sphere  0.654   0.299  0.106       -         0.534   0.257  0.025      1.04
Rank    2.0/2                                1.0/2
+/=/-   -                                    0/1/0
```

## 5. 质量指标（多目标）

多目标实验用 `Indicator` 归约——从**一次运行的整个解集（Pareto 前沿）**算一个质量标量。参数按问题给（`refPerProblem[p]`）：

| 指标 | 含义 | `refPerProblem[p]` 约定 |
|---|---|---|
| `HyperVolume` | 支配超体积（越大越好） | **参考点**：长度 = 目标数（各目标一个上界/劣点） |
| `GD` | 世代距离（越小越好，收敛性） | **参考前沿**：行主序展平，长度 = 前沿点数 × 目标数 |
| `IGD` | 反向世代距离（越小越好，收敛+分布） | 同 GD |
| `PeakRatio` | 多峰命中率（越大越好，越接近 1 = 找到越多全局峰） | **4 标量**：`{f*, 峰数, ε, r}`，见 §5.1 |

```cpp
// 例：2 目标，HV 参考点 (5,5)
az.reduceBy(ECAnalyzer::Indicator::HyperVolume, { {5.0, 5.0} });

// 例：IGD 参考前沿（每问题一份，行主序 [f1,f2, f1,f2, ...]）
std::vector<double> front = { /* x0f1,x0f2,  x1f1,x1f2, ... */ };
az.reduceBy(ECAnalyzer::Indicator::IGD, { front });
```

前提：多目标实验用 `Multiobject` 档案（结果日志里存整条前沿）。指标结果再经 `addStatistic(Stat::Mean)` 对重复取均值。

### 5.1 多峰命中率 PeakRatio（通用 niching 口径）

peakRatio 衡量多峰优化找到了多少个**全局峰**，工作在**决策/变量空间**：按适应度精度 ε 过滤到全局最优适应度 f\* → 按 niche 半径 r 去重 → 命中峰数 / 已知峰数。因此参数是 **4 个标量**（复用 `refPerProblem[p]`）：

```cpp
// refPerProblem[p] = { f*, 峰数, ε(适应度精度), r(niche 半径) }
az.reduceBy(ECAnalyzer::Indicator::PeakRatio, { { f_star, (double)peaks, 1e-1, rho } });
```

- **来源**：由外部 benchmark 或用户问题定义提供 f\*、全局峰数和峰半径 r；ε 是调用方选定的命中精度。合成双峰的端到端验证见测试支持问题，接入方式见外部 benchmark 教程。
- **要求决策变量**：peakRatio 需解的 x 坐标，故实验必须开 `logging(true)`（full result → `.rslt` 为 ver 1.1，含决策变量块）；否则该指标返回空。
- 结果 clamp 到 [0,1]，再经 `addStatistic(Stat::Mean)` 对重复取均值。
- 用**多峰档案** `Multimodal`（`gArchive("Multimodal")`）收集多个峰。

## 6. 非参统计检验套件（③比较的深化）

跨算法非参检验，按**样本关系 × 组数角色**分 2×3（全对齐 scipy / scikit-posthocs）：

| | 2 组·直接 | K 组·综合门槛 | K 组·后验 |
|---|---|---|---|
| **独立**（层1·吃①归约的逐run分布，逐问题）| `Significance`（Mann-Whitney U） | `KruskalWallis` | `Dunn` |
| **配对**（层2·吃②聚合的每(算法,问题)代表值，跨问题）| `WilcoxonSignedRank` | `Friedman` | `Nemenyi` |

- **独立 vs 配对**：独立=同问题内多次运行互不配对；配对=跨问题按问题分块、每算法一代表值。
- **综合门槛 → 后验**：`KruskalWallis`/`Friedman` 只答"K 个算法整体有无差异"；显著后需 `Dunn`/`Nemenyi` 找**具体哪对**不同。
- **输出**：层1 逐问题 → 主表列（`KW_p` / `Dunn_p`）；层2 跨问题汇总 → 表下行（`Friedman`(χ²/p) / `Nemenyi`(CD+平均秩) / `Wilcoxon(vs base)`）。
- **参数**：层2 检验带 `on=Stat`（用哪个聚合列当代表值，如 `Median`）。

```cpp
az.reduceBy(ECAnalyzer::Stat::Smallest)          // ①每run最优
  .addStatistic(ECAnalyzer::Stat::Median)        // ②代表值(供层2检验)
  .addComparison(ECAnalyzer::Compare::KruskalWallis)                                // 层1 KW_p 列
  .addComparison(ECAnalyzer::Compare::Dunn)                                         // 层1 Dunn_p 列
  .addComparison(ECAnalyzer::Compare::Friedman,  ECAnalyzer::Stat::Median)          // 层2 Friedman 行
  .addComparison(ECAnalyzer::Compare::Nemenyi,   ECAnalyzer::Stat::Median)          // 层2 Nemenyi 行
  .addComparison(ECAnalyzer::Compare::WilcoxonSignedRank, ECAnalyzer::Stat::Median);// 层2 Wilcoxon 行
```

> 实现对齐 scipy：小样本用精确分布（MW/Wilcoxon）、卡方生存函数（KW/Friedman）；大样本正态近似（= scipy `method='auto'`）。Nemenyi 用 Demšar 2006 临界差、Dunn 用 scikit-posthocs 口径。

## 7. 图表 SVG 输出 → LaTeX 引用

分析图（收敛曲线 / 箱线图 / Nemenyi 临界差图 / Pareto 前沿）以 **SVG**（矢量）输出——`out-svg.h` 直接写 SVG 文本，零第三方依赖。SVG 是**矢量母版**，同时喂 LaTeX / 可视化 UI / PNG 三个下游。

### 7.1 生成图表（流式 API）

**每个图种自暴露一个方法**，方法返回该图种**专属的构建器**，构建器上只有对它有效的选项 —— 传错参数**编译不过**。与 `ConfigBuilder` 的惯用法同构（`wf.strategy.velocityDriven(...)`）。

```cpp
// 样式:设一次,本 analyzer 所有图共用 ⇒ 同批跨图色表一致、相同算法同色
az.chartStyle(FileOut::ChartStyle
        .palette(FileOut::Palette::ColorblindSafe)   // 默认;另有 Categorical/Grayscale/Vibrant
        .lang(FileOut::Lang::EN)                     // 默认 EN;ZH 切中文(算法名不翻译)
        .caption(true));                             // 下方解释描述,可关

az.chart.boxPlot("box", "各问题分布").jitter(true).draw;
az.chart.convergence("conv", "收敛曲线").grid(400)
          .band(ECAnalyzer::Stat::Q1, ECAnalyzer::Stat::Q3).draw;
az.chart.paretoFront("pf", "前沿").objectives(0, 1).connect(true).draw;
az.chart.rankBar("rb", "平均秩").draw;
// → _analysis/*.svg (与 report 同路径约定:裸名落 _analysis/,目录自动建)
// 显式路径同样会补扩展名；与 format 冲突的后缀会被纠正并记录警告。
```

#### 图种与各自的专属选项

| 类 | 方法 | 专属选项 | 前提 |
|---|---|---|---|
| **逐问题**<br>（默认**一图一问题**：不指定问题则每问题各出一张，文件名自动加问题后缀）| `boxPlot` | `jitter` `norm` | — |
| | `barChart` | `norm` `statistic` `band`/`noBand` | — |
| | `convergence` | `grid` `statistic` `band` `swarm` | **`logging(_, true)`** 产出 `.prcs` |
| | `paretoFront` | `objectives` `run` `connect` | 问题需 ≥2 目标 |
| **跨问题**<br>（一图涵盖全部问题）| `multiBoxPlot` `multiBarChart` | 同上对应项 | — |
| | `cdDiagram` | — | `Compare::Nemenyi` |
| | `winTieLose` | — | `Compare::WinTieLose` |
| | `rankHeatmap` | `statistic` | `Compare::Rank`（或用 `statistic` 指定统计量）|
| | `rankBar` | — | `Compare::Rank` 或 `Compare::Nemenyi` |
| | `table` | — | — |

**共有选项**（所有构建器都有）：`path` `title` `style` `format` `pngFont`；逐问题类另有 `problem(i)` / `problems({...})`。共有项与专属项**顺序任意**。

`format(ChartFormat::Svg|Png)` 默认 **Svg**；PNG 见 §7.4（**有字体依赖与平台限制**）。

缺前提时**拒绝出图并写错误日志**，不会静默产出空图。

#### `draw` 与改参重画

`draw` 返回构建器自身，故可改参数再画一张：

```cpp
auto b = az.chart.multiBoxPlot("box", "原始口径");
b.draw;
b.norm(chart_detail::Norm::MinMax).path("box_mm").title("归一化").draw;
```

出图有副作用（写文件、可能报错），**不藏进析构（RAII）** —— 显式 `draw` 更诚实。
构建器持有 `ECAnalyzer*` 而非 `az.chart` 返回的临时门面，故 `auto b = az.chart.boxPlot(...)` **跨语句持有安全**。

#### 误用是编译错误（ 的核心收益）

下列写法在旧版扁平 `ChartSpec` 下**可以编译且被静默忽略**，现在**编译不过**：

```cpp
az.chart.boxPlot("x","t").grid(20);            // grid 仅收敛曲线有
az.chart.rankBar("x","t").norm(...);           // 秩条无 norm 概念
az.chart.table("x","t").problem(0);            // 表是跨问题类,无 problem
az.chart.convergence("x","t").jitter(true);    // jitter 仅箱线图有
az.chart.winTieLose("x","t").objectives(0,1);  // objectives 仅 Pareto 有
```

#### 其它要点

| 要点 | 说明 |
|---|---|
| **标题** | `boxPlot(path, title)` 的**每图参数**，故一套 style 可复用于整批图；`title` 可后改 |
| **色表** | 4 套内置，`ColorblindSafe`（默认，16 色 = Okabe-Ito 8 + Tol muted 8）|
| **同色保证** | 颜色按**对象索引**取（=算法在 analyzer 的添加序）⇒ **同一算法在该批所有图里同色**；换色表整批一起换 |
| **语言** | 框架文字随 `lang` 切，**默认 EN**；算法名是用户数据不翻译 |
| **超界检查** | 生成时累计图元包围盒，超出画布则告警（写日志）|
| **默认口径** | 一律**原始数据**，`norm`/`logScale`/`reverseY`/`jitter`/`band` 全部默认关 |
| **按需补算** | 图需要而未 `addStatistic` 声明的统计量，analyzer 内用同一套算法现算到临时缓冲、画完即弃，**不污染 `report` 的表格列** |

#### 收敛曲线补充（`convergence`）

- **横轴 = FES**（非代数）；数据来自 `.prcs`，**必须 `cb.logging(/*result*/true, /*process*/true)`**。
- **公共 FES 网格按问题建**（跨算法同一把尺）⇒ 曲线可比；`logScale` 时网格按对数取点。
- **重采样 = 阶梯保持**；首条记录之前为 `NaN` → **断线不连**。
- **流式**：两遍扫描，峰值内存 `O(网格点 × run 数)`，**与代数无关**。
- ⚠️ **不假定优化方向**：由问题自己的比较器决定（`addObjective` 的 `min_is_better`；外部最大化问题的曲线上升）。
- ⚠️ **认 `.prcs`  / **：更早的裸行流与  会被拒绝并提示重跑。
- **取源级别（`.swarm`， 两级日志）**：过程日志分**种群级**（全局 `_<run>.prcs`，逐 epoch、统一 FES）与**子群级**（`_<run>_<子群id>.prcs`，逐代）两级。收敛曲线默认读**种群级**；调 **`.swarm("<子群id>")`** 改读该子群的**子群级**曲线（逐代细粒度）。
  - 多 epoch 配置下种群级即平滑；**仅"子群预算==全局预算"的单 epoch 退化配置**种群级只有 1 个点，此时用 `.swarm(id)` 取逐代曲线。示例：`az.chart.convergence("conv","收敛").swarm("s0").grid(400).draw;`

#### Pareto 前沿补充（`paretoFront`）

- 点直取档案内容 —— 配 `archive("Multiobject")` 时它**本身就是非支配集**，故**不再做任何排序**。
- `connect` **默认关**：前沿不连续时（离散问题常见）连线会画出实际不存在的中间解；开启时说明文字会注明"连线只是阅读辅助"。

### 7.2 在浏览器/UI 查看
双击 `.svg` 或 `<img src="chart.svg">` 引用即渲染（浏览器/查看器内建 SVG 引擎，无需库）；矢量任意缩放不糊，UI 里还可挂交互（悬停/缩放）。

### 7.3 在 LaTeX 论文里引用（保矢量）
pdfLaTeX 的 `\includegraphics` **不直接吃 `.svg`**，标准做法是先转 **PDF**（矢量，无损）：

**做法 A · 先转 PDF 再引用（最稳，推荐）**
```bash
# 用任一转换器把 SVG 转成矢量 PDF
resvg chart.svg chart.pdf            # 或 inkscape chart.svg --export-type=pdf
#     rsvg-convert -f pdf -o chart.pdf chart.svg
```
```latex
\usepackage{graphicx}
\includegraphics[width=\linewidth]{chart.pdf}   % 矢量,缩放不糊
```

**做法 B · `svg` 宏包（编译时自动转）**
```latex
\usepackage{svg}                 % 需系统装 Inkscape,编译加 -shell-escape
\includesvg[width=\linewidth]{chart}   % 自动 SVG→PDF + 文字用 LaTeX 叠加
```

**做法 C · 转 TikZ（原生，无外部图）**
`svg2tikz chart.svg` 或 Inkscape「另存为 TikZ」→ 得 TikZ 代码，`\input{chart.tikz}` 原生渲染。保真度随图复杂度，简单图最佳。

> 关键：**SVG→PDF 保矢量**（论文缩放清晰），别转 PNG（栅格化会糊）。分析器已有的 `out-latex.h`（LaTeX 表格）+ 本节的 SVG 图 = 表格与图在同一 LaTeX 文档里齐活。

### 7.4 位图 PNG 输出

```cpp
az.chart.boxPlot("box", "分布").format(ChartFormat::Png).draw;   // → _analysis/box.png
```

**格式是二选一，不是叠加**：`format(Png)` 只出 PNG、不附带 SVG。两种都要就用改参重画：

```cpp
auto b = az.chart.rankBar("rb", "平均秩");
b.draw;                                // rb.svg
b.format(ChartFormat::Png).draw;       // rb.png
```

| 项 | 说明 |
|---|---|
| **实现** | `ChartCanvas` 记录**图元清单**，SVG 与 PNG 两后端重放同一份清单 —— **不解析 SVG**（NanoSVG 那类库不支持 `<text>`，而图表文字占比极高，走解析路线会产出无字废图）|
| **文字** | `stb_truetype` 真实渲染；按码点分派字体（`< 0x80` → 英文字体，其余 → 中文字体）|
| **分辨率** | `PngFontConfig::scale` 默认 **2.0**（2x 图）；`pngFont` 逐图可覆盖 |
| **体积** | 实测 20~74 KB（`stb_image_write` 自带压缩）|

#### ⚠️ 字体依赖与平台限制（重要）

> **Windows 默认字体路径已完成验证；Linux 英文 PNG 输出已在 Ubuntu 24.04.4 WSL2、CPython 3.12.3 环境通过显式传入 DejaVu 字体路径完成验证。**
>
> 默认字体为 **Times New Roman**（`C:/Windows/Fonts/times.ttf`）与**宋体**（`C:/Windows/Fonts/simsun.ttc`）。
>
> **这两个字体是商业字体**（Monotype / 中易中标，授权随 Windows 分发），**不随本项目分发**，程序在**运行期从本机字体目录读取** —— 用户安装 Windows 时已获授权，此路径合法。
>
> **在没有这两个文件的系统上**（Linux / macOS / 精简版 Windows），必须显式指定真实存在且可读的字体路径：
> ```cpp
> FileOut::PngFontConfig f;
> f.latin = "/usr/share/fonts/truetype/dejavu/DejaVuSerif.ttf";
> f.cjk   = "/usr/share/fonts/opentype/noto/NotoSerifCJK-Regular.ttc";
> az.chart.boxPlot("box", "分布").format(ChartFormat::Png).pngFont(f).draw;
> ```
> 否则**明确报错**（`no usable font: ...`）并**不产出图片** —— 不会静默给你一张没有文字的图。
>
> 当前不会自动替换字体。Linux 图形界面、模型连接、字体自动发现以及 macOS 仍。

#### 需要 SVG 而非 PNG 的场景

论文排版仍**推荐 SVG→PDF**（见 §7.3）：矢量无损、可任意缩放、文字可被 PDF 检索。PNG 适合 UI 嵌入、聊天/邮件分享、以及只接受位图的投稿系统。

## 9. 内部结构（供二次开发）

- `src/analyzer/ec-analyzer.h` —— `class ECAnalyzer`：`loadData`(读.rslt)→`_metric_cal`(①归约)→`_metric_analysis`(②聚合)→`_significant/_rank/_wl/_best/_kruskal/_wilcoxon/_friedman/_nemenyi/_dunn_statistic`(③比较)→`_analysis_table`(拼字符串表)→`report`。跨算法统计的额外列/行槽用具名枚举 `ExtraCol`(取代魔数偏移)。
