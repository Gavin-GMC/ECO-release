# 13 · 使用者篇 · 可执行程序

把库当**命令行工具**用：一个独立 exe，从**文件**读入「问题 + 配置」跑优化、输出结果，可被 cmd/终端/脚本调用。无需写 C++。

> 与前几章的区别：第 10–12 章是**在你自己的 C++ 程序里**用库（`#include "ecflow.h"`）；本章是**直接用编译好的 exe**，不写代码。

---

## 1. 构建

用 CMake（Windows MSVC / Linux g++·clang 通用）：

```sh
cmake -B build                       # 生成
cmake --build build --config Release  # 编译 → 分支根 ecflow(.exe)
```

- 产物 `ecflow`(`.exe`) 落**分支根**（与 `src/`、`_pdata/`、`config/` 同级），中间产物在 `build/`。
- Windows 下用 `/MT` 静态链接运行时 → exe **完全自包含**（仅依赖系统 `ADVAPI32`/`KERNEL32`，无需 VC++ 可再发行运行时），拷到任何 Windows 直接跑。

---

## 2. 用法

```
ecflow <问题文件> <配置文件> [选项]
```

**必需位置参数**

| 参数 | 说明 |
|---|---|
| `<问题文件>` | ECFlow 标准算例文件（头部含 `TYPE:`），按家族自动分派构造问题。格式见各 `_pdata/<kind>/README.md`。 |
| `<配置文件>` | 优化器配置 `.cfg`（v3.1 文本 / v3.2 JSON，首行自动分派）。生成见 `tutorial/config-generate*.cpp`。 |

**选项**

| 选项 | 作用 | 默认 |
|---|---|---|
| `-s <seed>` | RNG 种子 | 1 |
| `-n <runs>` | 独立运行次数（多次结果落 `.rslt` 日志，控制台报最后一次最优） | 1 |
| `-o <file>` | 结果写文件 | stdout |
| `--max-fes <N>` | 覆盖最大评估次数（总预算，同时覆盖全局与各子群） | 用配置的 |
| `--max-time <s>` | 覆盖最大运行秒数 | 用配置的 |
| `--max-conv <N>` | 覆盖最大停滞代数 | 用配置的 |
| `-q, --quiet` | 只输出最优 fitness（机读友好，便于脚本管道） | — |
| `-v, --verbose` | 每代进度回显到控制台 | — |
| `-h, --help` | 显示用法 | — |

**退出码**：`0` 正常 / `1` 运行错误 / `2` 参数错误。

---

## 3. 示例

```sh
# 基本：跑 TSP 算例 burma14,用蚁群配置 ACS,种子 42
./ecflow _pdata/tsp/burma14.tsp config/ACS.cfg -s 42

# 覆盖预算 + 只要 fitness(脚本友好)
./ecflow _pdata/qap/bur26a.qap config/ACS.cfg --max-fes 50000 -q

# 数值问题(CEC2013)用 CMA-ES,进度上屏
./ecflow _pdata/numerical/cec2013n-f3.num config/cmaes.cfg -v

# 结果写文件
./ecflow _pdata/tsp/burma14.tsp config/ACS.cfg -o result.txt
```

正常输出（非 `-q`）：

```
problem: _pdata/tsp/burma14.tsp
seed: 42
runs: 1
best_fitness: 30.8785
solutions: 1
  [1] length:  30.878504   x: 11 5 4 3 2 13 1 0 9 8 10 7 12 6
```

## 4. 路径规则（重要）

exe 按**当前工作目录（CWD）**解析 `_pdata/`、`config/`，**不是**按 exe 自身位置：

- **在分支根运行**：可用相对/短路径（`_pdata/tsp/...`、`config/...`）。
- **从别处运行**：给问题/配置传**绝对路径**，否则相对路径找不到文件。

问题文件路径本身也自适应：含 `/`、`\`、`.` 之一 → 当完整/相对路径用；否则当短名 → 拼 `_pdata/<kind>/<name>.<ext>`（仅在按家族直接调模板时；通用载入器 `loadProblem` 需真实路径以读取 `TYPE:` 头分派）。

---

## 5. 两条输出通道

| 通道 | 去向 | 内容 |
|---|---|---|
| **exe 的 stdout / `-o` 文件** | 控制台或指定文件 | 最终最优解（本章 §3 的输出） |
| **框架 Logger** | `_log/<name>/...` 下的 `.log`/`.err`/`.rslt`/`.prcs` | 执行日志、错误、每次运行结果、每代过程 |

二者独立：`-q`/`-o` 只影响 stdout 通道；`-v` 让每代过程**同时**回显控制台（原本只落 `.prcs` 文件）。日志文件始终生成（框架行为）。

---

## 6. 支持的问题家族

14 个家族均可经文件载入（`TYPE:` 头分派）：TSP、MKP、QAP、CFLP、CPMP、CVRP、FJSP、MDS、MIS、SR、STP、WFS（组合优化）+ NUMERICAL（CEC2013 数值基准，`.num` 描述文件）。各家族的数据文件格式见 `_pdata/<kind>/README.md`。
