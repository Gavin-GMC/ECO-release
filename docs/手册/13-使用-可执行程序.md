# 13 · 使用者篇 · 可执行程序

[English](../manual/13-command-line.md) | [简体中文](13-使用-可执行程序.md)

把库当**命令行工具**用：一个独立 exe，从**文件**读入「问题 + 配置」跑优化、输出结果，可被 cmd/终端/脚本调用。无需写 C++。

> 与前几章的区别：第 10–12 章是**在你自己的 C++ 程序里**用库（`#include "evoflow.h"`）；本章是**直接用编译好的 exe**，不写代码。

---

## 1. 构建

Windows x64 用户可直接解压 `EvoFlow-3.0.1.5-windows-x64.zip` 使用预编译的 `evoflow.exe`。程序包同时保留公开源码、CMake 入口、配置、教程、用户文档和 13 个首方最小样例；每个发布文件由根目录 `release-manifest.json` 记录大小和 SHA-256，整个 ZIP 另有同名 `.sha256`。

用 CMake 构建。Windows x64 + MSVC 是正式发布路径；Linux C++ 核心与 CLI 已在 Ubuntu 24.04.4 WSL2 x86_64、GCC 13.3、CMake 3.28.3、Ninja 1.11.1 环境完成源码构建与运行验证，但不提供 Linux 预编译发布包：

```sh
cmake -S . -B obj-cmake-release
cmake --build obj-cmake-release --config Release
```

- 也可以使用 `cmake -S build/cmake -B obj-cmake-release`，或用 Visual Studio 2022 打开 `build/vs/evoflow.sln`；完整说明见项目根目录 `build/README.md`。
- 产物 `evoflow`(`.exe`) 默认落**项目根目录**（与 `src/`、`_pdata/`、`config/` 同级）。`build/` 保存发布附带的构建入口，中间产物应放入可删除的 `obj-*` 目录。
- Windows 下用 `/MT` 静态链接运行时 → exe **不依赖 VC++ 可再发行运行时**（仍调用 Windows 自带系统 API）；应在受支持的 Windows x64 环境使用，不据此承诺任意 Windows 版本或其他架构。

## 2. 用法

> 无参数启动或双击 `evoflow.exe` 会打开图形界面；命令行优化请使用 `evoflow run`。

```
evoflow                              启动图形界面
evoflow run <问题文件> <配置文件> [选项]   跑一次优化
evoflow validate <路径> [选项]        配置验证报告
evoflow report <日志目录> [选项]       运行结果统计（按实验批次）
evoflow data [数据目录]               检查最小/完整数据包
evoflow --version                    显示 EvoFlow 3.0.1.5 产品版本
evoflow -h | --help                  用法
```

**退出码**：`0` 成功 / `1` 运行失败 / `2` 用法错误或子命令未实现。

### 2.1 图形界面

无参数运行或双击 `evoflow.exe`，程序会在 `127.0.0.1` 的动态端口启动本地服务，并用默认浏览器打开界面。页面与服务间使用本次启动生成的一次性令牌；服务不监听局域网地址。

完整界面现包含：

- 问题文件加载和定义态元信息；
- 表单式及积木式优化器构筑；
- v3.1/v3.2 `.cfg` 打开、保存、静态校验和装配验证；
- 实验批次扫描、统计表、SVG/PNG 图表查看与下载。

详细操作、安全边界和延期项见 [14-使用-图形界面](14-使用-图形界面.md)。

> 当前图形壳的服务层使用 Windows 系统 API；CLI 的 `run`/`validate`/`report` 已在上述 Linux 代表性环境完成实测。该结论不覆盖 Linux 图形界面或模型连接；图形界面与 CLI 共用 App 运行门面，也可直接启动优化。

### 2.2 `run` 子命令

**必需位置参数**

| 参数 | 说明 |
|---|---|
| `<问题文件>` | EvoFlow 标准算例文件（头部含 `TYPE:`），按家族自动分派构造问题。格式见各 `_pdata/<kind>/README.md`。 |
| `<配置文件>` | 优化器配置 `.cfg`（v3.1 文本 / v3.2 JSON，首行自动分派）。生成见 `tutorial/config-generate*.cpp`。 |

**选项**

| 选项 | 作用 | 默认 |
|---|---|---|
| `-s <seed>` | RNG 种子 | 1 |
| `-n <runs>` | 独立运行次数（多次结果落 `.rslt` 日志，控制台报最后一次最优） | 1 |
| `--tag <标签>` | **实验批次标识**。覆盖配置里的 tag，落进 `.rslt` 文件名，供 `report --tag` 聚合。**不给则用配置的 tag；配置的 tag 为空时框架回落到时间戳**，于是每跑一次都是一个新批次、无法聚合统计 —— 打算事后出报告就一定要给。 | 用配置的 |
| `--optimizer-name <名称>` | 覆盖配置内部优化器名，适合参数扫描建立互不混淆的输出身份；只接受 1–128 个 ASCII 字母、数字及 `._-+`。 | 用配置的 |
| `--run-start <N>` | 显式指定本批第一个零基结果编号；整个范围在优化开始前预检。 | 自动从最大已占用编号之后续号 |
| `--replace-existing` | 事务替换显式范围内的旧 `.rslt/.prcs`；必须同时给 `--run-start`。失败/取消会恢复旧文件。 | 关闭 |
| `-o <file>` | 结果写文件 | stdout |
| `--max-fes <N>` | 覆盖最大评估次数（总预算，同时覆盖全局与各子群） | 用配置的 |
| `--max-time <s>` | 覆盖最大运行秒数 | 用配置的 |
| `--max-conv <N>` | 覆盖最大停滞代数 | 用配置的 |
| `-q, --quiet` | 只输出最优 fitness（机读友好，便于脚本管道） | — |
| `-v, --verbose` | 每代进度回显到控制台 | — |
| `-h, --help` | 显示用法 | — |

**退出码**：`0` 正常 / `1` 运行错误 / `2` 参数错误。

### 2.3 `validate` 子命令

批量检查配置文件并一次列出**全部**问题（而非像装配那样遇到第一个 Error 就中止）。结果分为 Error / Warning / Info / Pass；含 Warning 或 Info 但无 Error 的配置仍可装配，完整边界见[优化器配置手册 §2.3](11-使用-优化器配置.md#23-组件间契约assertmatcher)。

```bash
evoflow validate config                    # 验整个目录
evoflow validate config/ACS.cfg            # 验单个文件
evoflow validate config -r --build         # 递归 + 深度检查
evoflow validate config -f json -o rep.json  # 结构化报告(供 UI/工具消费)
```

| 选项 | 说明 |
|---|---|
| `<路径>` | `.cfg` 文件，或含 `.cfg` 的目录 |
| `-r, --recursive` | 递归子目录（默认只扫一层）|
| `--build` | **深度检查**：真装配一次（不运行优化）。能抓到静态检查查不到的问题，如**子群绑定了不存在的 workflow**。默认关 —— 它会真的构造对象 |
| `-f, --format txt\|json` | 报告格式（默认 `txt`）|
| `-o <file>` | 报告写文件（默认 stdout）|
| `-q, --quiet` | 只输出汇总行 |

**退出码**：`0` 不含 Error（可以含 Warning/Info）/ `1` 存在 Error 或路径、加载失败 / `2` 参数错误 —— 可直接用于 CI。

**输出示例**（每条问题都带**触发组件**与**机器可读原因**）：

```
scanned: 1   pass: 0   info: 0   warning: 0   error: 1   status: error   depth: static

bad.cfg
  [error] workflow 'wf' [scope 0] . component[2] strategy 'NoSuchStrategyXYZ'
         unknown_tag: unknown strategy tag: 'NoSuchStrategyXYZ'
  [error] workflow 'wf' [scope 0] . component[3] generator 'ParallelConstruct'
         no_strategy_before_generator: generator 'ParallelConstruct': no strategy set before it
```

> 上例体现了**非 fail-fast 的价值**：一个未知 tag 引发的多个连锁问题一次全列；而 `run` 只会报第一个 Error 就退出。文本项使用 `[error] / [warn ] / [info ]`，JSON 的报告、文件和单条问题分别提供 `status`、四级文件计数及 `severity`；`pass` 只用于聚合状态。

**两级深度**：静态检查覆盖参数元数/范围/整值性、断言匹配、tag 合法性、流程完整性；`--build` 额外覆盖装配期才暴露的问题。

`reason` 是**稳定的机器可读键**（`unknown_tag` / `missing_provision` / `param_out_of_range` …），UI 与工具据此分类，不必解析消息文本；键表见 `src/optimizer/config/assert-matcher.h`。

### 2.4 `report` 子命令

把 `_log/` 里的运行结果**按实验批次**汇总成三线表（可选出图）。

**位置参数**：`<日志目录>`，缺省 `_log`。

| 选项 | 作用 | 默认 |
|---|---|---|
| `--list` | 只列出发现的实验批次，不出报告 | — |
| `--tag <标签>` | **对哪个批次出报告。必给**（原因见下） | — |
| `--charts <目录>` | 顺带出三张图：三线表 `table`、多箱形图 `dist`、平均秩柱状图 `rank` | 不出图 |
| `--png` | 图表出 PNG 而非 SVG（PNG 需本机系统字体，见手册 12） | SVG |
| `-f, --format <f>` | `txt`（人读，列对齐）/ `csv` / `latex` / `json` | txt |
| `-o <file>` | 报告写文件 | stdout |

**为什么 `--tag` 必给** —— 报告统计的是**一个批次内**的多次重复运行。`_log/` **没有自动清理**，里面通常混着许多历史批次，它们可能用了不同的问题、不同的预算、甚至不同版本的代码，**混在一起算均值和排名是没有意义的**。因此不给 `--tag` 时程序**不替你挑**，而是列出候选批次让你选：

```sh
$ evoflow report _log --list
experiment batches under the log directory (tag = one batch):

  --tag exp1
      optimizers: 2   problems: 1   runs each: 3   files: 6

pick one with --tag; results from different batches are NOT comparable
```

批次行里的 `runs each` 若各组合不一致，会额外标注 `ragged`（数据不完整，说明某些「优化器 × 问题」组合少跑了）。

**典型流程**：跑实验时给同一个 `--tag`，跑完对着它出报告。

```sh
evoflow run _pdata/tsp/sample.tsp config/ACS.cfg --tag exp1 -n 30
evoflow run _pdata/tsp/sample.tsp config/AS.cfg  --tag exp1 -n 30
evoflow report _log --tag exp1 --charts _analysis/exp1
```

```
                        ACS                                 AS
               mean         std      median        mean         std      median
sample   1.2000e+01  0.0000e+00  1.2000e+01  1.2000e+01  0.0000e+00  1.2000e+01
Rank       1.5000/2                            1.5000/2
```

统计量为 mean/std/median + 最优标注 + 平均秩，**与分析层 `report(Format)` 同源**（同一份表格缓冲），故 CLI 出的表和自己写分析程序出的表一致。

> ### 结果身份与覆写
>
> 结果身份由“优化器名 + 问题名 + tag + 结果编号”组成。同一 tag 分多次调用会安全续号，例如先运行 3 轮得到 `0–2`，再次运行 2 轮得到 `3–4`。参数扫描应为每个方案传不同的 `--optimizer-name`，避免在报告里把它们当成同一算法。
>
> 显式起点若碰到旧结果会在优化开始前拒绝，不会截断文件。确实要重做编号 `10–14` 时使用 `--run-start 10 --replace-existing -n 5`；旧结果和过程文件会在事务中备份，只有新批次成功才替换。执行/错误 `.log/.err` 始终追加，作为覆写操作的审计轨迹。

### 2.5 `data` 子命令

检查默认 `_pdata` 或指定数据根：

```sh
evoflow data
evoflow data D:\datasets\EvoFlow\_pdata
```

`minimal` 表示 13 个首方样例齐全，`full` 表示另有 701 个完整数据 overlay 实例；`missing` 和 `incomplete` 返回退出码 1。原生命令检查 manifest 文件集、大小和实例计数；需要复算 SHA-256 时使用 `python -m evoflow --check-data [路径]`。安装结构和状态语义见 [数据包与外部数据](../数据包与外部数据.md)。

## 3. 示例

```sh
# 基本：跑首方 TSP 小样例,用蚁群配置 ACS,种子 42
./evoflow run _pdata/tsp/sample.tsp config/ACS.cfg -s 42

# 覆盖预算 + 只要 fitness(脚本友好)
./evoflow run _pdata/qap/sample.qap config/ACS.cfg --max-fes 50000 -q

# 结果写文件
./evoflow run _pdata/tsp/sample.tsp config/ACS.cfg -o result.txt

# 参数扫描使用独立输出身份；同一 tag 的后续调用自动续号
./evoflow run _pdata/tsp/sample.tsp config/ACS.cfg --tag sweep --optimizer-name ACS_p1

# 明确重做结果编号 10（危险操作：显式起点 + 显式替换授权）
./evoflow run _pdata/tsp/sample.tsp config/ACS.cfg --tag sweep \
  --optimizer-name ACS_p1 --run-start 10 --replace-existing
```

正常输出（非 `-q`）：

```
problem: _pdata/tsp/sample.tsp
seed: 42
runs: 1
best_fitness: 12
solutions: 1
  [1] length:  12.000000   x: ...
```

> 首方 `sample.tsp` 是 3-4-5 三角形，任何合法三城巡回长度都为 12，因此它不依赖某个外部参考解，适合安装冒烟测试。

## 4. 路径规则（重要）

exe 按**当前工作目录（CWD）**解析 `_pdata/`、`config/`，**不是**按 exe 自身位置：

- **在项目根目录运行**：可用相对/短路径（`_pdata/tsp/...`、`config/...`）。
- **从别处运行**：给问题/配置传**绝对路径**，否则相对路径找不到文件。

问题文件路径本身也自适应：含 `/`、`\`、`.` 之一 → 当完整/相对路径用；否则当短名 → 拼 `_pdata/<kind>/<name>.<ext>`（仅在按家族直接调模板时；通用载入器 `loadProblem` 需真实路径以读取 `TYPE:` 头分派）。

## 5. 两条输出通道

| 通道 | 去向 | 内容 |
|---|---|---|
| **exe 的 stdout / `-o` 文件** | 控制台或指定文件 | 最终最优解（本章 §3 的输出） |
| **框架 Logger** | `_log/<name>/...` 下的 `.log`/`.err`/`.rslt`/`.prcs` | 执行日志、错误、每次运行结果、每代过程 |

二者独立：`-q`/`-o` 只影响 stdout 通道；`-v` 让每代过程**同时**回显控制台（原本只落 `.prcs` 文件）。日志文件始终生成（框架行为）。

## 6. 支持的问题家族

13 个精确 `TYPE` 可经文件载入（`TYPE:` 头分派）：ATSP、CFLP、CPMP、CVRP、FJSP、MDS、MIS、MKP、QAP、SR、STP、TSP、WFS。TSP/ATSP 共用 TSP 资料家族，因此对应 12 个具体文件模板。各家族的数据文件格式见 `_pdata/<kind>/README.md`。

现成可执行程序只加载这些已注册模板，不动态装载任意外部 DLL/SO。连续优化和外部 benchmark 请使用 C++ 宿主或 Python callable 教程接入。

程序包只携带 13 个首方样例。许可明确的 701 个外部实例单独发布；TSPLIB、QAPLIB 和 GK 数据由用户按 [外部数据教程](../../tutorial/external-data/README.md) 自行下载和转换。
