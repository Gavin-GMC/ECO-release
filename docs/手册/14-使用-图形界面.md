# 14 · 使用者篇 · 图形界面

EvoFlow 图形界面面向不想手写配置、希望先检查问题定义、连接模型服务或直接查看实验统计结果的使用者。界面由一个本机服务和默认浏览器组成，仍由同一个 `evoflow.exe` 提供，不需要另外安装前端程序。

图形界面和模型连接当前仅在 Windows x64 发布包中提供。Linux 核心/CLI 的后续验证不代表这两个 Windows 系统 API 功能已移植。

> 图形界面负责**读取并另存问题、构筑并保存优化器配置、运行当前问题与配置、分析已有运行日志**。批量运行和完整命令行选项仍见 [13-使用-可执行程序](13-使用-可执行程序.md)。

---

## 1. 启动与退出

### 1.1 启动

以下两种方式等价：

```text
双击 evoflow.exe
```

```sh
evoflow
```

程序会：

1. 在 `127.0.0.1` 的动态端口启动本地服务；
2. 生成本次会话专用的一次性令牌；
3. 用默认浏览器打开 EvoFlow；
4. 在界面左下角显示“本地服务已连接”，并在左上角标识下显示实际产品版本。

从资源管理器双击时，启动终端会在浏览器成功打开后自行关闭；从已有 CMD 或 PowerShell 启动时，原终端只恢复提示符，不会被 EvoFlow 关闭。真正承载界面的后台宿主没有控制台窗口。

平台左上角使用发行目录中的 `figs/Logo.png` 作为 EvoFlow 标识。Logo 下方显示“**模块化演化计算工作台**”主标题以及由本机健康接口返回的 `EvoFlow 3.0.1.5` 产品版本；英文模式同步显示 “Modular evolutionary computation workbench”。使用完整交付目录时无需额外配置；若手工移动 `evoflow.exe`，应同时保留同级 `figs` 目录。

### 1.2 退出

点击右上角 **“退出 EvoFlow”**。页面会请求本地服务有序关闭，并显示“EvoFlow 已退出”。

直接关闭浏览器标签页或窗口时，页面也会通知本地服务；服务保留约 2 秒刷新宽限后自动取消正在执行的优化并退出。正常刷新会由新页面的即时心跳撤销关闭请求，不会误关服务。浏览器被强制结束而来不及发送通知时，仍由心跳超时兜底。

如果页面提示“缺少会话令牌”或“本地服务未连接”，不要继续使用旧标签页，重新运行 `evoflow.exe`。

## 2. 三个页面

| 页面 | 用途 | 输入 | 输出 |
|---|---|---|---|
| **问题定义** | 定义、检查并另存当前问题 | 自然语言描述、标准问题文件，或描述配合非标准文本数据 | 问题元信息及原始问题数据文件 |
| **优化器构筑** | 新建、打开、编辑、校验、保存并运行当前配置 | v3.1/v3.2 配置，或空白骨架 | `.cfg` 及按设定参数得到的运行结果 |
| **统计分析** | 扫描已有实验日志并生成报告 | `_log` 或其他日志根目录 | 可配置统计表、图表预览、SVG/PNG 下载 |

三个页面共用同一个本地服务。切换页面不会启动新的进程。

### 2.1 全局模型设置

右上角 **“模型设置”** 不属于某一个页面。大模型功能使用 OpenAI-compatible Chat Completions，需要填写：

| 字段 | 说明 |
|---|---|
| **完整接口地址** | 直接填写 Chat Completions endpoint，而不是只填服务根地址 |
| **模型名称** | 服务端实际接受的模型标识 |
| **API Key** | 可选；不需要认证的本地模型可留空 |

公网接口必须使用 HTTPS；明文 HTTP 只允许 `127.0.0.1` 或 `localhost`。点击 **“测试连接”** 后，界面显示未配置、测试中、已连接或连接异常状态。测试只发送固定的连接检查消息，不发送问题文件或配置内容。瞬时网络、超时、限流或服务端错误最多执行三次实际请求；按每次最长 90 秒接收超时计算，极端情况下可能等待约 4.5 分钟。

这些设置只保留在当前页面内存中。刷新、关闭页面或退出 EvoFlow 后都会清除，不会写入浏览器存储、配置文件、问题文件或普通日志。自然语言问题构建与现有配置推荐已分别在 2.4.2、2.4.3 接入，并在 2.4.4 完成动态资料与有界重试调整。

### 2.2 中英文切换

右上角 **“中 / EN”** 按钮可在中文和英文界面之间即时切换。导航、页面标题、表单、画布状态、统计指标和图表菜单会一并切换；用户填写的名称、文件内容、组件 tag 和运行结果不会被翻译或改写。

语言选择只属于当前浏览器页面，不写入浏览器存储或配置文件。刷新页面后重新以中文显示。

## 3. 问题定义

### 3.1 统一输入与自动分流

“问题定义”页只有一个入口，包含可选的自然语言描述、可选的数据文件和一个提交按钮。至少提供一项；选择文件时只会暂存文件，不会立即加载。点击提交后按输入组合自动分流：

| 输入 | 处理方式 | 是否使用模型 |
|---|---|---|
| 仅自然语言描述 | 自动识别现有问题类型，按对应模板生成、检查并加载问题 | 是 |
| 仅数据文件 | 把文件视为 EvoFlow 标准问题格式，在本地检查并加载 | 否 |
| 自然语言描述 + 数据文件 | 先在本地尝试标准格式；成功则直接加载，失败才把文件作为参考数据交给模型转换 | 视文件而定 |

仅文件路径允许单个标准问题文件最大 **64 MiB**。文件类型由问题数据中的 `TYPE:` 及既有 `loadProblem` 路径识别；支持范围和格式见 [10-使用-问题模块](10-使用-问题模块.md) 及各 `_pdata/<家族>/README.md`。标准格式解析失败时不会自动把文件上传给模型；界面会提示用户补充自然语言描述后再提交。

描述配合文件时，系统仍会先尝试把文件作为标准问题数据在本地加载。因此即使描述只是“请帮我定义这个问题”，配合标准文件也能直接成功，不要求用户预先判断文件类别，描述和文件均不会上传。只有标准加载失败后，文件才会进入参考数据路径；此时参考数据须为有效的 UTF-8 文本，支持普通文本、CSV、TSV 或 JSON，最大 **1 MiB**，不得包含 NUL；当前不解析 `.xlsx`、图片、压缩包等二进制附件。例如可填写“我想访问附件中的所有地点，请规划总路程最短的路线”，并附加地点名称与坐标 CSV。

### 3.2 显示内容

加载成功后显示：

- 文件名、问题名称、问题类型和决策维度；问题名称与问题类型分栏显示，不再把内部临时路径拼在类型后；
- 变量总数，以及每个变量的名称、种类、值类型、长度、下界和上界；
- 每个目标的名称、最小化/最大化方向、优先级和关联变量；
- 每条约束的类型、作用变量、惩罚系数和施加目标。

这里读取的是问题的**定义态规格**：

- 不调用 `compile`；
- 不构造 `ProblemHandle`；
- 不运行优化器；
- 不把编译期自动生成的域约束混入定义态列表。

当前页面的定义内容只读：问题名称、变量、目标和约束不能在本版本中修改。加载成功后可点击 **“另存问题”**，把当前会话中的原始问题数据写到新位置；浏览器不支持文件系统写入 API 时会退化为下载。该操作不重新序列化问题模板、不改变格式，载入文件与另存文件逐字节一致。

手动载入的问题使用所选文件的主文件名（去掉扩展名）作为稳定问题名称。例如 `berlin52.tsp` 的问题名称为 `berlin52`。模型生成的问题使用生成数据中的 `NAME:`；生成提示要求模型给出简洁、稳定且不照抄示例的名称。问题一旦成功载入，本次会话内的后续单轮或多轮运行都复用这个名称，不再根据随机临时文件重命名，因此同一问题的评估日志会持续归入 `_log/<优化器名>/<问题名称>/`。

### 3.3 模型辅助构建问题（2.4.2 / 2.4.4）

> 2.4.2 的两轮流程已实现；2.4.4 根据试用反馈加入运行期资料发现和每阶段最多三次的有界修复。

先在右上角配置模型并通过连接测试，然后：

1. 在自然语言输入框中说明对象、数据、决策目标和约束；
2. 如数据尚未整理为 EvoFlow 标准问题格式，可附加 UTF-8 文本、CSV、TSV 或 JSON；
3. 点击统一提交按钮；按钮会随输入显示“智能构建问题”或“结合数据构建问题”；
4. 系统从当前注册的问题模板与 `_pdata` 运行期资料中自动识别类型；
5. 类型通过白名单后自动进入第二轮，按该模板生成问题数据；
6. EvoFlow 检查格式、规模与 `TYPE`，沿既有加载路径读取并执行一次 `compile`；
7. 成功后复用现有表格显示问题名称、变量、目标和约束。

界面不会要求用户选择或确认 TSP、CVRP、QAP 等专业模板类型。自动识别的类型只作为进度信息展示。如果描述不属于当前任何已注册模板，操作会失败，不会凭相似名称强行映射。

点击模型辅助构建即表示把自然语言描述以及所附参考数据发送到用户配置的模型服务。两者在提示中都被明确标记为不可信数据，附件只作为事实来源，不得改变系统格式要求。模型只负责分类和生成候选数据；以下判断始终由 EvoFlow 机械执行：

- 类型是否属于精确白名单；
- 返回是否为约定的严格 JSON；
- 数据大小、关键计数和矩阵/图规模是否安全；
- 文件内 `TYPE` 是否与分类结果一致；
- 既有模板是否能加载；
- 问题是否能 `compile`。

分类和生成各自最多发出三次实际模型请求。网络、超时、限流和瞬时服务错误会用原提示重试；严格 JSON、白名单、数据预检、模板加载或 `compile` 失败会把受限的机器原因与上一响应反馈给模型，要求返回完整替代结果。认证失败、设置错误、本地资料不可用、合法 `type:null` 或临时文件不可写会立即结束。任何最终失败都不会覆盖当前已加载的问题。生成成功的数据保留在当前 UI 会话的临时目录，并可通过结果区的 **“另存问题”** 写出。

当前运行期有 13 个精确文件 `TYPE`、12 个资料家族。TSP 与 ATSP 暂时仍用文件 `TYPE` 表达对称/有向语义，但程序把二者分派到同一个 `_pdata/tsp` 格式资料和 `PT_TSP`；不会创建独立 ATSP 目录或样例。图形界面不动态装载任意外部原生 benchmark；此类问题从 C++/Python 用户侧接口接入。

## 4. 优化器构筑

### 4.1 文件与草稿

工具栏提供：

| 操作 | 说明 |
|---|---|
| **新建** | 建立一个可继续编辑的空白配置骨架 |
| **打开 .cfg** | 打开 v3.1 文本或 v3.2 JSON 配置；单文件最大 64 MiB |
| **保存** | 已获得文件写入句柄时覆盖原文件，否则转入“另存为” |
| **另存为** | 选择新目标；不支持文件系统写入 API 的浏览器会退化为下载 |
| **格式** | 选择保存为 v3.1 文本或 v3.2 JSON；扩展名统一为 `.cfg` |
| **装配验证** | 真正构造一次优化器，但不运行优化 |
| **运行标签 / 种子 / 运行轮数** | 会话级运行设置；标签最多 128 个字符，种子为 0～4294967295，独立运行轮数为 1～10000 |
| **运行当前配置** | 以当前问题、当前配置和会话级运行设置执行优化；终止预算取自配置 |

无论打开的是 v3.1 还是 v3.2，编辑期间都只保留一份规范化内存草稿。表单和积木视图读取、修改的也是这同一份草稿；保存时才由既有编码器输出所选版本，不产生新的配置文件类型。

优化器表单中的**配置默认标签**属于配置文件，会随打开的文件读取并随保存写回。工具栏下方“运行设置”中的**运行标签**属于当前界面会话，载入、新建或推荐其他配置都不会改变它；填写后会在本次运行中覆盖配置默认标签，留空则使用配置默认标签，两者都为空时按既有规则自动生成实际标签。

有未保存修改时再点“新建”或“打开”，界面会要求确认。

### 4.2 根据当前问题推荐现有配置（2.4.3）

> 2.4.3 已实现；2.4.4 增加非法 JSON 或未命中白名单时的有界修复，候选范围和载入规则不变。

先加载或智能构建一个问题，并在右上角连接模型服务。进入“优化器构筑”页后点击 **“根据当前问题推荐”**：

1. 服务端读取当前问题的类型、维度、变量、目标和约束；
2. 只枚举启动工作目录下固定 `config` 目录中的直属 `.cfg`；
3. 候选先经现有配置解码器转为 canonical 内存草稿；
4. 模型从候选精确文件名白名单中选择一个；
5. 服务端再次逐字命中该文件名，然后把机械读取的候选草稿交给现有配置编辑器。

模型不能返回任意路径、配置正文或新算法定义，也不能修改组件、顺序或参数。返回名大小写不一致、带解释、带 Markdown、包含额外 JSON 字段或不在候选目录中，会在同一阶段最多三次实际请求的预算内附机器原因要求完整重答；耗尽后拒绝。

若当前草稿尚未保存，界面会在载入推荐项前请求确认；取消或推荐失败不会改变当前草稿。推荐项不持有内置配置文件的写入句柄，因此点击“保存”会转入“另存为”，不会覆盖 `config` 中的原候选。

点击推荐会把当前问题的必要结构化摘要与候选配置摘要发送到用户填写的模型 endpoint。产品不预置模型服务、模型名或 Key。

### 4.3 左侧配置结构

“配置结构”按四层组织：

1. **优化器设置**
   - 优化器名称与运行标签；
   - FES、时间、停滞代数终止条件；
   - 结果、过程、完整过程和整群快照日志开关；
   - 全局档案组件及参数。
2. **Workflows**
   - 可新增、删除多个 workflow；
   - 每个 workflow 包含标识、初始化器和有序组件；
   - 修改 workflow 标识时，引用它的子种群会同步更新。
3. **Subpopulations**
   - 可新增、删除多个子种群；
   - 设置标识、规模、绑定 workflow、局部终止条件和子群档案。
4. **Cooperation**
   - 配置子群管理器、子群构建器和协作拓扑。

至少保留一个 workflow 和一个子种群。优化器、workflow、子种群等写入 v3.1 的标识不使用空格，建议只用字母、数字、下划线、点和连字符。

### 4.4 表单式 workflow

一个 workflow 的组件按列表顺序执行。可使用：

- **添加组件**；
- 类别和组件下拉框；
- 上移、下移；
- 复制；
- 删除。

workflow 内可出现的六类有序组件是：

```text
学习拓扑 → 修复器 → 学习策略 → 子代生成 → 评价器 → 环境选择
```

这不是强制每类只出现一次；真实要求由组件契约和执行语义决定，同一类别可以重复出现。`SET` 型组件通常必须位于消费它的生成组件之前。

左侧“组件目录”来自当前注册表，共列出 12 个类别。目录顶部可按**组件 tag、类别关键字、中文或英文类别名称**即时检索；检索只改变显示范围，不修改配置。`individual` 和 `feature` 由装配期自动推断，只用于浏览，不直接写入 workflow 配置。

### 4.5 参数控件

参数控件由组件的 `ParameterTemplate` 动态生成，不在网页中维护另一份参数表。

每个参数会显示：

- 名称；
- Enum、Int 或 Real 类型；
- 硬边界；
- 推荐区间；
- 当前值；
- 是否允许留空。

勾选 **“使用组件内部默认参数”** 时，配置中不写参数数组；取消后会填入注册表给出的推荐默认值。动态参数会根据前面参数的取值继续披露。

当前 Enum 元数据只有数值范围，因此部分枚举下拉显示数值而不是友好名称；当前尚未提供语义标签，前端不会自行猜测。

### 4.6 静态校验与装配验证

每次修改后，页面会自动执行静态校验，并在顶部状态徽章及下方“配置校验”区域显示：

- Error、Warning、Info 数量及整体最高级；
- 问题所在 optimizer/workflow/subpopulation；
- workflow 中的组件下标；
- 稳定的 `reason` 键；
- 具体消息。

点击一条问题可以定位到对应表单项。

四级含义为：Error 表示静态可确定无法构建或执行链无效；Warning 表示可以构建但无法保证正常执行或退出；Info 表示可以执行并退出，但语义、结果、效率可能偏离预期或存在冗余；Pass 表示静态检查没有发现配置问题。Pass 是整体状态，不会生成单条问题，也不是对所有运行时输入的绝对证明。

点击 **“装配验证”** 会进一步真正构造优化器，用于发现静态结构检查无法捕获的问题，例如子种群引用了不存在的 workflow。它不运行问题和优化算法。

界面、CLI 和 Python 的 `validate` 使用同一条 `ConfigValidator → AssertMatcher + ParamMatcher` 路径。只有 Error 阻止装配与运行；Warning 和 Info 允许保存、装配和运行，并保留明确提示。保存仍允许用户保留含 Error 的未完成草稿，但会要求确认。因此“文件已经保存”不等于“配置能够运行”；正式运行前至少应消除 Error，并核对所有 Warning/Info 是否符合意图。

## 5. 积木式 workflow

### 5.1 进入积木视图

选择一个 workflow，然后点击工具栏中的 **“积木”**。切回 **“表单”** 时，组件和参数保持同步，因为两种视图共用同一份内存草稿。

初始化器显示为固定的 `START` 起点；初始化器类型和参数仍在表单中编辑。

### 5.2 自由画布与缩放

支持以下操作：

- 从左侧组件目录把组件拖到画布任意位置；
- 双击目录中的组件，将其追加到当前有效单链末尾；
- 在上下、左右或组合布局中自由拖动现有积木；
- 在右侧检查器中切换类别、组件、参数或删除积木；
- 选中积木后按 `Delete` 或 `Backspace` 删除。

积木的位置不决定执行顺序，workflow 也不再要求从左到右排列；执行方向只看有向箭头。工具栏的 **− / 百分比 / +** 可在 40%～180% 之间缩放画布，点击百分比恢复 100%；低于 90% 时 SVG 会真实缩小，不再受固定最小宽高撑回。**“自动整理”** 会按当前有向流重新排成紧凑网格。

**“适应全貌”** 会根据当前工作流的实际边界和画布可见区域自动计算缩放，并把视图回到左上起点。**“画布全屏”** 会让积木编辑器覆盖当前窗口，暂时隐藏外部配置侧栏和常驻参数检查栏，并自动适应全貌。全屏画布左上角同时提供可收起的**浮动算子库**；它与普通组件目录共用检索条件，仍可把算子拖入画布。双击已有积木会在右侧打开浮动参数设置窗口；双击浮动算子库中的算子会把它追加到有效单链末尾，并立即打开新算子的参数设置。点击参数窗口的关闭按钮或按 `Esc` 会先关闭参数窗口；再次按 `Esc`，或点击 **“退出全屏”**，才退出全屏并恢复常驻参数栏。画布超出可见范围时仍可横向或纵向滚动。

二维位置和缩放属于当前页面的编辑状态，不写入 `.cfg`。重新载入配置时，界面会根据组件顺序建立默认二维布局。

### 5.3 有向箭头与配置顺序

从某块积木右侧输出卡扣拖线到另一块积木左侧输入卡扣，会建立一条**源 → 目标**的有向箭头。重新从同一输出卡扣连线时，旧的输出连接先断开；连接到已有输入的积木时，旧的输入连接会被替换。点击一条连线或在其获得键盘焦点后按 `Delete`、`Backspace`、`Enter` 可删除它。

只有满足以下条件时，画布才把顺序写回配置草稿：

1. 从 `START` 出发；
2. 沿箭头恰好访问全部积木一次；
3. 没有分叉、环或遗漏积木；
4. 得到一条覆盖全部组件的单一有向流；
5. 该顺序通过现有配置连接检查。

当前 `.cfg` 的 workflow 仍是**线性有序数组**，不是任意 DAG。画布从有效单链读取组件顺序并写回原数组，不创建新的边文件或新配置类型；保存后不包含独立连线和坐标数据。

### 5.4 临时孤立组件与离开保护

拖入新组件、断开箭头或重新接线的过程中，画布允许暂时出现孤立组件、断链和不完整路径。这些状态只留在画布编辑层，不覆盖当前配置草稿；因此可以先摆放多块积木，再逐步接线。

画布会持续保留最近一次已经通过检查的完整单链。若仍有孤立、断开或未通过检查的组件，此时切换到表单、其他页面、其他 workflow，或用新建/打开/推荐替换当前草稿，界面会提醒：

- 选择**取消**：留在当前画布，临时组件和连线保持不变；
- 选择**确认离开**：丢弃临时状态，恢复历史最近的有效单一流后再离开。

刷新或关闭浏览器页面时也会触发浏览器的未完成修改提醒。若用户确认关闭，当前配置草稿本来就只包含最近有效单链，因此不会把孤立组件误写进配置。

### 5.5 连接检查与状态

每当箭头重新组成完整单链，候选顺序会送到服务端，沿现有配置校验链检查。合法候选写回草稿；非法候选保留为画布临时状态并显示原检查原因，直到用户修复连接或恢复历史有效流。

颜色状态如下：

| 状态 | 含义 |
|---|---|---|
| **满足** `satisfied` | 当前组件的结构契约满足 |
| **信息** `informational` | 可继续并可正常退出，但语义、结果、效率可能偏离预期或存在冗余 |
| **有警告** `notfullysatisfied` | 可继续，但无法保证正常执行或退出 |
| **数量不足** `failsatisfied` | 供给数量低于需求 |
| **不满足** `unsatisfied` | 缺少类型、顺序或其他硬契约 |
| **临时孤立** `isolated` | 组件尚未接入从 `START` 开始的当前路径 |

选择积木后，右侧检查器会显示：

- 当前类别和组件；
- 当前参数下的需求与供给；
- 对应校验原因；
- 参数控件；
- “在表单中定位”按钮。

删除和断线都允许产生临时不完整状态；下方共用校验报告始终只对应已经写入配置草稿的最近有效单链。

## 6. 运行当前问题与配置

在问题页成功加载或生成问题后，在配置页的“运行设置”中填写**运行标签**、**种子**和**运行轮数**。**结果起点**通常留空，让系统从同一优化器/问题/tag 的最大已有编号后自动续号，再点击 **“运行当前配置”**。界面会先要求当前配置通过静态校验和装配验证，然后：

1. 把当前内存草稿机械编码为临时 v3.1 `.cfg`；
2. 复用与 CLI 相同的 `App::runOptimization`，执行“载问题 → 读配置 → 装配 → 运行”；
3. 按配置中的终止条件以及本页填写的种子和轮数运行；
4. 优先使用会话级运行标签；留空时使用配置默认标签，两者均为空则自动生成；
5. 运行期间动态显示当前轮次、已完成轮数和总进度；
6. 全部轮次完成后保存每一轮的独立结果，显示实际标签、优化器身份、调用内轮次、实际结果编号、种子、最优适应度、目标值和完整解文本；
7. 请求结束后删除临时配置文件。

当前配置无需先保存到磁盘。修改配置后，旧运行结果会隐藏，避免把旧结果误认为新配置的结果。多轮运行会按既有日志规则分别记录；每一轮结果写入完成后，进度会从 `1 / N` 推进到下一轮。全部完成后，结果区上方出现 **← / →** 翻页按钮，可在第 `1…N` 轮之间切换，每页显示该轮自己的实际结果编号、最优适应度、目标值和解文本。

只有填写非负的**结果起点**后，“覆写旧结果”才可勾选；勾选并点击运行时还会出现二次确认。未勾选时，显式范围内任一 `.rslt/.prcs` 已存在都会在优化开始前整批拒绝。勾选后旧文件先进入事务备份，新批次失败、取消或关闭页面时恢复；全部成功才提交替换。执行/错误日志始终追加，保留操作审计。

进度粒度是“独立运行轮次”，不是单轮内部的迭代次数或函数评价次数，因此耗时较长的一轮执行期间，当前轮次会保持不变。当前入口不提供手动暂停或预算覆盖；退出 EvoFlow 或关闭页面会请求取消当前后台运行。其他场景仍可在项目根目录或正确工作目录使用：

```sh
evoflow run <问题文件> <配置文件> [选项]
```

建议流程：

```text
问题定义页检查问题
→ 优化器构筑页完成配置
→ 静态校验通过
→ 装配验证通过
→ 运行当前配置
```

也可以保存 `.cfg` 后使用 `evoflow run`。

需要批量验证配置时使用：

```sh
evoflow validate <配置或目录> --build
```

完整命令、预算覆盖和日志参数见 [13-使用-可执行程序](13-使用-可执行程序.md)。

## 7. 统计分析

### 7.1 数据前提

统计页读取 `evoflow run` 已经生成的 `.rslt` 日志，不重新运行优化器。实验运行时应显式使用同一个 `--tag`：

```sh
evoflow run problemA configA --tag exp1 -n 30
evoflow run problemA configB --tag exp1 -n 30
```

### 7.2 生成报告

1. 输入日志根目录，默认 `_log`。相对路径按 EvoFlow 的启动工作目录解析，也可输入绝对路径。
2. 点击 **“扫描批次”**。
3. 选择一个 tag 批次。
4. 勾选要比较的优化器和问题。
5. 在“分析设置”中调整归约、跨轮统计、优化器比较和报告图表。
6. 点击 **“生成统计报告”**。

每份报告只允许一个“单次运行归约”指标。归约可以选择：

- 描述统计，并指定目标列；
- 自定义分位数，并指定目标列；
- HyperVolume、GD、IGD 或多峰质量指标。质量指标需要按所选问题填写参考数据。

“跨轮统计”可以添加、删除多个统计列，包括 Mean、Std、Median、Q1、Q3、SEM、CV 等，也可以重复添加不同分位点的 Percentile。至少保留一个跨轮统计指标。

“优化器比较”可以添加多个比较指标。需要代表值的比较可选择依据的已添加统计列；Best、Rank、Win/Tie/Lose 还可设置“越小越优/越大越优”。Significance、Kruskal–Wallis 和 Dunn 直接使用运行分布，不显示无效的依据与方向控件。基准优化器用于需要基准的统计检验。参数化 Percentile 可以显示为统计列，但比较依据当前只接受具名统计指标。

未修改设置时仍使用原有默认口径：

```text
每次运行最小值
→ Mean / Std / Median
→ Best / Rank
→ 统计表 / 跨问题箱线图 / 平均秩图
```

图表菜单支持：

| 图表 | 主要设置或前提 |
|---|---|
| 统计表图 | 无额外设置 |
| 单问题/跨问题箱线图 | 问题、归一化、抖动点 |
| 单问题/跨问题统计柱状图 | 统计列、区间、归一化 |
| 平均秩柱状图 | 需要 Rank 或 Nemenyi |
| 排名热力图 | 选择已添加的具名统计列 |
| 胜/平/负图 | 需要 Win/Tie/Lose 比较 |
| Nemenyi 临界差异图 | 需要 Nemenyi 比较 |
| 收敛曲线 | 需要对应 `.prcs` 过程日志；可设问题、统计列、区间和采样网格 |
| Pareto 前沿 | 需要多目标结果；可设问题、目标轴、运行轮次和连线 |

可通过菜单多次添加同一类图表并分别设置；每个单问题图明确绑定一个所选问题。若依赖的数据或比较指标不存在，生成报告时会明确拒绝，不会显示空图。

SVG 由 CLI 共用的 `buildReport → ECAnalyzer` 路径生成并直接嵌入页面，浏览器不重新计算统计量或重画另一份图。

### 7.3 数据不齐

批次存在下列情况时会标记“数据不齐”：

- 某个“优化器 × 问题”组合缺失；
- 各组合重复次数不同；
- run 编号不连续。

生成报告时，所选矩形范围必须包含从 run 0 开始的共同连续数据。页面会使用共同可用的最小重复次数，并提示其余运行没有参与统计；若缺少 run 0，则拒绝生成。

### 7.4 图表下载

每张图可以下载：

- **SVG**：页面内同源的矢量图；
- **PNG**：服务端从同一图表数据生成的位图。

PNG 设置包括英文字体、中文字体和分辨率倍率。默认字体路径为：

```text
C:/Windows/Fonts/times.ttf
C:/Windows/Fonts/simsun.ttc
```

项目不分发商业字体。页内 SVG 不依赖这些字体文件；只有 PNG 下载受影响。字体路径无效时，PNG 生成会明确报错。

## 8. 本地服务与数据安全

图形界面的安全边界如下：

- 只监听 `127.0.0.1`，不监听局域网地址；
- 每次启动生成新的随机令牌；
- 令牌经 URL fragment 交给页面，不进入普通 HTTP 路径或服务日志；
- API 校验令牌、`Host` 和 `Origin`；
- 请求头和文件体有大小限制；
- 当前问题使用的临时文件在替换问题、退出或服务析构时删除；临时文件名不参与问题身份和日志目录命名；
- 页面关闭会发送带会话令牌的关闭通知；后台运行收到取消请求后在终止检查点结束，宿主不再等待完整预算耗尽；
- 统计图临时目录在响应构造后清理；
- 图表下载只接受本次报告中已校验的图表 ID，不接受任意文件路径。
- 模型 Key 只随当前请求保留在内存中，不写磁盘、浏览器存储、日志或接口回包；
- 模型客户端关闭自动重定向，避免把认证头转发到另一个地址；
- 公网模型 endpoint 只允许 HTTPS；本机模型的 HTTP 例外仅限 loopback 主机。

标准问题文件单独加载、配置编辑和统计分析不会上传到互联网。模型连接测试会访问用户填写的 endpoint，但只发送固定检查消息；模型辅助问题构建会把用户输入的问题描述及可选参考数据发送到该服务；现有配置推荐会发送当前问题的必要结构化摘要，以及服务端已规范化的受限候选目录。模型只负责返回候选 ID，不能提供最终载入的配置正文。

## 9. 常见问题

### 页面显示“缺少会话令牌”

不要直接收藏或重新打开旧 URL。关闭旧标签页并重新运行 `evoflow.exe`。

### 左下角显示“本地服务未连接”

服务可能已退出或心跳超时。重新运行 `evoflow.exe`；不要继续在断开的页面中编辑。

### 保存后找不到原文件

浏览器不支持 File System Access API 时，“保存/另存为”会退化成浏览器下载。到浏览器默认下载目录查找生成的 `.cfg`。

### 配置能保存但不能运行

保存允许用户保留尚未完成的草稿。检查顶部错误数、下方校验报告，并执行“装配验证”；也可以运行 `evoflow validate <配置> --build`。

### 统计页找不到批次

检查：

- 日志根目录是否按启动工作目录解析；
- 运行时是否生成了 `.rslt`；
- 多个算法是否使用了同一个显式 `--tag`；
- 是否误把配置文件名当成优化器名。日志中的优化器名来自 `.cfg` 内部 `name`。

### PNG 下载失败

确认字体路径存在、倍率在 `0.25–8` 范围内。也可直接下载不依赖系统字体的 SVG。

### 模型连接测试失败

依次检查完整 endpoint、模型名称和 Key。公网地址必须是 HTTPS；本机 HTTP 地址应使用 `127.0.0.1` 或 `localhost`。界面会区分认证失败、限流、超时、网络失败、服务端拒绝和非法响应。部分服务虽宣称 OpenAI-compatible，但响应字段不同，仍会被当前固定协议拒绝。

### 自然语言问题构建失败

先看失败发生在“识别模板类型”还是“生成并机械检查”。识别失败通常表示描述不属于当前模板白名单，或模型连续三次未返回严格 JSON；生成失败可能来自格式、规模、`TYPE`、模板加载或 `compile`。界面会在发生重试时显示实际尝试次数。三次耗尽或遇到不可重试错误后才结束，失败不会清空此前已加载的问题。

如果使用了参考数据，还要确认文件不超过 1 MiB、采用 UTF-8 文本编码且不含 NUL。只有标准问题文件时若解析失败，请补充自然语言任务说明后再提交；系统不会在没有说明的情况下擅自把失败文件发给模型。

### 现有配置推荐失败

先确认已经成功加载问题并通过模型连接测试。候选目录不可读、其中某个 `.cfg` 无法经既有解码器规范化或当前问题摘要过大属于本地错误，会立即拒绝。模型未返回严格 `{"config":"文件名.cfg"}` 或文件名未逐字命中白名单时会在最多三次实际请求内要求重答。最终失败不覆盖当前配置，也不会退化为让模型生成一个新配置。

## 10. 当前范围与延期项

当前已实现：

- 问题文件加载与定义态元信息；
- 载入问题或模型生成问题的原始数据另存；
- 表单式优化器构筑；
- 积木式线性 workflow 构筑；
- v3.1/v3.2 `.cfg` 打开、保存和另存；
- 静态校验和装配验证；
- 当前问题 + 当前内存配置草稿的单次运行与结果展示；
- 运行日志扫描、统计表和 SVG/PNG 图表；
- OpenAI-compatible 模型设置、连接测试和结构化错误展示；
- 自然语言描述 → 运行期模板资料发现 → 自动类型识别 → 模板数据生成 → 有界机械修复 → 加载/compile 的问题构建；
- 当前问题摘要 → 现有 `.cfg` 精确白名单选择 → 有界机械修复 → canonical 草稿载入的配置推荐。

当前未实现或明确延期：

- 问题名称、变量、目标和约束等定义内容修改，以及修改后按原格式保存；
- 在图形界面中暂停、取消、批量运行或实时监视优化；
- Enum 参数的友好语义标签；
- 非模板问题代码生成、配置自适应生成和自动运行反馈闭环——安排在 **3.5**。
