# 21 · 开发者篇 · 内部组件（注册表 · 断言 · 加一个新算子）

面向要**扩展算子**的开发者。核心机制两个：**自注册表**（组件即插即用）+ **装配期断言**（组件间兼容校验）。
末尾给出「加一个新学习策略」的完整可照抄步骤（本项目 GWO/WOA/免疫/FWA 都按此加）。

## 1. 自注册表 `Registry<Base>`

每个组件基类（`LearningStrategy`/`LearningTopology`/`EnvirSelect`/…）有**一张** `Registry<Base>`（Meyers 单例，`core/registry.h`）。组件用 `ECFLOW_REGISTER` 宏（C++17 `inline` 变量）在自己文件末尾**自注册**，按字符串 `tag` 入表。配置层/装配器只按 tag `create`，**不认识具体类**——所以加算子无需改工厂/配置层。

### Entry 结构（注册项）
```cpp
inline Registry<LearningStrategy>::Entry xxxEntry() {
    return {
        "MyStrategy",                       // tag(配置用名;行为名,纪律 4)
        ModuleType::T_learnstrategy,        // 类别(见 §3)
        ParameterTemplate{ {               // 参数模板(名/类型/范围/推荐值),供校验+自动生成
            {"alpha", ParamKind::Real, 0.0, 10.0, false, 1.0, 3.0},
        } },
        sizeof(MyStrategy),                 // 供内存估算
        [](const double* p) -> LearningStrategy* {          // create:按参数造实例
            return p ? new MyStrategy(p[0]) : new MyStrategy();
        },
        [](AssertList& L, const double* p){ MyStrategy::preAssert (L, const_cast<double*>(p)); }, // 需求
        [](AssertList& L, const double* p){ MyStrategy::postAssert(L, const_cast<double*>(p)); }  // 提供
    };
}
ECFLOW_REGISTER(lstrat_mystrategy, LearningStrategy, xxxEntry());   // 唯一 id, 基类, entry
```
- **create** 收 `const double*`（配置传入的参数数组，可空→默认构造）。
- `ParamKind`：`Real`/`Int`/`Enum`/`Bool` 等；字段 = 名, 类型, 下界, 上界, 允许空, 推荐下界, 推荐上界。
- **createArray(tag, n, para)**：批量造 n 个（个体族用）。

> **MSVC 注意**：含非 ASCII 注释的源文件需 UTF-8 **BOM** 或 `/utf-8`，否则被当 GBK 吃掉换行 → C2059。

## 2. 装配期断言 `AssertMatcher`

组件间的兼容契约用 **pre/postAssert** 声明，`buildOptimizer()` 时由 `AssertMatcher`（`config/assert-matcher.h`）沿 workflow 校验：**沿途累积各组件 postAssert（"我提供 X"），逐组件核对 preAssert（"我需要 X"）**，不满足则装配期抛（早失败）。

```cpp
// 声明一条断言:类别, 上下文名, 值, 匹配方式
list.add(new Assert(ModuleType::T_individual,    "velocity",     1, MatchType::equal));          // 需求
list.add(new Assert(ModuleType::T_learntopology, "objects",      2, MatchType::notLessButNotice)); // 需求(≥2,不足告警)
list.add(new Assert(ModuleType::T_learnstrategy, "constructive", 1, MatchType::postAssert));      // 提供(我支持逐维构造)
```

两类最常见（见 [11-使用-优化器配置 §2](11-使用-优化器配置.md)）：
- **个体特性（INDIV-COMPOSE）**：策略/拓扑经 `featureDemands()` 声明所需特性（`velocity`/`pbest`/`sigma`/`whalestate`/`fireworkstate`/`setvelocity`），装配期推断、逐个体挂载、运行期按身份键取用；无个体子类。（旧 N6「个体类型提供上下文」机制已废，死路径清理见未来规划 ASSERT-N6-CLEANUP。）
- **拓扑学习对象数 `objects`**：策略要 objects≥N，拓扑 postAssert 声明产出数。
- **`constructive`**：策略声明支持逐维构造 → 才能配 `orderedConstruct`/`parallelConstruct` 生成器。

> 断言词汇需一致（`objects` 非 `object`、`constructive` 拼写等），见 未来规划 ASSERT-REVIEW。

## 4. 加一个新学习策略（完整步骤）

以「加一个新算法策略 `MyStrategy`」为例（拓扑/选择器/修复等同理，换基类与聚合头）：

**① 建文件** `src/optimizer/strategy/lstrategy-mystrategy.h`
- 4 段文件头 + UTF-8。
- 定义 `class MyStrategy : public LearningStrategy`，实现所需生命周期钩子：
  - `preparation_s(pop, terminator)`（每代前，可扫种群/读进度）、`preparation_i`（每个体前）、`nextDecision(d, individual, learning_object, handle, child)`（逐维取值）或 `getNewIndividual`（整体生成）。
  - `preAssert`/`postAssert`（静态，声明需求/提供）。
- 写 `xxxEntry()` + `ECFLOW_REGISTER(...)`（见 §1）。

**② 挂聚合头**：在 `strategy/learning-strategies.h` 加一行 `#include "lstrategy-mystrategy.h"`（拓扑→`learning-topologies.h`；新选择器→`optimizer-builder.h` + `assert-matcher.h` 的 include 点）。

**③ 加配置方法**：`config/config-setter.h` 的对应 `XxxSetter` 加一个具名方法：
```cpp
void myStrategy(double alpha = 1.0) { set("MyStrategy", { alpha }); }
```

**④（按需）逐个体状态怎么存** —— **INDIV-COMPOSE 后统一用特性挂载**（不再派生个体子类）：
| 状态性质 | 做法 | 实例 |
|---|---|---|
| **确定函数**（由种群/个体适应度算出，非随机） | `preparation_s` 建只读 `map<Individual*,double>`,`nextDecision` 查表（连状态都不必存） | 免疫 `AffinityHypermutation` / FWA `ExplosionSpark`。**constructive-safe** |
| **逐个体状态**（velocity/sigma/系数/集合速度…） | 组件 `featureDemands()` 声明一个特性（role/kind/scope/init）→ 装配期推断挂载；`ini` 缓存身份键；`preparation_i`/`nextDecision` 经 `individual->feature<T>(key)` 存取 | PSO `velocity` / ES `sigma` / WOA `whalestate`(scalar 4) / FWA `fireworkstate`(scalar 1) / SetPSO `setvelocity` |
| **跨代记忆**（历史最优）| 声明 `pbest`（`PbestFeature`）：`inheritAtBirth` 生成时随粒子前传、`afterEvaluate` 评估后择优 | PSO/SetPSO 的 pbest（由 `pgBest` 拓扑声明） |
| **停滞/年龄计数** | 声明 `age`（`AgeFeature`）：`get/reset/ageing`，`ini` 归零 | 年龄感知接受 `AgingAccept`（停滞→scout） |
| **解血缘**（源自哪个亲本）| 声明 `kinship`（`KinshipFeature`，Singular）：出生经 `birthFrom` 派生 `parent_id=parent.id`、`isChildOf` 一步归属 | ABC 逐源贪心 / 精英局搜（消费方另立增量） |
| **复用既有算子** | **装饰器**:内部经 Registry 造 inner、拥有、转发 ini/setProblem,包裹逻辑 | 禁忌 `TabuDecorator` / 免疫超变异包 `Gauss` |

> ⚠️ **逐个体状态别存策略成员标量**:`ParallelConstruct` 会**批量前置** `preparation_i`,共享标量被最后个体覆盖 → 存进个体的**特性**(状态随对象走)才安全。**特性 kind 与作用域** scope（Private/Exclusive/Singular）见 [24 §9](24-开发-组件清单.md)；共享同一特性经 `shareFeature`/`feature_channels`（如 PSO+CSO 同速度）。

**⑤ 配置表 + 冒烟**：`tutorial/config-generate*.cpp` 加一个配置；`tests/optimizer/.../smoke-xxx.cpp` 加收敛 + 装配兼容性验证（输出英文，纪律 6）；`build.ps1 tests\...\smoke-xxx.cpp` 跑绿。

**⑥ 命名（纪律 4）**：可插拔算子用**行为名**（PSO 拓扑→`PGBest`、GWO 策略→`GreyWolfEncircling`），不用母版算法名。

## 5. 选择器的两层设计（加环境选择时须知）

`EnvirSelect`（`selector/selector.h`）= **两层**：
- **第一层**（`update_subswarm(parent, offspring)`）：**找谁替换**——`Index` 逐位 / `Rank` 择优归并 / `Close` 最相似 / `WorstReplace` 最差 / `DistanceSelect` 距离密度。
- **第二层**（`AcceptCriterion`）：**是否替换**——`Unconditional` / `Better`(爬山) / `Anneal`(Metropolis) / `Aging`(年龄感知 = Better + `age` 特性 + scout)。`Rank`/`WorstReplace`/`DistanceSelect` 内建全局逻辑，不走接受层（传占位 `UnconditionalAccept`）。第二层 `accept` 透传 `Terminator*/BestArchive*`（Aging scout 记 FES/更新档案）。

加"新接受准则"改第二层；加"新替换结构"加一个 `EnvirSelect` 子类。
