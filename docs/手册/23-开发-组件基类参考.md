# 23 · 开发者篇 · 组件基类参考

按**基类**逐个说明：职责语义 + 关键虚接口（签名/语义/调用时机）+ 契约。
这是比 [11-优化器配置](11-使用-优化器配置.md)（具体 tag 目录）更底层的参考，面向要实现新组件或读懂流水线的开发者。
补充：注册/断言/扩展步骤见 [21-内部组件](21-开发-内部组件.md)，执行链见 [20-架构与流程](20-开发-架构与流程.md)。

> 约定：`=0` 纯虚（子类必实现）；`virtual`（可覆写，有默认）；`static preAssert/postAssert`（装配期声明需求/提供，见 21 §2）。

---

## 1. LearningTopology — 学习拓扑（谁向谁学）

**职责**：为当代种群构建**学习图** `LearningGraph`——每个个体（起点）配若干学习对象（终点=解）。执行型纯算子，注册于 `Registry<LearningTopology>`（`T_learntopology`）。

**接口**：
```cpp
virtual void ini() = 0;                                   // 每轮 exe 复位内部状态
virtual LearningGraph* getTopology(
    IndividualArray** subswarm,     // 子群数组;subswarm[0] = 当代种群
    BestArchive**     best_holder,  // 档案数组;best_holder[0] = 全局最优档案(可读全局最优)
    const int         swarm_number,
    IndividualArray*  offspring,
    LearningGraph*    last_graph) = 0;                     // 上代图(Inherit/NoChange 续用)
```
**契约**：
- 返回的图**调用方(生成器)负责 delete**；图内起点/终点是**指针引用**（不拥有，生命周期在本代内有效）。
- `postAssert` 声明产出的学习对象数 `objects`（策略据此校验，见 21 §2）。
- `objects=0` 表示自扰动（无学习对象，如 Isolate/爆炸类）。

### LearningGraph（学习图，非注册组件）
每条边 = 一个起点 `Individual*` + `end_point_size` 个终点 `Solution*`。`addStart`/`addEnd` 逐条构建；`getStartPoint(i)`/`getEndPoint(i)`(→`Solution**`)/`getSize`/`getEndSize`。**终点 `nullptr` = 该起点不学习、直接复制进子代**（生成器契约）。

## 2. LearningStrategy — 学习策略（怎么学 / 怎么生成）

**职责**：给定学习对象，生成子代。两条生成路径——**整体**（`getNewIndividual`）与**逐维构造**（`preparation_d`+`nextDecision`）。注册于 `Registry<LearningStrategy>`（`T_learnstrategy`）。

**生命周期钩子**（生成器按序调用）：
```cpp
virtual void ini(ProblemHandle*);                                   // 每轮 exe 复位
virtual void setProblem(ProblemHandle*);
virtual void preparation_s(IndividualArray& population, Terminator*);// 每代前(可扫种群/读运行进度)
virtual void preparation_i(Individual*, Solution** learn_obj, Individual* child); // 每个体前
virtual void preparation_d(int d, Individual*, Solution** learn_obj, ProblemHandle*, Individual* child); // 每维前
virtual double nextDecision(int d, Individual*, Solution** learn_obj, ProblemHandle*, Individual* child);// 逐维取值
virtual void update_d/​update_i/​update_s(...);                       // 维/个体/子代后更新
virtual void getNewIndividual(Individual* child, Individual*, Solution** learn_obj, ProblemHandle*); // 整体生成(默认=逐维循环)
```
**契约**：
- `nextDecision` **默认抛 `std::logic_error`**（该策略不支持逐维构造）；支持逐维的策略覆写它并 `postAssert("constructive",1)`。
- `preparation_s` 的 `Terminator*` 供读运行总进度（`getProgress()`，如 GWO/WOA 系数衰减）。
- **逐个体随机态**（每代重抽、跨维复用）须存进**个体对象**而非策略标量（`ParallelConstruct` 批量前置 `preparation_i` 会覆盖标量），见 21 §4 三范式。

## 3. OffspringGenerator — 子代生成器（驱动拓扑+策略）

**职责**：调 `topology.getTopology` 得图，对每条边用 `strategy` 生成子代，经 `repairman` 修复。注册于 `Registry<OffspringGenerator>`（`T_offspringgenerator`）。

**接口**：
```cpp
virtual void generate(
    Terminator*, SolutionRepaireman*&, LearningTopology*&, LearningStrategy*&,
    IndividualArray* offspring, IndividualArray** parent, BestArchive** archive,
    int subswarm_number,
    std::queue<LearningStrategy*>& after_fes,   // 后置更新队列(评估后)
    std::queue<LearningStrategy*>& after_upd,   // 后置更新队列(选择后)
    LearningGraph*& last_graph) = 0;            // 传入上代图/传出本代图
```
**四种框架**（`inplace` 参数）：`Generation`（整体+约束修复，最常用）/ `GenerationNoCheck`（整体无修复）/ `OrderedConstruct`（逐维顺序，需策略 constructive）/ `ParallelConstruct`（逐维并行，每体独立句柄+逐维约束传播）。
**契约**：offspring **追加**（不清空，跨段累积）；终点 `nullptr` → 复制亲代进子代并 `has_evaluted=true`（评估器跳过）。

## 4. EnvirSelect — 环境选择（两层设计）

**职责**：用子代更新种群。**两层**：找谁替换 + 是否替换。注册于 `Registry<EnvirSelect>`（`T_selector`）。

**第一层**（找谁替换）：
```cpp
virtual void update_subswarm(IndividualArray& parent, IndividualArray& offspring,
                             Terminator* terminator, BestArchive* archive) = 0;   // terminator/archive 透传给接受层(Aging scout 用)
```
实现：`Index`（逐位 1:1）/ `Rank`（(μ+λ) 择优归并）/ `Close`（替换最相似）/ `WorstReplace`（无条件换最差 λ）/ `DistanceSelect`（留最优+距离密度）/ `RankCrowding`（多目标非支配 rank+拥挤度，NSGA-II）/ `ScalarReplace`（多目标 Tchebycheff 邻域替换，MOEA/D）。

**第二层** `AcceptCriterion`（是否替换）：
```cpp
virtual void accept(Individual& offspring, Individual& parent,
                    Terminator* terminator, BestArchive* archive) = 0; // 判是否 swap;terminator/archive 供 Aging scout
virtual void update();  virtual void reset();                          // 退火降温/复位
virtual std::vector<FeatureDemand> featureDemands();                   // age 感知准则声明所需特性(默认空)
virtual void setFeatureKey(role, key);                                 // 装配期回填身份键
```
实现：`Unconditional` / `Better`（爬山，仅更优才换）/ `Anneal`（Metropolis）/ `Aging`（年龄感知贪心 = Better + `age` 特性 + scout：`age>limit` 重生、更优换+归零、未改进 age++）。`Rank`/`WorstReplace`/`DistanceSelect` 内建全局逻辑，不走接受层（传占位 `UnconditionalAccept`）。
**契约**：`RunSelect` 包装在 `update_subswarm` 后 `offspring.clear()`（故 offspring 跨段累积到本次选择为止）。

## 5. Evaluator — 评估器

**职责**：对子代群体逐个求真实适应度，并驱动最优档案 + 终止器(FES)。注册于 `Registry<Evaluator>`（`T_evaluator`）。

**接口**：
```cpp
virtual void setProblem(ProblemHandle*);
virtual void evaluate(Terminator*, BestArchive*, IndividualArray& offspring) = 0;
```
**契约（逐个体）**：已评估(`has_evaluted`)跳过 → 终止则停 → 真实评估 + `has_evaluted=true` → `archive.updateBest` → `terminator.update`。实现：`Basic`（逐个计 FES）/ `Hash`（重复解命中不计 FES、回填 fitness）。

---

## 6. Terminator — 终止器（单一具体类，非注册族）

**职责**：迭代停止条件。三条件 `_conditions[3]`（FES / Convergence 停滞代数 / Time 秒），任一达标即停；`_states[3]` 为当前进度。由编排层直接持有、传入。

**关键方法**：
```cpp
void update(bool best_update);   // FES++; best_update→停滞归零 else 停滞++; Time=now-start
bool termination();              // 任一 state≥condition
int  getFESTimes();  void reset();
double getProgress();            // 已启用条件中 state/condition 的最大比例(供策略读运行进度)
void merge(...);  void limited(...); // 子/上级终止器协作:累加进度 / 约束子资源
```
**契约**：`_conditions[i]==ECFLOW_MAX` 表示该条件不启用；构造即清零 `_states`（避免 reset 前误读）。

## 7. BestArchive — 最优档案

**职责**：记录运行过程最优（或可接受）解。注册于 `Registry<BestArchive>`（`T_bestarchive`）。

**接口**：
```cpp
virtual Solution* getBest();                 // 全局最优(默认 _best_solution)
virtual Solution* getElite() = 0;            // 单个精英(供 MMAS/领袖类取)
virtual bool updateBest(const Solution&) = 0;// 更优则收纳,返回是否更新
virtual int  getBestSize();  virtual void clear();
virtual void setProblem(ProblemHandle*) = 0; // 设 comparer(方向感知)
```
实现：`Basic` / `Multiobject` / `Multimodal`（`Historic` 未注册）。
**契约**：`updateBest` 用 comparer 方向感知比较；`getBestSize()==0` 表示尚无最优（首代生成前档案空，读 `getBest()` 需判空）。

## 8. SolutionInitializer — 解初始化器

**职责**：生成初始候选解。经 `workflow.initializer("Random")` 按 tag 指定。**注意：初始化器是唯一不走注册表的组件族**——由 `OptimizerBuilder::Ibuild(tag)` 的 if-else 硬编码构造（加新初始化器需改 `Ibuild`，不像其它组件"一文件+一行注册"）。

**接口**：
```cpp
virtual void ini_solution(double* result, int size) = 0;   // 填一个解(逐维)
void ini_solution(Solution&);                               // 填 + 按需评估(否则 fitness[0]=EMPTYVALUE 作未评估标签)
virtual void setProblem(ProblemHandle*);
```
实现：`Random`（域内随机）/ `Greedy`（优先级贪心）/ `R_G`（按概率随机或贪心）/ `Distribution`（分布采样）/ `No`（空）。

---

## 9. SolutionRepaireman — 解修复器

**职责**：把非法解的某一维修复到合法值。注册于 `Registry<SolutionRepaireman>`（`T_Repair`）。

**接口**：
```cpp
virtual double repair(const Solution&, int dim, ProblemHandle*) = 0; // 返回该维修复值
```
实现：`Boundary`（夹回最近边界）/ `Modular`（模映射绕回域内，FWA）/ `Random`（域内随机）/ `Greedy`（优先级贪心）/ `No`（原值）。
**契约**：仅当 `!constrainCheck(dim,val)` 时被生成器调用。

## 10. Individual — 个体（基本单元）

**职责**：优化器基本单元，持一个候选解 + 状态。注册于 `Registry<Individual>`（`T_individual`）。

**成员/接口**：
```cpp
Solution solution;  bool has_evaluted;  int _age;
int getSolutionSize();  int getObjectNumber();
virtual void setProblem(ProblemHandle*);  virtual void setProblem(const Individual&);
int getAge();  void rebirth();  void ageing();                 // 年龄(停滞计数,见 AGE-STAGNATION)
virtual void ini(bool ini_solution=true, bool evaluate=true, bool ini_speciality=false);
virtual void copy/shallowCopy/shallowClear/swap(...);          // 值/浅/交换语义
double& operator[](int d);                                     // 逐维读写(委派 solution)
bool operator<(Individual&);                                   // 经 comparer 方向感知比较(更优在前)
static preAssert/postAssert;                                   // N6 个体上下文
```
**无个体子类（INDIV-COMPOSE 收官）**：只有基类 `Individual`，逐个体状态改为**挂载特性**（`Registry<Feature>`：`vector`/`scalar`/`solution`/`pbest`/`setvelocity`/`age`/`kinship`）。组件经 `featureDemands()` 声明（role/kind/scope/init），装配期推断、逐个体挂载；运行期 `individual->feature<T>(key)` 取用。**出生携带**：`inheritAtBirth=true` 的特性在生成时经 `Feature::birthFrom(parent)` 并入子代——默认 = `copyFrom`（pbest/setvelocity 拷记忆），`kinship` 覆写为"派生"（`parent_id=parent.id`）。特性清单见 [24 §9](24-开发-组件清单.md)。

## 11. Subpopulation — 子种群

**职责**：生成+选择的**基本单元**。持一条 `O_Workflow` + `parent`/`offspring`（`IndividualArray`）+ 子群档案。
**关键方法**：`setProblem` / `ini()`（初始化种群、绑初始化器）/ **`run()`**（每代跑 workflow：生成→评估→选择）/ `getBest(best,size)` / `getSize()`。

---

## 12. SubpopulationManager — 子群协作管理器

**职责**：**定义子种群交互的方式**，并作为**驱动者**调用另外两个种群级组件（构建器 §13 = 个体如何形成子群；拓扑 §14 = 子群交互的拓扑）。注册于 `Registry<SubpopulationManager>`（`T_subswarmmanager`）。

**接口（模板方法化）**：
```cpp
// —— 框架固定时序,非虚:子类不得改写,终止器协作 + 预算记账 + 拓扑维护由基类包办 ——
void ini();          // 逐子群闭环初始化(按全局剩余设限,一次性成本)
void runEpoch();     // 跑一轮:interact() → 拓扑维护 → 逐子群(配额→跑→并账)
// —— 子类扩展点(钩子):只描述"这一轮的交互方式" ——
protected: virtual void interact() {}   // 迁移 / 驱动构建器重构 / ...(无交互则不覆写)
protected: virtual void iniHook()  {}   // 初始化末尾的额外动作
// —— 仍为 virtual(尚无框架骨架) ——
virtual void globalOptimumCollection(BestArchive*);  virtual void setProblem(ProblemHandle*);
```
实现：`Single`（单子群）/ `NoInteraction`（多子群独立进化+全局汇集）/ `Immigrant`（`interact`=向邻居迁入本群最优）/ `RebuildTopology`（`interact`=驱动构建器重聚类）。多子群还需配 **子群构建器**（§13）+ **子群拓扑**（§14）。

**★ 两级预算契约**：子群终止器装**每轮(epoch)预算**、全局终止器装**总预算**；`runEpoch` 每轮由 `Terminator::limited` 取 `min(每轮预算, 全局剩余)` 下发配额，跑完立即 `merge` 并账 —— 既不跑超总预算，又保持"每 N 次评估交互一次"的节奏。**添加新 manager 时只写 `interact()`，切勿自行 merge/reset 终止器**。

## 13. SubpopulationConstructer — 子群构建器（划分/重构）

**职责**：把全体个体**(重新)划分到各子种群**的策略。多子群协作时由管理器持有，负责构建初始子群划分、或运行中重聚类。注册于 `Registry<SubpopulationConstructer>`（`T_subswarbuilder`）。

**接口**：
```cpp
virtual void build(Subpopulation** subpopulations, int& swarm_number) = 0; // (重新)划分个体到各子群
virtual void ini(Subpopulation** subpopulations, int& swarm_number);       // 初次构建
```
实现：`Fixed`（固定划分，不重构）/ `Distance`（按解间距离重聚类）/ `Fitness`（按适应度重聚类）。
**契约**：`build` 就地 swap 个体到目标子群（个体全程守恒）。

---

## 14. SubpopulationTopology — 子群拓扑（子群间邻域）

**职责**：子种群**之间**的邻域拓扑模型——持 `NeighborSet` 数组（每子群一份邻居集），决定协作（如迁徙）时"哪个子群与哪个子群相邻"。注册于 `Registry<SubpopulationTopology>`（`T_subswarmtopology`）。

**接口**：
```cpp
virtual void build(Subpopulation** subpopulations, int& swarm_number) = 0; // 建邻居集(数目未变时重填)
virtual void ini(Subpopulation** subpopulations, int& swarm_number)  = 0;   // 分配邻居集尺寸 + build(数目变化时)
```
实现：`Connected`（全连接）/ `Star`（星型）/ `Toroidal`（环面）/ `Preswarm`（前驱）/ `NoConnect`（无连接）。
**契约**：`runEpoch` **每轮驱动 `build`** —— 随机/动态拓扑在 `build` 里重新抽样即获得"每轮刷新"，静态拓扑填回相同内容。故"拓扑是否动态"由 `build` **是否随机自身决定，无需声明位**。与管理器配合：`SubpopulationManager` 的交互（如 Immigrant 迁徙）沿本拓扑的邻居集迁移个体。区别于 §1 的 `LearningTopology`（那是**个体间**学习图；这是**子群间**邻域）。
