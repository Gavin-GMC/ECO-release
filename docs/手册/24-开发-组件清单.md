**变异**
| tag | 语义 · 参数 | 编码 |
|---|---|---|
| `Bit`/`BitFlip` | 位变异/位翻转：`mutation_rate` = **逐维选中概率** | 二进制/通用 |
| `PM` | 多项式变异：`eta` 分布指数 · `mutation_rate` = **逐维选中概率**（NSGA-II 原文的 pm，常取 1/n） | 连续 |
| `Gauss` | 高斯变异（选中的维加高斯噪声）：`sigma` 步长 · `mutation_rate` = **逐维选中概率** | 连续 |
| `Overturn`/`Exchange`/`Insert`/`Reorder`/`SegmentRelocate` | 片段/排列变异：`times` 操作次数 · `mutation_rate` | 排列/序列 |
| `CyclicExchange` | 循环交换：k 个互异维的值**环状轮转**（k=2 严格退化为 `Exchange`）；值多重集守恒。`cycle_length` 环阶 k · `mutation_rate` | 排列/序列 |
| `BlockSwap` | 块互换：前\|A\|M\|B\|后 → **A、B 互换**（长度可不等、可隔任意距离，中段 M 次序不动）；守恒。**统一推广**：M 空即 `SegmentRelocate`、A/B 均单维即 `Exchange`。`times` · `mutation_rate` | 排列/序列 |
| `MultiPointSameValue` | 多点同值：**逐维**以 `point_rate` 独立选中（同 `Bit` 的参数语义），选中维**全置同一个**域内随机值（与 `Bit` 的唯一区别=共用一个值） | 通用/指派 |
| `SetExchange` | 集合交换：随机取两现值 a/b，"取值=a 的维"与"取值=b 的维"**各取随机子集互换取值**（值类层面成组迁移；rate=1 即两类整体对调）。`subset_rate` 成员入选概率，**留空(EMPTYVALUE)→ 免参**：两侧各随机抽率（非对称迁移+规模展宽） | 指派/分组 |
| `ClassRelocate` | 值类外迁（**单向**）：取值=a 的维取随机子集，**整体迁到域内新抽的值 c**。c 未被使用 → **拆分类/启用闲置值**；c 已在用 → 单向并入。（`SetExchange` 只在两已有类间对调，二者皆做不到）。`subset_rate` 同上，**可留空** | 指派/分组 |
| `ClassMerge` | 值类合并：取值=a 的维**全部**并入另一**现值** b → 类 a 消失、**在用值个数确定减 1**（整合/关停）。目标取自现值故必被占用——这是"确定减一"的来源（`ClassRelocate` 满率有约半数只是"改名"）。`mutation_rate` | 指派/分组 |

> **`mutation_rate` 的语义由继承的基类决定**——是**类型级区分**，不靠注释辨认：
> - **`PerDimMutation` 族**（`Bit`/`BitFlip`/`PM`/`Gauss`）→ **逐维选中概率**。门控在**基类**：`nextDecision` 里 `if (rand01() < rate) 调子类 mutatedValue`，子类只答"这一维**变成什么**"、不管"变不变"。**新增逐维变异一律继承本族**，勿自行内联门控。
> - **整体型**（`Overturn`/`Exchange`/`Insert`/`Reorder`/`SegmentRelocate`/`CyclicExchange`/`BlockSwap`/`ClassMerge`，各自 override `getNewIndividual`）→ **整体施加概率**（本次算子做或不做）。
> - 另有独立命名者：`MultiPointSameValue` 的 `point_rate`（逐维选中）、`SetExchange`/`ClassRelocate` 的 `subset_rate`（值类成员入选）。

> GA/DE 无独立策略类 = 交叉+变异+拓扑的多段组合。

## 4. 环境选择 `Registry<EnvirSelect>`（10）

| tag | 语义 | 参数（含义） |
|---|---|---|
| `Index` | 逐位 1:1 替换 | `accept_type` 0无条件/1择优(爬山)/2退火/3年龄计龄 —— **仅此一项是选择器自己的**；其后参数由 `accept_type` **渐进披露**（模板的 `next`）：仅 **2 退火** 追加 `T0`·`decay`（均可留空→回落 100.0/0.95），0/1/3 零追加 |
| `IndexAnneal` | 逐位 + Metropolis 退火 | `T0` 初温 · `decay` 每代降温系数(<1) |
| `Rank` | (μ+λ) 择优归并 | — |
| `Close` | 替换最相似（欧氏距离） | `accept_type` 同 Index |
| `CloseAnneal` | Close + 退火接受 | `T0` · `decay` |
| `WorstReplace` | 无条件替换最差 λ（免疫换血） | —（λ 由子代数推断） |
| `DistanceSelect` | 留最优 + 距离密度选（FWA 保多样性） | — |
| `RankCrowding` | 多目标：合并 μ+λ→非支配 rank 逐层填、末层按前沿内拥挤度截（NSGA-II，配 Multiobject） | — |
| `ScalarReplace` | 多目标：Tchebycheff 标量化替换邻域内 ≤nr 个（MOEA/D，z\* 历史单调） | `nr` 每子代最多替换 · `T` 邻域大小（须与 Neighborhood 一致） |
| `Kinship` | ABC onlooker：血缘定向（读 `offspring.parent_id` 定位源槽逐源比较，多对一）。声明 kinship（Singular） | `accept_type` 同 Index（ABC 用 3 计龄） |

**接受准则 `AcceptCriterion`（第二层，被 Index/Close/Kinship 组合）**：`Unconditional`（无条件换）/ `Better`（仅更优才换=爬山）/ `Anneal`（Metropolis：更优必收、更差以 e^{-Δ/T} 概率收）/ `Aging`（年龄感知贪心 = **Better + 停滞计龄**：更优 → 换 + age 归零，未改进 → age++〔= trial+1〕；需 `age` 特性〔Singular〕，装配期推断挂载）。<br>**scout 不在接受层**（曾内联，因 onlooker 多对一会 pullback → 剥离为独立 scout 段 `AgeActivation`+`Reinitialize`，见 §1/§2）。接受准则透传 `Terminator*/BestArchive*`（签名一致；`Aging` 拆分后已不用）。<br>**装配契约**：选择器 postAssert 追加 `acceptPostAssert`（`Aging`→提供 `ageMaintained`），供 age 消费方（`AgeActivation` 拓扑 preAssert）配对——缺计龄接受则硬报错。

## 9. 个体特性 `Registry<Feature>`

> **INDIV-COMPOSE 收官**：个体只有唯一基类 `Individual`，不再有子类（`Particle`/`SetParticle`/… 已删）、也无 `Registry<Individual>`。逐个体状态改为**可挂载特性**：组件经 `featureDemands()` 声明需要哪些特性，装配期推断、逐个体挂载，运行期按身份键取用（`individual->feature<T>(key)`）。配置**无需**指定个体类型。

| 特性 kind | 承载 | 用于（声明它的组件） |
|---|---|---|
| `vector` (`VectorFeature`) | 按解维实数向量（初始化策略可选 Zero/Constant/RandomInDomain） | velocity（PSO/BPSO）、sigma（自适应 ES，Constant σ0） |
| `scalar` (`ScalarFeature`) | k 个标量 | whalestate（WOA，k=4：p/A/C/l）、fireworkstate（FWA，k=1：g）、**wavestate**（水波，k=2：h 波高/λ 波长，**Singular** 供折射/碎波拓扑按常量键读 h） |
| `solution` (`SolutionFeature`) | 一个 `Solution` | 通用"持有一个解"（中性） |
| `pbest` (`PbestFeature`) | 历史最优（`SolutionFeature` + 记忆前传 `inheritAtBirth` + 评估后择优 `afterEvaluate`） | pbest（PGBest 拓扑，Singular） |
| `setvelocity` (`SetVelocityFeature`) | 每变量一个 `SetVelocity`（集合速度矩阵） | setvelocity（SetPSO） |
| `age` (`AgeFeature`) | 整数年龄/停滞代数（`get/reset/ageing`；Singular，多组件共享一份 trial 计数） | 计龄接受 `AgingAccept`（写）+ scout 拓扑 `AgeActivation`（读，`age>limit` 触发重生）+ `Reinitialize`（ini 归零） |
| `kinship` (`KinshipFeature`) | 解血缘 id（`id`+`parent_id`，`isChildOf` 一步等值归属） | 直系亲本标记：出生经 `birthFrom` 派生 `parent_id=parent.id`（Singular；消费方 ABC/精英局搜另立增量） |

**作用域 scope**：`Private`（每实例私有，可经通道共享）/ `Exclusive`（禁共享）/ `Singular`（每个体唯一，所有读者共用，如 pbest）。加新逐个体状态 = 声明 `featureDemands`（选/加一个特性 kind），**不再新增个体子类**。

> 个体无需在配置中指定（只有基类 `Individual`）；所需特性由组件 `featureDemands()` 声明、装配期推断挂载。

# 附录：添加一个新组件时的实现清单

按顺序过一遍。标 **必做** 的漏掉会**静默失效**（不报错、只是行为不对），历史上每一条都真实踩过。

## A. 代码

- [ ] **必做｜继承正确的基类**，实现其纯虚接口 —— 基类职责与钩子时序见 [23 组件基类参考](23-开发-组件基类参考.md)。
- [ ] **必做｜行为名命名**：可插拔算子（拓扑/变异）用**行为名**（PSO 拓扑 → `PGBest`），不用原算法名；整体算法策略（`AntSystem`/`CMAES`/`GreyWolfEncircling`）可留标准名。
- [ ] **必做｜写 `Registry<Base>::Entry` 并 `ECFLOW_REGISTER`**：`{name, category, params, size, create, pre, post}`。
- [ ] 若组件需要**个体状态**（velocity/age/kinship/自定义）：声明 `featureDemands()` + 实现 `setFeatureKey()`，**不要**加成员变量 —— 装配期特性推断会供给（见 [23 §10](23-开发-组件基类参考.md)）。选 `Private`/`Exclusive`/`Singular` 域时注意：**`Singular` 的键 = role 常量**，任何组件不声明也能读。
- [ ] 若组件对上下游有**契约要求**（如"需要 topology 提供 ≥1 个学习对象"）：在 Entry 的 `pre`/`post` 里声明断言，由 [AssertMatcher](../src/optimizer/config/assert-matcher.h) 在装配期匹配。**断言写在组件自己的实现文件里**，matcher 只管匹配规则。

## B. 参数模板（机读入口 —— 两个消费方都靠它）

`ParameterTemplate` 是该组件参数的**权威 schema**：`config-setter` 的具名方法参数序取自它，**自动化配置生成**与**装配期校验**（[ParamMatcher](../src/optimizer/config/param-matcher.h)）都读它。填错 = 两边一起错。

- [ ] **必做｜每个参数填全 6 项**：`{name, kind, low, high, allow_empty, rec_low, rec_high}`。
  - `kind`：`Int`/`Enum` 会被校验**整值性**；`low`/`high` 是**硬边界**（校验用），`rec_low`/`rec_high` 是**推荐区间**（自动生成采样用），两者不同。
- [ ] **必做｜`allow_empty` 是一个承诺，不是标签**。声明 `true` 就**必须**在**构造函数**里处理 `EMPTYVALUE`（`is_empty(v) ? 默认 : v`），放 ctor 而非工厂以覆盖所有构造路径。不兑现 → NaN 一路灌进去 → **静默退化**（前车之鉴：`AnnealAccept` 留空曾使退火退化为纯择优）。反之，**没有"未设置"语义就填 `false`**（`vel_init_scale` 的 `0` 本身即"关"，曾误标 `true`）。
- [ ] **必做｜只声明"自己的"参数**。别把**别的组件**的参数拍平进来 —— `Index` 曾把 `AnnealAccept` 的 `T0`/`decay` 硬编进模板，等于在语义上把选择器绑死到退火接受，与"选择器 ⊥ 接受准则"的设计相悖。
- [ ] 若**后续参数的 schema 由前面参数的取值决定** → 在 `ParameterTemplate` 上挂 **`next`** 钩子（渐进披露），别硬编并集：
  ```cpp
  ParameterTemplate{ { {"accept_type", ParamKind::Enum, 0, 3, false, 0, 1} },   // 本级
                     acceptParaTemplate }                                        // next:下一级
  ```
  | 情形 | 例 | `next` 返回 |
  |---|---|---|
  | 枚举选出另一个准则/组件 | `Index` 的 `accept_type` | 该准则的参数（`acceptParaTemplate`） |
  | 枚举选出内层组件 | `TabuDecorator` 的 `inner` | `Registry::params(内层tag)` —— **原样返回即可**，内层自己的 `next` 会跟着带入 |
  | 计数决定重复项 | `ALNS` 的 `op_count` | N 份该项 |

  三条要点：
  - **`next` 收的是「本级切片」**（从本级第一个参数起），**不是整个 para** —— 按**相对下标**读自己的参数。这使模板可被任意嵌套复用；若按绝对下标读，被嵌套时就会读到上层的参数。
  - **描述而非裁决**（返回模板、不返回 bool）：自动化配置生成要能问出"给定 `accept_type=2`，接下来要什么"。
  - **不必手写递归**：返回的模板若自带 `next`，解析方会继续逐级展开（`ParamMatcher` 设有深度上限防环）。
- [ ] 若工厂**按位置无条件读** `para`（如 `create` 里 `p[1]`、或把 `p + k` 传给内层）：确认模板声明的元数与之**严格一致**。少给即**越界读** —— `Index`（`makeAccept` 读 `p[1]/p[2]`）与 `TabuDecorator`（`create` 传 `p+2`）都曾有此洞，现由 ParamMatcher 在装配期堵住。

## C. 配置与文档

- [ ] **必做｜加 `config-setter.h` 的具名方法**，参数序**与模板一致**，行内注释写清语义。
- [ ] 加配置表生成（`tutorial/config-generate*.cpp`）—— 历史上 ABC 曾整个漏掉。

## D. 测试

- [ ] **必做｜写 smoke**，放 `tests/optimizer/<族>/`，输出**英文**，以 `fails ? 1 : 0` 返回。
- [ ] **验行为，别验"不崩"**。`chk("...", true)` 这种恒真断言什么都没验证 —— 找一个能把正确实现与错误实现**区分开**的可观测量。私有状态无 getter 时借行为反推（例：`AnnealAccept` 的温度不可见，但**接受率就是温度的指纹** —— `exp(-Δ/T)`，NaN 温度必得 0.000）。
- [ ] 尽量做**结构性验证**而非统计验证。若解可构造成全互异（`parent[d]=d`），常能从子代**反解**出算子的断点/映射，逐位核对（例：`BlockSwap` 反解四断点核对 `B+M+A`）。
- [ ] 加**对照组**：与最相近的既有算子对比，证明新算子**确实不同**（例：`ClassRelocate` 能启用未使用的值、`SetExchange` 一次都不能）。
- [ ] 跑**全量回归**，不只跑自己那条。

## E. 常见静默陷阱速查

| 陷阱 | 症状 | 参见 |
|---|---|---|
| 裸 `== EMPTYVALUE` | 恒假，守卫**永不触发** | 代码规范 §3 |
| NaN 流进比较 | `rand01() < NaN`、`low <= NaN <= high` 恒假 → 静默放行/永不选中 | 同上 |
| `allow_empty` 声明了不兑现 | NaN 灌进组件 → 行为静默退化 | 上文 B |
| 工厂越位读 `para` | 越界读，多数时候"看起来正常" | 上文 B |
| 特性用成员变量存 | `swap` 随基因换特性袋 → 状态错位 | [23 §10](23-开发-组件基类参考.md) |
| 恒真断言 | 测试全绿但零覆盖 | 上文 D |
