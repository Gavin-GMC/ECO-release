## 1. 加一个新约束

约束走 **ConstrainDefine（描述）→ compile() → ConstraintManager（引擎）** 路径。每个具体约束是一个 `Constrain` 子类。

### 1.1 `Constrain` 基类接口（`problem/constrain/ecflow-constrain.h`）
```cpp
virtual void   ini() = 0;                                   // 每次求解前复位内部状态
virtual bool   meet(int dim, double value) = 0;             // 该维取 value 是否满足(约束检查)
virtual void   update(int dim, double value) = 0;           // 落子 value 后更新/传播内部状态
virtual double violation(double* variables, int size) = 0;  // 整解的违反程度(→ 惩罚)
virtual void   regionReduction(int dim, discrete_view& region) = 0; // 对该维可行域做缩减(cp 传播)
virtual ConstrianLevel getConstrainLevel() = 0;             // 约束层级(range/discrete/customization…)
virtual Constrain*     clone() = 0;                         // 深拷(并行/句柄复制用)
virtual void   addCorresConstrain(Constrain*) {}            // 关联约束(可选)
```
**语义要点**：`meet`+`update` 支撑逐维构造时的检查与传播；`regionReduction` 支撑域缩减（写 `discrete_view`）；`violation` 支撑罚函数；`getConstrainLevel` 决定该约束参与哪条运行路径。

### 1.2 落地步骤
1. **实现子类** `class ConstrainXxx : public Constrain`（`problem/constrain/`），实现上述纯虚。参考现成：`ecflow-domain.h`（域）、`ecflow-cardinality.h`（基数）、`ecflow-graph-constrain.h`（图）、`ecflow-constrain.h`（cp 表达式）、`ecflow-accumulate.h`（累积）。
2. **加种类枚举**：`ConstrainDefine::ConstrainKind` 加一个值（`problem/define/constrain-define.h`）。
3. **加描述存储 + `addConstrainXxx()`**：在 `ConstrainDefine` 填一条 `Spec`（`kind` + `related_variables`/`related_objects`（承接惩罚目标）+ `params`（打包参数，`vector<vector<double>>`）+ 视需要的 `graph_edges`/`addresses`(函数指针存 `long long`) 等）。
4. **在 `compile()` 里造对象**：`ConstrainDefine::compile(varMgr, objMgr)` 按 `Spec.kind` 加一个 `case`，从 Spec 参数构造你的 `ConstrainXxx`，交给 `ConstraintManager`。
   > 校验（合法性/参数）**在 compile 时做**（"define 存 spec、build 时校验"约定）——非 add 时。
5. **在 `Problem` 暴露 API**：`problem/core/problem.h` 加 `void addConstrainXxx(...) { _conDef.addConstrainXxx(...); }`（委派）。
6. **用户文档**：在 [10 §3.1 约束详表](10-使用-问题模块.md) 加一行；补一个 smoke（`tests/`）验证 meet/violation/regionReduction。

> 参数打包约定：`Spec.params` 是 `vector<vector<double>>`（每条一段），约定 `buf[0]=长度` 等；函数指针存进 `addresses`（`long long`）在 compile 时 `reinterpret_cast` 回来。

## 2. 加一个新问题模板

问题模板 `PT_Xxx` = **用问题模块公共接口把一个具体问题"组装"出来**的便利类。13 个现成模板（`problem/template/pt-*.h`）就是范例与最佳参照。

**模式**：
```cpp
class PT_Xxx {
public:
    void setName(std::string);          // 可选
    void setData(...);                  // 问题实例数据(城市/矩阵/图…)
    void setPenalty(double);            // 可选(图/惩罚型)
    Problem* getProblem() {             // 组装并返回(调用方拥有,用完 delete)
        Problem* p = new Problem(_name);
        p->addVariable(...);            // 定义决策变量(维数/域/精度/编码)
        p->addObjective(...);           // 目标(函数指针/functor/公式)
        p->addConstrain...(...);        // 约束(选合适的约束族)
        p->addInspiration...(...);      // 启发(可选,供贪心构造)
        return p;
    }
};
```
**要点**：
- 编码选择决定配什么算子——排列/序列（TSP/QAP/调度）→ 配 ACO/序列 GA；连续（Numerical）→ PSO/ES/…；二进制/选择（MKP/MDS/MIS）→ GA/二进制 PSO。
- 目标/启发的 `double**` 布局见 [10 §3](10-使用-问题模块.md)；复杂目标可用 `eccalcul_functor`（带状态，如 TSP 的距离表）。
- 无需注册表——模板是纯便利类，用户 `#include "pt-xxx.h"` 后直接用。
- 端到端示例见 `tutorial/5.template.cpp`。

## 3. 加目标 / 启发后端

**目标**（`addObjective` 三形式，见 [10 §2](10-使用-问题模块.md)）：函数指针 `double(*)(double**)` / 函数对象 `eccalcul_functor*`（带状态）/ 公式串（muParserX）。绝大多数新目标用这三种即可，**无需改框架**。
**启发**：`addInspirationFunc/Matrix/Expr/Random/Boundary`（见 [10 §4](10-使用-问题模块.md)）。

> 若要加**全新的求值后端**（如新的表达式引擎 / 新的 `CalcKind`）：涉及 `problem/define/calc-spec.h`（CalcSpec/CalcKind）+ 对应 calculator。属较深改动，建议充分评估影响后再动。cp 表达式约束 / muParserX 目标公式的语法见 [26-表达式公式语法](26-开发-表达式公式语法.md)。

## 4. 小结：问题侧 ⇄ 优化器侧扩展对照

| | 问题侧（本篇） | 优化器侧（[21](21-开发-内部组件.md)） |
|---|---|---|
| 加"算子/约束" | 新 `Constrain` 子类 + Kind + Spec + compile case + Problem API | 新组件类 + `ECFLOW_REGISTER` + 聚合头 + config-setter |
| 装配方式 | Define→compile→Manager（非注册表，compile 内 switch by kind） | 自注册表 `Registry<Base>` + 按 tag create |
| 便利封装 | 问题模板 `PT_Xxx`（组装 add*） | 算法配方（[11 §6](11-使用-优化器配置.md) 组件组合） |
