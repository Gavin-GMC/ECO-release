# 26 · 表达式公式语法（约束 cp / 目标·启发 muParserX）

框架里**两处**可用字符串公式，走**两套不同引擎**——语法/能力不同，务必分清：

| 用途 | API | 引擎 | 关键差异 |
|---|---|---|---|
| **约束**表达式 | `addConstrainExpr(var, elements, formula, …)` | **cp**（区间传播） | 算术+关系，**无数学函数**；支持**域缩减/传播** |
| **目标 / 启发**表达式 | `addObjective(…, formula)` / `addInspirationExpr(…, formula)` | **muParserX** | 算术+**完整数学函数**；**直接求值**（无传播） |

**公共**：元素引用都写 `变量名[下标]`——`x[0]`、`x[1]`…（`x` = `input_elements` 里的变量名，`[i]` = 该变量第 i 维元素）。

---

## 1. 约束表达式（cp 引擎，`addConstrainExpr`）

```cpp
p.addConstrainExpr("x", "x", "x[0]+x[1]-10", 1, "g");   // 约束: x[0]+x[1] <= 10
```
- **语义**：公式 `F` 是**违反度算术表达式**，约束 = **`F <= 0`**，**违反度 = `max(0, F)`**（满足时 F≤0、违反度 0）。
- **支持的运算**（`cp/compile/parser.h`）：
  - 算术：`+` `-` `*` `/`、一元负 `-`
  - 关系：`<` `<=` `>` `>=` `==` `!=`
  - 操作数：`变量名[常量下标]`、数字（含 `1e-3` 科学计数）、括号 `(...)`
  - **⚠️ 无数学函数**（没有 sin/cos/sqrt/abs/pow…）——需要函数请改用自定义约束或把逻辑拆成算术。
- **关系子式 = {0,1} 指示因子**：括号里的关系式取值 0/1，如 `(x[0]>5)`。可用**指示算术**编码逻辑（在 `violation=max(0,F)` 下）：
  | 逻辑 | 写法（违反度） |
  |---|---|
  | 蕴含 a→b | `(a)-(b)` |
  | 至多 k 个成立 | `(c1)+(c2)+…+(cn)-k` |
  | 与/或 | 指示相加减组合（见 `ecflow-constrain.h` 头注表） |
  > 注意：关系型约束的域缩减**保守但不会过度剪枝**（边界处可能留一格），罚函数兜底。
- **域缩减**：cp 会据公式反向传播、缩窄各维可行域（`regionReduction`），供逐维构造（`getFeasibleList`/`getPrioriChoice`）。
- **跨变量**：`input_elements` 可含多个变量（如 `"x,y"`），公式按其在 elements 里的**元素展开顺序**索引。
- **坏公式**：cp 解析失败 → 构造/compile 时抛 `std::invalid_argument`（"define 存 spec、compile 时校验"）。

## 2. 目标 / 启发表达式（muParserX，`addObjective(formula)` / `addInspirationExpr`）

```cpp
p.addObjective("f", 1, true, "x", std::string("x[0]*x[0] + x[1]*x[1]"));  // 最小化 Σx²
p.addInspirationExpr("x", "", "x[1]");                                     // 启发分 = x[1]
```
- **引擎**：muParserX（`calculator/` + `exprTree/`，`TreeCalculator`）——功能远比 cp 丰富。
- **支持**：算术 `+ - * / ^`、括号、`变量名[下标]` 元素、常量，**+ 标准数学函数**（`sin/cos/tan/exp/log/log10/sqrt/abs/pow/min/max/…`，以 muParserX 函数集为准）。
- **求值**：对给定解**直接算出目标值/启发分**（无域传播）。目标按 `min_is_better` 定优化方向、`priority` 定择优序（见 [10 §2](10-使用-问题模块.md)）。
- **坏公式**：`TreeCalculator` 编译失败 → 抛 `std::invalid_argument`（muParserX 会向 stderr 打印 "Compile Error…"，属提示性）。
- **不想写公式**？目标/启发也可传**函数指针**或 **`eccalcul_functor`**（任意 C++ 逻辑、可带状态），见 [10 §2/§4](10-使用-问题模块.md)——公式只是便利形式。

---

## 3. 速查对照

| | 约束 cp | 目标/启发 muParserX |
|---|---|---|
| 元素引用 | `x[i]` ✅ | `x[i]` ✅ |
| 算术 `+ - * /` | ✅ | ✅（另有 `^`） |
| 关系 `< <= > >= == !=` | ✅（作 {0,1} 指示） | —（muParserX 有比较，但目标一般不用） |
| 数学函数 sin/exp/sqrt… | ❌ **无** | ✅ |
| 语义 | `F<=0`，violation=max(0,F) | 直接求值 |
| 域缩减/传播 | ✅ | ❌ |
| 备选（非公式） | 自定义约束 `addConstrain(ini,chk,chg)` | 函数指针 / functor |

---

## 4. 常见错误
- 在**约束**公式里写 `sqrt(x[0])` → cp 无函数、解析失败。改：目标用 muParserX，或约束改自定义/拆算术。
- 下标必须是**常量整数**：`x[0]` ✅、`x[i]`（变量下标）❌。
- 约束公式忘了"违反度=F"语义：要表达 `a<=b`，写 `a-b`（即 `a-b<=0`），不是写 `a<=b` 当整体（虽然 cp 顶层接受关系式，但 ECFlow 层约定传违反度算术式 `F`）。
