# 数据包、校验与外部数据

EvoFlow 3.0.1.5 将程序包和大型问题数据分开交付。程序包始终带 13 个首方小样例，足以覆盖 12 个文件家族和 13 个注册 `TYPE`；可选完整数据 overlay 只增加许可状态明确的 701 个外部实例，不覆盖程序包样例。

Windows 发布资产命名为 `EvoFlow-3.0.1.5-windows-x64.zip`、`EvoFlow-3.0.1.5-data-minimal.zip` 和 `EvoFlow-3.0.1.5-data-full.zip`，每个 ZIP 均带同名 `.sha256`。程序 ZIP 内的 `_pdata` 只含最小 manifest、13 个首方样例、格式 README 和数据来源说明，不含 `manifest-full.json`；因此未安装 overlay 时会稳定报告 `minimal`，不会把缺失的可选数据误报为损坏。

## 包结构

```text
程序目录/
├─ evoflow.exe
├─ python/evoflow/
├─ config/
└─ _pdata/
   ├─ manifest-minimal.json
   ├─ DATA_LICENSES.md
   └─ <12 个家族的 sample.*，共 13 个>

完整数据 overlay/
└─ _pdata/
   ├─ manifest-full.json
   ├─ DATA_LICENSES.md
   └─ <701 个额外实例>
```

完整 overlay 与最小包的数据文件交集必须为零，因此可以直接把 overlay 解压到程序目录。若解压工具询问是否覆盖实例文件，应停止操作并检查目录层级；正常情况下只会合并 `_pdata` 目录。

## 状态检查

原生程序：

```text
evoflow data
evoflow data D:\datasets\EvoFlow\_pdata
```

Python：

```text
python -m evoflow --check-data
```

状态含义：

- `missing`：数据根不存在；
- `minimal`：13 个最小样例与 manifest 一致；
- `full`：最小包和 701 个 overlay 文件均与 manifest 一致；
- `incomplete`：manifest 缺失、文件缺失、大小/摘要不匹配或出现错误的包组合。

Python 检查会复算 manifest 中每个文件的 SHA-256；原生命令不内置密码学实现，只检查 manifest 声明计数、文件集、大小和可加载实例计数。发布资产本身另带 `<zip>.sha256`。

## 构建数据资产

在项目根目录执行：

```powershell
.\build-data-packages.ps1
```

脚本会先验证清单边界和 13/701/714 三个固定计数，再生成固定条目顺序与固定时间戳的 ZIP、逐文件 manifest 和整包 SHA-256。重复构建的 ZIP 摘要必须一致。输出目录默认为 `_release-data`，不进入源码包。

## 获取未随包发布的数据

下载与转换示例见 [`../tutorial/external-data/README.md`](../tutorial/external-data/README.md)。转换器默认拒绝覆盖已有文件；确认需要覆盖时才显式传 `--overwrite`。用户自行加入的数据不写入官方 manifest，因此不会被误报成官方完整包的一部分，但仍可按普通路径加载和发现。
